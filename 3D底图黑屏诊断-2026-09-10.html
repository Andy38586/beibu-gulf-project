3D 底图加载不出来 / 真实地形异常 — 诊断结论（2026-09-10 线上实测）
一句话根因：服务器上 /static/terrain/layer.json（新版，声明了 z0 根瓦片）与实际瓦片目录（旧版，缺 z0 根瓦片）版本错配。Cesium 地形四叉树的两个根瓦片 404 → 整个地球网格建不起来 → 影像底图没有可贴附的表面、根本不发请求 → 3D 只剩星空/深蓝球面。不是天地图 key、不是网络、不是证书问题。
① 线上实测证据（https://112.74.32.206/flood-analysis）

0/1/0.terrain → 404

▶ 现场反证实验（决定性）
故障时 Cesium 0 次请求天地图；在页面内把 terrainProvider 换成平坦椭球后，瞬间触发 248 次影像请求、136 张天地图瓦片，卫星影像立即完整渲染。
② 故障传导链（为什么缺 2 个根瓦片 = 整个 3D 黑屏）
部署版本错配：服务器 layer.json 是 09-09 补过"树根完整性"的新版（available[0] 强制声明两张全球根瓦片），瓦片目录却是更早一版重切产物（z1–z12，没有补 z0 海洋根瓦片）。两者是分两次手工传上去的。
↓
CesiumTerrainProvider.fromUrl 成功（layer.json 200，不进 catch 分支、不回退椭球），但渲染时按四叉树请求根瓦片 0/0/0、0/1/0 → 双双 404，根四边形永久失败。
↓
地表网格一层都建不起来：Cesium 的影像瓦片（img_w/cia_w）是"贴"在地形四边形上的，地形根失败 → 子节点无法细化 → requestImage 永不触发（实测 0 次请求），globe.tilesLoaded 却显示 true。
↓
用户看到：没有任何影像贴层，只剩 globe.baseColor（深蓝 0,0,0.5）；而进 3D 时相机又被代码"故意不定位"（CesiumRenderer._positionCamera 只开光照、不设视角，等城市按钮 flyTo），首屏直接是满天星空的纯黑画面 —— 即"3D 底图加载不出来"。点城市 flyTo 后能看到边界/标签，但地表依旧深蓝无图。
注：右侧"真实地形"按钮控制的是 hillshade 贴图（geotiff 图层显隐），并不会切换 terrainProvider —— setTerrainEnabled() 在源码里是"预留钩子，当前无调用方"，所以用户点这个按钮无法自救。
③ 为什么这个 bug 频繁出现（同一症状已第 6 次复发）
时间 当时的"层" 表象
08-05 a027 前端根本没接 terrainProvider 无真地形
08-10 z085 镜像缓存旧 dist，源码更新没进镜像 生产仍是 2D 贴图
08-10 z092 nginx 给 layer.json 误标 gzip 地形静默失效
09-05 CTB quantized-mesh 格式本身是坏的，重切 heightmap 暗色球面/无起伏
09-05 B11 对抗报告已记录"根瓦片 404"，定级 P3 未修 刷 404
09-10 本次 layer.json 与瓦片目录版本错配，缺 z0 根瓦片 3D 全黑、底图不出
结构性原因 1｜资产不随代码走
4.9 万张瓦片被 .gitignore + .dockerignore 排除，靠 compose 挂载宿主机目录、再手工 scp/rsync 上传；git clone、--no-cache 重建、清理进程、漏传/中断都不会报错，且 layer.json 与瓦片可分别上传 → 版本错配无人拦截。
结构性原因 2｜失败是"静默"的
fromUrl 只校验 layer.json（200 即成功），后续单瓦片 404 不触发任何回退；缺一个根瓦片就拖垮全球面，UI 无提示、只在 console 留两行错，看起来就像"底图挂了"。
结构性原因 3｜本地永远复现不了
dev 走 vite/express 直读本地目录，本地有什么就读什么，与生产部署物天然不一致；历史上多次"本地全绿、上线全黑"。
结构性原因 4｜没有部署后校验
链路里没有任何一步核对"layer.json 的 available 声明 ↔ 磁盘瓦片文件"是否一一对应，09-05 B11 已发现根瓦片问题却挂账，于是同一类问题换个层反复出现。
④ 修复建议（按优先级）
立刻止血（服务器侧，10 分钟）
用最终版 tools/dem-pipeline/07-heightmap-reslice.py 全量重切，把 layer.json + 全部瓦片（含 0/、1/3/1）作为一个整体重新同步到服务器 ./backend/static/terrain/，重启后校验：0/0/0.terrain、0/1/0.terrain、1/3/1.terrain 必须 200。缺 DEM 源文件时，这三张都是 0 高程海洋瓦片，可按 heightmap-1.0 编码（(0+1000)×5、gzip）直接补齐。
代码兜底（防止再全黑）
1) 监听 terrainProvider.errorEvent / 根瓦片失败计数，连续失败自动降级 EllipsoidTerrainProvider，保证影像底图永远能出；
2) 给"真实地形"按钮接上 setTerrainEnabled（目前是空钩子）；
3) 进 3D 首屏给一个默认相机定位，别让首屏停在星空。
根治反复（流程）
1) 地形产物制品化：要么随镜像打包，要么打成版本化 tar 包一次部署，禁止 layer.json 与瓦片分散上传；
2) CI/部署脚本加门禁：遍历 layer.json.available 声明的瓦片逐一 HEAD 校验，缺一张即部署失败；
3) 部署后用无头浏览器跑一次 3D 冒烟（断言 requestImage 被调用、首屏非黑）。
诊断方式：线上页面 Console / Performance Resource Timing / 页面内 fetch 状态码 / Cesium 运行时 Scene 状态读取 / 本地仓库与部署配置比对。所有结论均可复现。
