### 8.12 【基准】作业区平面/高程基准（**全项目唯一一处定义**）· 2026-10-04 11:0x

用户问「要不要定一个基准？」——**要，本条即基准**。

| 基准            | 定义                                                                                                                                             | 落地位置                                                                               |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| **平面基准**    | 交付包 `backend/static/qinzhou-port/tiles/tileset.json` 的 `root.transform`（作业区 ENU 系）。所有自建层必须由它派生经纬→ENU                     | `build-roads.rootTransform()` / `build-ground.rootTransform()`（同一实现，读同一文件） |
| **高程基准 u₀** | **从交付包几何派生**：`rail`（轨道，铺在场面上）与 `concrete` 两个材质各自高度的中位数取平均。实测 ≈ **−15.5 ~ −17.6 m**（取决于纳入哪些细瓦片） | `build-roads.groundLevel()`——**全项目唯一一处**，`build-ground.mjs` 复用它，不复制     |
| 派生规则        | 路面 = u₀ + 0.15 m；地面片 = u₀ + 0.05 m（低 10 cm 不抢深度）                                                                                    | 同上                                                                                   |

### 为什么必须定（本轮实测根因）

| 项         | 事实                                                                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 旧基准     | `groundLevel()` 读 `rebuilt/tileset.json` 里**切块包围盒的底** = −20.35 m。切块是**空间分桶**，盒底由分桶网格决定、与地面无关                                       |
| 后果       | 路网 + 地面片整层放在 **−20.2 / −20.3**，比真实场地低 **4.7 m** ⇒ 埋在交付包表面之下、只在没有几何处露头 = 用户说的「路不平、有缝隙」                               |
| 交付包实测 | 细瓦片按材质：`rail` 中位 **−15.52** / `concrete` 中位 **−15.54**（两个独立材质一致到 0.02 m）；整包竖直范围 −41…+31 m ⇒ **场地本身有起伏**，任何绝对水平板都贴不上 |
| 修法       | `groundLevel()` 改为从交付包 `t4/t5` 瓦片现算（新模块 `glb-read.mjs`），越界即**报错**（不静默返回 0）；重建后 roads u=−17.55、ground u=−17.50                      |

### 失效条件（基准的作废条件）

1. 交付包换版 ⇒ 函数每次现算，自动跟随；但若新版**不再含 `rail`/`concrete` 材质**，函数会报错，必须显式换判据（禁止静默退回常数）；
2. 若日后作业区实测场地高程与交付包不符（交付包本身错），基准改为**实测值**，并同笔更新本条与 `groundLevel()`；
3. 纳入哪些细瓦片会影响 u₀ ±2 m 级（本次用 `t4_*`/`t5_*` 全集；只有作业区那 7 块参与渲染）——若要把口径收紧到"只按渲染中的瓦片"，需另立判据（当前不收紧，因场地本身起伏就有 ±5 m）。

**三条结论**：

1. **竖直基准三套并存**：枢纽构件 = 交付包各自的**局部平面**（三个枢纽互差 14 m）；运河带 = 根原点
   **切平面**；港区 = **真实高程**（陆域 ≈ +5 m 正高，符合钦州港实况）。地形关模式下表现为
   「运河侧整体上浮、港区整体下沉」，**方向相反**。
2. **运河带没有烘焙椭球曲率**（新根因）：`tools/3dtiles-build/build-canal.mjs:103` 的
   `const u = groundU + lift` 是**常量**，`glb.mjs:26 enuToGltf` 只换轴序不改数值 ⇒ 整条带是
   根原点切平面上的平板，其大地高 = d²/2R。三枢纽实测吻合：马道 d=29.5 km → 预测 +68.2 / 实测 +69.7；
   企石 17.5 km → +24.1 / +24.6；青年 28.0 km → +61.7 / +61.5。远端（郁江口 d≈58 km）理论浮空 ≈260 m，
   实测带水最大 +202（P95）。⇒ 带与枢纽模型在同一处竖直相差 **+59.2 / +10.9 / +39.8 m**（马道/企石/青年）。
3. **视差分量**：地形关时上述 15~260 m 竖直偏置在斜视角下表现为**与机位相关的横向视差**
   （量级 ≈ h·视角相关项），与 §8.16–8.18 的横向残差同量级，**且平面工具分辨不出** —— 这是"没正位"的
   第三个分量（前两个：横向残差、LOD）。

**待裁（不自行选边）**：① 只修运河带曲率（判据明确：三枢纽处带水高度不再等于 d²/2R，而与枢纽/设计
水位一致）；② ①+把三枢纽构件按「地面 = 椭球 0」重摆（治视差；代价：不再表达真实高程）；
③ ①+按真实正高摆三枢纽（须开真地形，与互斥裁定冲突）。港区是否抬 15~18 m 与 ①②③ 同批定。
