# DEM 渲染管线技术方案（A 路线）

> 产出日期：2026-07-30
> 背景：用户已用 SAGA 完成 ASTER GDEM 30m 填洼，交付 `filled_CGCS2000_int16.tif`（tmerc / Int16 / NoData=32767）。
> 决策：用户选择 A 路线「真做 DEM 渲染管线」，要求先出技术方案、不动代码，待评审后再实施。
> 适用纪律：阶段六决策铁律——本文所有带「待拍板」的项，均由用户逐项决策，AI 不代选。

---

## 1. 目标与范围

把填洼后的真实 DEM 接入北部湾 WebGIS 平台，让洪涝模块从「预置 JSON 驱动」升级为「真 DEM 驱动」，并能在地图上渲染真实地形。

**交付边界（A 路线）**
- 2D（OpenLayers）：叠加真实 DEM 山体阴影 / 着色地形图层。
- 3D（Cesium）：加载真实 DEM 地形（真 z 值起伏，数字孪生核心）。
- 后端：洪涝淹没范围由 DEM 实时/离线计算生成，替换手写 `floodArea.json`。

**不在本路线范围**
- PostGIS / GeoServer 空间数据库（属阶段二演进，本文仅标注衔接点）。
- 业务功能堆砌；本文专注于「让真实 DEM 进项目」的数据链路与渲染。

## 3. 坐标系策略（共同前置）

填洼必须在**米制坐标系**做（已完成，正确）。但 Web 地图全是经纬度（4326），tmerc 米制 DEM 无法直接采样/显示。

**决策：以 `filled_CGCS2000_int16.tif` 为母本，离线派生一份 EPSG:4326 版本作为所有增量的统一输入。**

```bash
# 派生 4326 版（GeoTIFF，保留 Int16 + NoData=32767）
gdalwarp -t_srs EPSG:4326 -dstnodata 32767 \
  filled_CGCS2000_int16.tif dem_4326.tif
```

后续 增量①②③ 全部基于 `dem_4326.tif`，避免重复重投影。

## 5. 增量① 2D 真实地形渲染（低风险，立即见效）

**目标**：在 OL 地图上叠加真实 DEM 山体阴影/着色图层，面试官立刻看到「这是真地形」。

### 5.1 离线处理（GDAL CLI，已验证可用）
```bash
# 山体阴影（Byte，体积小，适合 Web）
gdaldem hillshade dem_4326.tif dem_hillshade.tif -z 1.5 -az 315 -alt 45 -of COG
# 高程着色（可选，elevation colormap）
gdaldem color-relief dem_4326.tif colormap.txt dem_color.tif -of COG
# 加 overviews 提升浏览器缩放性能
gdaladdo dem_hillshade.tif 2 4 8 16
```
产物放 `frontend/public/data/dem/`（静态托管）或后端 static。

### 5.2 前端改动
1. `types/core/layerManager.ts`：扩展 `LayerType` 联合类型，加 `'geotiff'`。
2. `core/map/layerAdapters.ts`：在 `LAYER_ADAPTERS` 加 `geotiff` 条目，调用 `renderer.addGeoTIFFLayer(key, url, options)`。
3. `OLRenderer.js`：实现 `addGeoTIFFLayer` ——
   ```js
   import GeoTIFF from 'ol/source/GeoTIFF'
   const src = new GeoTIFF({ sources: [{ url }], normalize: false })
   const layer = new TileLayer({ source: src, opacity: 0.7 })
   this.map.addLayer(layer)
   ```
   （`ol/source/GeoTIFF.js` 在 OL 10.9.0 **已存在**，无需新增依赖。）
4. 洪涝页 / 选址页通过 `BusinessLayerManager` 注册 `geotiff` 图层（写入端），不绕过 Manager（规避 E13① 类架构违规）。

### 5.3 验收标准
- `npm run typecheck` 0 错误；`npm run build` 通过。
- 启动 dev，洪涝页可勾选「真实地形」图层，地图显示 DEM 山体阴影，与钦州边界对齐（无偏移）。
- 图层走 BusinessLayerManager，路由切换无残留（对照 a013）。

### 5.4 风险与回退
- **42MB 单文件在浏览器解码偏重**：用 COG + overviews 缓解；若仍卡，改用 `gdal2tiles` 切 XYZ/PNG 瓦片（生产级）。demo 阶段 COG 足够。
- Cesium 渲染器暂不实现 geotiff（3D 走增量③），`addGeoTIFFLayer` 在 Cesium 侧标 optional，避免破坏双引擎契约。

## 6. 增量② 后端真洪涝计算（让分析变真，最大加分）

**目标**：淹没范围由 DEM 实时/离线计算，替换手写 `floodArea.json`；设施点高程由 DEM 采样刷新。把「假 JSON 驱动」翻成「真 DEM 驱动」。

### 6.1 计算逻辑（与坐标系无关，DEM 像元值即高程米）
```
对每个水位档 level：
  mask = (DEM <= level) AND (DEM != NoData)
  裁剪 mask 到区域边界（钦州/北部湾边界 GeoJSON）
  多边形化 mask → GeoJSON FeatureCollection（带 riskLevel/waterLevel 属性）
```
设施高程：`gdallocationinfo dem_4326.tif lon lat` 逐个采样 → 更新 `facilityPoints.json.elevation`。

### 6.2 实施方案对比（诚实，含沙箱限制）

| 方案 | 做法 | 风险 | 推荐度 |
|---|---|---|---|
| **X 预生成（离线）** | GDAL CLI 离线算好 GeoJSON，落入 `backend/data/flood/`，现有端点零改动返回 | 最低；无运行时依赖、无注入面 | ⭐ 首推 |
| Y 实时端点 | 后端 `child_process` 调 `gdal_calc`/`gdal_polygonize` 按任意水位实时算 | 需校验 waterLevel（防 A02 类越权/注入）；有延迟 | 进阶 |
| Z node-gdal | 前端/后端直连 `node-gdal` 绑定 | ❌ **本沙箱无法编译原生扩展**，不可用 | 否决 |

> 沙箱限制实锤：node 原生 gdal 绑定需 C++ 编译，环境无编译器 → **不选 Z**。
> GDAL CLI 已通过 QGIS 安装验证可用；Python `rasterio` 在托管 venv 安装风险高（需 GDAL 头文件）→ **优先 X，Y 用 GDAL CLI 而非 rasterio**。

### 6.3 数据流（方案 X）
- 离线产物直接替换 `backend/data/flood/floodArea.json`（多档位）与 `facilityPoints.json`（真实高程）。
- 前端 `floodAdapter` 仍走 `getFloodAnalysis` → 现有契约不变，**对前端透明**。这正是 Adapter 模式的价值：数据源从「手编」变「DEM 派生」，业务层无感。

### 6.4 验收标准
- `floodArea.json` 各档位多边形与 `dem_4326.tif` 在 QGIS 中叠加吻合（DEM<=level 区域 == 多边形）。
- `facilityPoints.json.elevation` 与 `gdallocationinfo` 采样值一致（抽 5 点核对）。
- 洪涝页切换水位，淹没范围随 DEM 真实变化（非手写档位跳变）。
- 若做 Y：`waterLevel` 入参校验 `isFinite + 下限 + 上限`（补 A02/B-R2 缺口）。

### 6.5 风险与回退
- 多边形化在海岸线复杂边界可能产生碎面 → `ogr2ogr -simplify` + 面积阈值过滤。
- 预生成（X）覆盖率有限（仅预设档位）；实时（Y）覆盖任意水位但引入运行时复杂度。建议 **X 先交付，Y 作为演进项**。

## 7. 增量③ Cesium 真三维地形（最高风险，数字孪生核心）

**目标**：Cesium 加载真实 DEM 地形瓦片，实现真 z 值起伏（非贴图）。

### 7.1 瓦片生成（⚠️ 可行性门禁）
Cesium 真地形需 **quantized-mesh** 瓦片。生成工具：
- `cesium-terrain-builder`（Python 包，底层包裹 C++ `ctb` 库）→ **需 C++ 编译**，本沙箱能否装必须实测。
- `quantized-mesh`（Python 包）→ 需验证可安装性。

**门禁动作（实施前必做）**：在托管 Python venv 试 `pip install cesium-terrain-builder`，确认能构建；失败则 增量③ 降级为 7.3 回退方案，并如实记录。

### 7.2 前端改动（若瓦片生成可行）
```js
// CesiumRenderer.js
const terrain = await CesiumTerrainProvider.fromUrl('/terrain/')
viewer.terrainProvider = terrain
```
图层入口：`layerAdapters.ts` 加 `terrain` 类型（注释已预留），`CesiumRenderer` 实现 `addTerrainLayer`。

### 7.3 回退方案（瓦片生成不可行时）
用山体阴影栅格做 Cesium **ImageryLayer 贴图**，叠加在 `EllipsoidTerrainProvider`（平面球）上：
- 视觉有地形明暗感，但**无真 z 值**（非数字孪生级）。
- 诚实标注：这是「伪三维」，面试时讲清与真地形的区别，反而显专业。

### 7.4 验收标准
- 真地形：Cesium 视角倾斜可见海岸/地势真起伏，与 2D 山体阴影空间一致。
- 回退：球体有地形贴图，但剖面无 z 起伏（如实说明）。

### 7.5 风险
- C++ 构建失败（最高概率阻断真地形）→ 门禁前置验证。
- 瓦片体积大 → 需切片 + 静态托管，部署注意 nginx（当前仅 gzip，无缓存，见 PERF 项）。
