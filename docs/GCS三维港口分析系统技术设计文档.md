## 第一章 项目背景与升级目标

### 1.1 当前系统（v1.0）

**项目名称**：北部湾港WebGIS综合分析平台

**技术栈**：

- 前端：Vue 3 + OpenLayers + Turf.js + ECharts + Element Plus
- 后端：Node.js Express + JSON数据存储 + JWT用户系统

**已完成业务**：

- 港口选址分析系统（地图交互、缓冲区分析、POI设施分析、权重计算、结果展示）
- 已公网部署

### 1.2 v2.0升级目标

本次升级不是简单增加页面，而是**WebGIS平台化重构**。

**核心目标**：从二维地图业务系统升级为支持二维与三维业务扩展的综合GIS平台。

**主要升级**：

1. 新增Cesium三维业务能力
2. 建立统一业务模块规范
3. 建立统一数据接口
4. 建立统一UI Panel规范
5. 优化地图引擎生命周期

### 1.3 设计原则

| 原则     | 说明                                             |
| -------- | ------------------------------------------------ |
| 工程演进 | 证明有能力把已上线项目继续演化，不是堆企业级名词 |
| 业务闭环 | v1证明业务闭环，v2证明架构可扩展                 |
| 控制范围 | 学生项目可上线规模，不设计生产级系统             |
| 按需加载 | Cesium不独立页面，根据路由按需初始化             |

## 第二章 系统架构设计

### 2.1 整体架构

```
App
 |
 HomeLayout
 |

 |
 +-- 首页 (OpenLayers)
 +-- 选址分析 (OpenLayers)
```

**说明**：

- Cesium不是独立项目，是主系统的一个业务路由

```
+-----------------------------------------------------------+
|  可视化层 (Visualization)                                   |
|  |-- Cesium渲染器 (CesiumRenderer扩展)                      |
|  |-- ECharts图表 (剖面图、统计图)                            |
|  +-- GCS面板系统 (4x4 Cell布局)                             |
+-----------------------------------------------------------+
|  数据访问层 (Data Access)                                   |
|  |-- GCS统一API客户端 (/api/gcs/*)                          |
|  +-- 数据缓存策略                                           |
+-----------------------------------------------------------+
|  后端服务层 (Backend)                                       |
|  +-- Node.js Express + JSON文件存储                         |
+-----------------------------------------------------------+
```

## 第三章 地图引擎生命周期

### 3.1 核心问题

**问题**：

- Cesium体积大（~5MB JS）、GPU占用高（200~400MB内存）
- 首屏加载会影响普通OL业务性能
- 2D/3D业务频繁切换时，重建Viewer开销大

**解决方案**：单例缓存 + 按需挂载。

### 3.2 生命周期设计

```
首屏加载：
  只加载OpenLayers，Cesium不加载

用户首次点击Cesium路由（如/heatmap）：
  |
  v
路由守卫检查 meta.engine === '3d'
  |
  v
动态加载Cesium模块（首次）
  |
  v
创建CesiumViewer单例
  |
  v
挂载到当前路由的DOM容器
  |
  v
OL隐藏（v-if移除DOM）

用户切回OL路由（如/selection）：
  |
  v
CesiumViewer从DOM卸载（unmount）
  |
  v
Viewer实例保留（不销毁）
  |
  v
OL重新挂载

用户再次进入Cesium路由：
  |
  v
复用已有Viewer实例
  |
  v
重新挂载到DOM
  |
  v
状态保留（相机位置、图层等）
```

### 3.3 关键设计决策

| 决策           | 选择                | 原因                          |
| -------------- | ------------------- | ----------------------------- |
| Cesium加载时机 | 路由级按需加载      | 首屏只加载OL，降低首屏时间    |
| Viewer生命周期 | 单例缓存 + 按需挂载 | 创建一次，反复挂载，避免重建  |
| 引擎切换       | 根据路由meta决定    | 自动化，取消手动2D/3D切换按钮 |
| 底图携带       | 记住底图类型        | 切换引擎后加载对应Cesium底图  |

### 3.4 CesiumViewer单例管理器

```
CesiumViewerManager:
  - create()    → 首次创建Viewer
  - mount(el)   → 挂载到指定DOM容器
  - unmount()   → 从DOM移除（不销毁Viewer）
  - destroy()   → 真正销毁（一般不调用）
  - getInstance() → 获取单例

路由切换时：
  OL路由 → viewer.unmount()，OL显示
  Cesium路由 → viewer.mount(el)，OL隐藏
```

### 3.5 性能对比

| 方案         | 首屏加载 | 切换速度  | 内存占用      | 状态保留 |
| ------------ | -------- | --------- | ------------- | -------- |
| v-show共存   | +5MB     | 瞬间      | 常驻200~400MB | 天然     |
| v-if重建     | 0        | 2~3秒     | 用时才有      | 丢失     |
| **单例缓存** | **0**    | **0.5秒** | **用时才有**  | **保留** |

### 3.6 实现要点

- 首屏只加载OL，Cesium按需加载
- CesiumViewer单例模式，全局只创建一次
- 离开Cesium路由时unmount（不销毁）
- 再次进入时mount复用，状态保留
- 隐藏时设置 `requestRenderMode = true` 暂停渲染，降低GPU占用

## 第四章 路由设计

### 4.1 路由入口

**入口**：Dock栏第4个按钮"三维分析"（原"热力图"）

```javascript
// 路由配置
{
  path: '/heatmap',
  name: 'GCSAnalysis',
  component: () => import('@/business/gcs-analysis/GCSAnalysisPage.vue'),
  meta: {
    engine: '3d',  // 触发Cesium引擎
    title: '三维港口分析'
  }
}
```

### 4.2 路由说明

| 属性   | 值         | 说明                                    |
| ------ | ---------- | --------------------------------------- |
| path   | `/heatmap` | 复用原热力图路由                        |
| engine | `3d`       | 触发Cesium引擎，自动切换                |
| layout | 继承       | 继承Home Layout的壳（顶部标题、Dock栏） |

### 4.3 引擎自动切换

**取消手动2D/3D切换按钮**，由路由meta.engine自动驱动：

| 路由                    | meta.engine | 使用的引擎 |
| ----------------------- | ----------- | ---------- |
| `/` (首页)              | `2d`        | OpenLayers |
| `/selection` (选址分析) | `2d`        | OpenLayers |
| `/heatmap` (浸没分析)   | `3d`        | Cesium     |
| 未来：航线分析          | `3d`        | Cesium     |

**切换流程**：

```
用户点击Dock栏按钮
  |
  v
路由守卫检查目标路由的meta.engine
  |
  v
如果engine变化：
  |
  +-- 从2d到3d：加载Cesium模块，创建/复用Viewer，隐藏OL
  |
  +-- 从3d到2d：卸载Cesium DOM，显示OL
  |
  +-- 同引擎切换：无需切换引擎
```

### 4.4 页面结构

```
GCSAnalysisPage.vue
+-----------------------------------------------------------+
|  Cesium场景（全屏背景）                                      |
|  +-------------------------------------------------------+|
|  |  水位模拟面板 (top-left)                                ||
|  +-------------------------------------------------------+|
|  |  剖面分析面板 (top-right)                               ||
|  +-------------------------------------------------------+|
|  |  淹没分析面板 (bottom-left)                             ||
|  +-------------------------------------------------------+|
|  |  港口影响面板 (bottom-right)                            ||
|  +-------------------------------------------------------+|
+-----------------------------------------------------------+
```

### 4.5 图层携带策略

**核心原则**：数据层引擎无关，图层对象按引擎重建。

#### 4.5.1 数据层 vs 图层对象层

```
数据层（引擎无关，可共享）：
  - GeoJSON数据
  - 坐标、属性
  - 样式配置
  ↓
  +-- OL渲染器 → 创建 ol/layer/Vector
  +-- Cesium渲染器 → 创建 GeoJsonDataSource / Primitive

切换引擎时：
  数据保留 → 销毁旧图层对象 → 用新渲染器重建
```

#### 4.5.2 可携带的图层

| 切换方向    | 可携带                       | 不可携带                    |
| ----------- | ---------------------------- | --------------------------- |
| OL → Cesium | 业务GeoJSON（POI、缓冲区等） | OL特有样式效果              |
| Cesium → OL | 业务GeoJSON数据              | 3D模型、地形、水面Primitive |

#### 4.5.3 底图携带

**策略**：记住底图类型，切换引擎后加载对应Cesium底图。

```
用户在OL选择天地图影像底图
  |
  v
localStorage记录：baseMapType = 'tianditu_img'
  |
  v
切换到Cesium
  |
  v
读取localStorage，加载Cesium版天地图影像
```

## 第六章 业务模块设计

### 6.1 水位模拟模块

**目标**：模拟港口区域水位变化。

**功能**：

- 无极水位调节（0~10米，步进0.1米）
- 快捷水位档位（平均海平面、设计高潮位、极端最高水位）

**数据流程**：

```
用户拖动Slider
  |
  v
节流处理（100ms）
  |
  v
更新waterLevel状态
  |
  v
CesiumRenderer更新水面高度
  |
  v
切换对应淹没范围GeoJSON
```

**数据来源**：

- `waterLevel.json`：5个基准水位，3个潮汐站
- `floodArea.json`：5级水位淹没范围GeoJSON

**Cesium表现**：

- 水面使用Primitive渲染（非Entity）
- 根据水位切换淹没范围
- requestRenderMode，仅在水位变化时渲染

**面板设计**：

```
水位模拟面板 (4x2 Cell)
|-- 标题：水位动态模拟
|-- Slider：0~10米，步进0.1米
|-- 快速切换：平均海平面(2.5m)、设计高潮位(4.5m)、极端最高水位(6.8m)
+-- 显示：当前水位高度
```

### 6.2 剖面分析模块

**目标**：展示地形变化。

**功能**：

- 选择预设剖面线
- 生成ECharts高程剖面图

**数据流程**：

```
用户选择剖面线
  |
  v
读取terrainProfile.json对应剖面数据
  |
  v
ECharts折线图（X轴：距离，Y轴：高程）
  |
  v
叠加水位线
```

**数据来源**：

- `terrainProfile.json`：4条预设剖面线，53个采样点

**面板设计**：

```
剖面分析面板 (4x2 Cell)
|-- 标题：剖面分析
|-- 下拉选择：4条预设剖面线
|-- 按钮：生成图表、导出PNG
+-- ECharts：高程剖面图（含水位线）
```

### 6.3 淹没分析模块

**目标**：根据不同水位展示影响区域。

**功能**：

- 显示淹没范围
- 对比不同水位结果
- 统计影响面积

**说明**：

- 当前版本采用模拟数据
- 不实现真实水动力模型

**数据来源**：

- `floodArea.json`：5级水位淹没多边形
- `floodStatistics.json`：6级水位统计数据

**面板设计**：

```
淹没分析面板 (4x2 Cell)
|-- 标题：淹没风险分析
|-- 统计信息：淹没面积、受影响建筑、受影响POI
|-- 图层控制：显示淹没范围、显示受影响POI
+-- 按钮：开始分析、清除结果
```

### 6.4 港口影响分析模块

**目标**：分析洪水对港口设施影响。

**功能**：

- 显示受影响设施
- 展示风险等级
- 计算模拟损失

**说明**：

- 采用模拟设施数据
- 定位为辅助决策展示
- 不设计成专业灾害模型

**数据来源**：

- `facilityPoints.json`：25个设施点（含value、damageRate）

**评估逻辑**：

```
损失计算：loss = value * damageRate

示例：
- 钦州港LNG接收站：80000万 * 0.98 = 78400万
- 防城港东湾油库：35000万 * 0.95 = 33250万
```

**面板设计**：

```
港口影响面板 (4x2 Cell)
|-- 标题：港口影响分析
|-- 评估结果：受影响设施数量、预估损失、影响等级
|-- 设施列表：名称 | 损失金额
+-- 按钮：生成报告、清除评估
```

## 第七章 数据设计

### 7.1 当前数据规模

**设计原则**：学生项目可上线规模。

| 数据类型 | 数量           | 存储方式 | 文件                 |
| -------- | -------------- | -------- | -------------------- |
| 基准水位 | 5个            | JSON     | waterLevel.json      |
| 淹没范围 | 5级x10个多边形 | JSON     | floodArea.json       |
| 统计数据 | 6级            | JSON     | floodStatistics.json |
| 剖面线   | 4条x53点       | JSON     | terrainProfile.json  |
| 设施点   | 25个           | JSON     | facilityPoints.json  |

**总计**：约100KB，无需空间索引。

### 7.2 数据结构

```
server/data/flood/
|-- waterLevel.json         // 5个基准水位，3个潮汐站
|-- floodArea.json          // 5级水位淹没范围GeoJSON
|-- floodStatistics.json    // 6级水位统计数据
|-- terrainProfile.json     // 4条剖面线，53个采样点
+-- facilityPoints.json     // 25个设施点（含value、damageRate）
```

### 7.3 数据格式说明

**facilityPoints.json 关键字段**：

| 字段       | 类型   | 说明                              |
| ---------- | ------ | --------------------------------- |
| id         | string | 设施唯一标识                      |
| name       | string | 设施名称                          |
| type       | string | 设施类型（泊位/码头/仓储区/油库） |
| port       | string | 所属港口（钦州港/防城港/北海港）  |
| longitude  | number | 经度                              |
| latitude   | number | 纬度                              |
| elevation  | number | 高程（米）                        |
| value      | number | 资产价值（万元）                  |
| damageRate | number | 损害率（0~1）                     |
| riskLevel  | string | 风险等级（低/中/高/极高）         |

### 7.4 未来扩展方向

**当前版本不做**：

- 空间Tile系统
- 4x4空间网格
- 动态Tile加载

**未来演进**（数据规模扩大时）：

- 增加空间索引
- 数据切片
- PostGIS空间查询
- Cesium 3D Tiles

## 第八章 API设计

### 8.1 API规范

**基础路径**：`/api/gcs/`

**返回结构**：

```json
{
  "code": 200,
  "data": {},
  "message": "success"
}
```

### 8.2 数据接口

| 接口                | 方法 | 说明         | 参数       | 返回                 |
| ------------------- | ---- | ------------ | ---------- | -------------------- |
| `/water-levels`     | GET  | 获取基准水位 | -          | waterLevel.json      |
| `/flood-areas`      | GET  | 获取淹没范围 | waterLevel | floodArea.json       |
| `/flood-statistics` | GET  | 获取统计数据 | waterLevel | floodStatistics.json |
| `/terrain-profiles` | GET  | 获取剖面数据 | -          | terrainProfile.json  |
| `/facilities`       | GET  | 获取设施点   | -          | facilityPoints.json  |

### 8.3 分析接口

| 接口                 | 方法 | 说明     | 参数       | 返回                  |
| -------------------- | ---- | -------- | ---------- | --------------------- |
| `/analysis/disaster` | POST | 灾害评估 | waterLevel | affected[], totalLoss |

### 8.4 未来PostGIS迁移

**当前JSON实现**：

```javascript
async function getFacilities() {
  const data = await fs.readFile('data/flood/facilityPoints.json')
  return JSON.parse(data)
}
```

**未来PostGIS实现**（接口签名不变，前端无需修改）：

```javascript
async function getFacilities() {
  const result = await db.query('SELECT * FROM facilities')
  return { facilities: result.rows }
}
```

## 第九章 Cesium性能优化

### 9.1 生命周期优化

| 优化项     | 方案             | 说明                    |
| ---------- | ---------------- | ----------------------- |
| 路由级加载 | 动态import       | 首次进入GCS才加载Cesium |
| 单例模式   | 全局唯一Viewer   | 避免重复创建            |
| v-show隐藏 | 离开时隐藏不销毁 | 再次进入直接显示        |

### 9.2 渲染优化

| 优化项            | 方案            | 说明           |
| ----------------- | --------------- | -------------- |
| requestRenderMode | 启用按需渲染    | 仅必要时渲染   |
| Primitive优先     | 水面用Primitive | 性能优于Entity |
| 控制Entity数量    | <1000个         | 避免帧率下降   |

**requestRenderMode实现**：

```javascript
const viewer = new Viewer(container, {
  requestRenderMode: true,
  maximumRenderTimeChange: Infinity,
})

// 数据更新后手动触发渲染
viewer.scene.requestRender()
```

### 9.3 数据优化

**当前**：

- 小规模JSON（100KB）
- 直接读取，无需优化

**未来**：

- 空间数据库
- 数据切片
- 按需加载

### 9.4 交互优化

| 优化项     | 方案  | 说明         |
| ---------- | ----- | ------------ |
| Slider节流 | 100ms | 避免频繁更新 |
| 相机防抖   | 300ms | 避免频繁加载 |

**Slider节流**：

```javascript
let sliderTimer = null
function onSliderChange(value) {
  clearTimeout(sliderTimer)
  sliderTimer = setTimeout(() => {
    updateWaterLevel(value)
  }, 100)
}
```

### 9.5 优化优先级

| 优先级     | 优化项                           | 实现时间 |
| ---------- | -------------------------------- | -------- |
| P0（必须） | requestRenderMode、Primitive水面 | 1天      |
| P1（推荐） | Slider节流、相机防抖             | 1天      |
| P2（可选） | 未来Tile切片、LOD分级            | 3天      |
