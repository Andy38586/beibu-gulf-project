## 一、一句话结论

本次仓库损坏**不是单一 bug**,而是 **8 窗口并行编辑同一工作树(无 worktree 隔离)** 触发,叠加 **agent 提交工作流在本环境下的系统性失效**(被杀的提交 + 自动 gc + 激进自修)与一次 **中文路径编码事故**。

- 最初触发:**用户按 8 批次开 8 窗口并行改同一工作区**,git 单仓库 index/refs 写入互斥抢锁 + 批次文件重叠后写覆盖先写 → cache-tree 损坏 + 20+ missing blob。
- 扩大层:**agent 在 ~120s 短超时下执行 `git commit`,触发 husky `npx lint-staged`(扫数百前端文件)被杀死**,随后连锁(留锁/孤儿对象 → 自动 gc 误删 → 修复 agent 激进自修 + IDE 后台 git 删 refs/)。
- 独立事故:`git checkout` 经 Git Bash 传递中文路径被篡改,把工作树整体覆盖回 `origin/main`。

- **F1 终态**:`.git/refs/` 缺失/空、`.git/index` 损坏(缓存树/resolve-undo 指向非法 sha1,缺失 blob `b49f2f9`)、工作树被覆盖(临时丢失 45 处本地修改 ≈1818 行,后从整树备份救回)。

## 三、根因(触发层 → 上游 → 下游)

### 触发层(本次损坏的起点)

- **T1(8 窗口并行编辑同一工作树)**:用户按 8 批次开 8 个窗口并行改同一工作区。两路失效:① git 单仓库 index/refs 写入互斥,并发 commit 抢锁;② **批次间文件重叠**(floodAdapter/forecastAdapter 属批次 2+3、OLRenderer/CesiumRenderer 属批次 4+6、useApiRequest 属批次 2+4),后写覆盖先写。结果:`fsck` 报 cache-tree 损坏 + 20+ missing blob(lint-staged 的 stash 与并发写对象库竞争,导致 index 指向未写完的对象)。这是本次 index 损坏与缺失对象的**最初来源**。

### 上游 / 下游(修复过程让损坏扩大)

- **RC-A(修复层起火点)**:agent 提交触发 husky `npx lint-staged` 扫数百前端文件,耗时超过 agent 工具 ~120s 超时 → commit 进程被杀。
- **RC-B**:进程被杀后留 `.git/index.lock`、半写 `.git/index`、孤儿松散对象,**无人善后**。
- **RC-C(二次损坏)**:默认 `gc.auto` / `maintenance.auto` 在后续某次 git 操作时自动执行,把 RC-B 留下的孤儿对象(仍被悬挂引用/损坏 index 半指向) prune 掉 → 对象损坏(`b49f2f9` 丢失)。
- **RC-D(refs/ 被删的真正原因)**:修复 agent(含主 agent)随后做**激进自修**——对 `.git` 跑 `rm`(被拦截留半成品)、移动/重写 refs、重写 packed-refs——与 **IDE 后台 git(Cursor autofetch / backgroundValidation)** 并发撞车,导致 `.git/refs/` 被移除。
  - **纠正记录**:本 agent 最初把"git 自身 pack-refs/rmdir 空 refs 目录"误判为根因。该机制 git 确实能做,但**本次删除是修复过程 + IDE 所为,非 git 自发**(F2 已反证 checkout 不删 refs)。此误判已更正。
- **RC-E(独立事故,另一根)**:任何"可能覆盖工作树"的 git 操作若经 Git Bash 传递中文路径 → pathspec 篡改 → 工作树被整体覆盖。

### 哪个是真正的"根"?

没有单一根,是一条**触发 → 扩大**链:

- **最初触发是 T1**(8 窗口并行编辑同一工作树,无 worktree 隔离 + 批次文件重叠)→ 直接造成 cache-tree 损坏 + 缺失对象。
- **扩大层是 RC-A→B→C→D**(agent 在超时下被杀死的提交 + 自动 gc 补刀 + 修复 agent 自己下狠手 + IDE 后台 git)。
- **RC-E 是独立另一根**(中文路径编码)。
- 简言之:仓库坏成 `not a git repository`,几乎总是"**并发/被杀的提交 + 自动 gc + 激进自修**"三连,git 自身很少是元凶。

## 四、解决方案(对应根因)

| 根因 | 方案                                                                                                                                                                                                                                                                                | 状态                              |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| T1   | 并行改同一仓库用 `git worktree` 隔离(每批次独立 index/工作树,共享 objects/refs,不抢锁);前提=批次间文件零交集(先重新划批重叠文件)或串行。命令:`git worktree add ../beibu-batch2 -b batch-2` → 该目录正常 commit → 主仓库 `git merge batch-2` → `git worktree remove ../beibu-batch2` | 已教用户                          |
| RC-A | agent 提交**绝不在短超时下跑 husky**:用 `git commit --no-verify`(lint 挪到 CI),或给钩子 ≥5min                                                                                                                                                                                       | 已立为红线                        |
| RC-B | 提交前先查 `.git/index.lock`;存在则停手;被杀后 `mv`(非 `rm`)清锁再重试                                                                                                                                                                                                              | 已立为红线                        |
| RC-C | 本仓库关自动 gc/maintenance:`gc.auto=0` `maintenance.auto=false` `gc.autodetach=false`                                                                                                                                                                                              | **已落地**                        |
| RC-D | agent **只报告 git 异常,不激进自修**:禁 `rm .git`、禁擅自重写 packed-refs/移动 refs;关 IDE 后台 git(Cursor 已删;VSCode autofetch 已在 `.vscode/settings.json` 关)                                                                                                                   | 已立为红线 + 部分落地             |
| RC-E | 中文路径**绝不经 bash 直传**:走 Python `subprocess`(list args, UTF-8/UTF-16)或 `--pathspec-from-file`;任何覆盖工作树操作前先 `robocopy` 整树备份(不含 `/PURGE`)                                                                                                                     | **已落地**(本次靠 23:11 备份救回) |
