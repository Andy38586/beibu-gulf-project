## 一、已修复（7 项）

### 1. 专项1 P0-2 正式数据含占位符 —— ✅ 已修
- **改动**：`backend/data/ports.json` 删除 3 处伪造 phone 字段（"0779-xxx"/"暂无"×2）；前端 `PortInfoPanel.vue:26` 已有 `phone || '暂无'` 兜底，无需改前端；`types/map.ts` phone 为可选字段，契约兼容。
- **理由**：演示数据不编造联系方式（面试诚实性原则）；缺失由 UI 兜底。
- **验证**：JSON 语法合法；类型契约 `phone?: string` 兼容。
- **回滚**：`git revert` 该提交，或手动补回 3 个 phone 字段。

### 2. 专项8 8-1 查表键格式不匹配 —— ✅ 已修（P0 级阻断，一行修复）
- **改动**：`backend/controllers/floodAnalysisController.js` `lookupFloodZone`：`String(Math.round(level*10)/10)` → `(Math.round(level*10)/10).toFixed(1)`（表键为 "0.0"/"3.0" 格式，整数档此前全部 miss，251 档表退化为 6 档）。
- **验证**：实测 0/0.5/1/2.5/3/5/10/15 全部命中 251 档表（此前整数档 miss）。
- **回滚**：`git revert`；或把 `toFixed(1)` 改回 `String(...)`。

### 3. 专项8 8-6 水位 0 档虚淹没 —— ✅ 已修
- **改动**：`backend/flood-service/main.py` `flood_online`：`key <= 0 且 floodedKm2 > 0` 时归零（预计算 0 档存在海面种子误差 floodedKm2=6.87 但 features 空，导致前端"淹没 6.87km²"数字与空地图矛盾）。
- **理由**：02 §4.3 应然契约「水位 0 → 无淹没」；前端 `_riskLevelFromFlood` 已有 level<=0 特判，本修改补齐面积数字。
- **验证**：Express 侧 floodArea.json 0 档 features=0 已确认正常；FastAPI 0 档现返回 floodedKm2=0.0。
- **回滚**：删除该特判块。

### 4. 专项1 P1-6 除零 NaN —— ✅ 已修
- **改动**：`frontend/src/business/forecast/composables/useOverviewCharts.ts` 柱状图月均计算加分母守卫（空系列 → 0，不再 `reduce/0 = NaN`）。
- **理由**：02 §5.6 不变量 5（NaN 禁传播）；不变量 2（防御可触发——空系列是真实可达输入）。
- **回滚**：还原该 map 回调。

### 5. 专项2 F-3 登出快照残留 —— ✅ 已修
- **改动**：`frontend/src/stores/forecastStore.ts` 新增 `clearState()`（包装 `persisted.clearPersistedState()`）；`frontend/src/App.vue` `resetStores()` 登出时补调 `useForecastStore().clearState()`。
- **理由**：`reset()` 刻意不清快照（注释 L144 是设计，保证卸载重置链路）；但登出必须清——此前 forecast 快照在三 store 中唯一不可清，登出后残留，下次登录会恢复旧会话状态。flood/siteSelection 均有 clearState 且已在 resetStores 调用。
- **回滚**：删 App.vue 新增行 + forecastStore 的 clearState 定义与导出。

### 6. 专项1 P1-13 响应信封 code 契约偏离 —— ✅ 已修（文档漂移）
- **改动**：`docs/根基文档/开发指南与决策.md` §四 信封描述「成功 code=0」→「成功 code=同 HTTP 状态（200/201，权威口径见 API契约文档 §1.1）」。
- **理由**：API契约文档.md（活文档，03 指向）§1.1 明确「成功: HTTP 2xx + { code: <同 HTTP 状态> }」；03 是过时表述。代码（sendSuccess code=statusCode）与活文档一致，无需改代码；前端 unwrapEnvelope 不校验 code 值，行为正确。
- **回滚**：改回 code=0 表述。

### 7. 专项1 P1-8 底图 localStorage 键无版本化 —— ✅ 已修（白名单校验替代版本化）
- **改动**：`frontend/src/stores/mapStore.ts` `readStoredBaseLayer` 增加合法 key 白名单（base-image/base-vector，与 UnifiedMap.vue 注册处同源），非法旧值返回 null。
- **理由**：底图 key 集合演进后旧 localStorage 值会静默降级（UnifiedMap 的 `?? 'base-image'` 只兜 null 不兜非法值）；白名单校验比版本迁移更轻且不破坏现有存储。
- **回滚**：还原 readStoredBaseLayer。
