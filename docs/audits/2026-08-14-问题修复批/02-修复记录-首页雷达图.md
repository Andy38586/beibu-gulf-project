# 02-修复记录 · 首页雷达图复用选址分析数据源（2026-08-14）

## 现象
首页（AppLayout 默认右侧面板）的雷达图面板**无任何数据**（只有标题框）。

## 根因（两处叠加）

1. **AppLayout.vue 雷达图数据硬编码空值**：`:xiaoqu="null" :selected-types="[]" :facility-poi="{}"`——RadarChart 对 `xiaoqu=null` 用 `v-if` 整图不渲染（RadarChart.vue L124/128），面板恒空。
2. **siteSelectionStore 分析结果字段是死状态**：`matchedXiaoqu/selectedTypes/facilityPoi` 仅被 `clearState` 清空、**从未写入**——SiteSelectionPage 把结果只写页面本地 ref（L87-89），store 字段形同虚设。即使 AppLayout 接 store 也拿不到数据。

## 修复（复用选址分析同源数据，非首页另造）

| 文件 | 改动 |
| --- | --- |
| `stores/siteSelectionStore.ts` | 新增 `setResult({ matchedXiaoqu, selectedTypes, facilityPoi })` action（此前字段为死状态，补写入路径） |
| `business/site-selection/SiteSelectionPage.vue` | `handleResult` 与快照恢复 `restoreState` 两处调用 `stateStore.setResult(...)`，分析结果统一入 store |
| `visualization/charts/radarSnapshot.ts` | 从 `business/site-selection/composables/` **上移**到 visualization 层（radarSnapshot 仅依赖 types，层合规；core 与 business 均可引用）——原位置依赖 core→business 会违规 |
| `core/layout/AppLayout.vue` | 雷达图接 `useSiteSelectionStore`：`xiaoqu = matchedXiaoqu[0] ?? SNAPSHOT_XIAOQU`、`selected-types = selectedTypes.length ? selectedTypes : SNAPSHOT_SELECTED_TYPES`、`facility-poi = store.facilityPoi`——**与选址页同一数据源、同一快照兜底逻辑（面板不空态）** |

## 验证

- `vue-tsc` exit=0 ✓
- `dependency-cruiser` **0 violation**（164 模块）✓——core→stores 为设计确认例外，visualization 层移动后分层合规
- radarSnapshot 两处引用（SiteSelectionPage/AppLayout）已指向新路径 ✓

## 回滚

`git revert` 该提交；或手动：AppLayout 雷达图还原硬编码空值 + 删除 setResult 调用 + radarSnapshot 移回 business。

## 行为说明

- 分析过选址 → 首页/任意页右侧雷达图显示**第一名小区真实评分**（与选址页同步）
- 未分析 → 显示快照兜底（腾龙阁示例，与选址页一致，注释已声明为 UI fallback 非真实数据）
