## 一、产品定位（回答"用户是谁"）

### 1.1 定位一句话

> **港口选址情景推演与多准则决策支持平台**——不是"给政府做更准的选址系统"（做不到，政府有更精密的方案），
> 而是"快速探索'如果-那么'情景的决策研究工具"（政府没有的）。

### 1.2 为什么这个定位成立

| 政府/专业机构的方案 | 本平台 |
|---|---|
| 精确、高精度、大投入 | 快速、可复现、参数化 |
| 静态结论（一次评估） | **情景推演**（权重/假设可调，结论随情景变化） |
| 数据封闭 | 全开源数据 + 数据融合方法公开 |
| 黑盒 | 方法链透明（ARIMA → 权重 → 多准则叠加 → 矩阵输出） |

政府的痛点是"换一组假设就要重新委托评估"；本平台的价值是"假设可调、秒级重算、方法可审计"。
这是**研究方法论的价值**，不与政府方案竞争精度，竞争的是**探索效率与可复现性**。

### 1.3 用户三层模型

| 层 | 用户 | 消费什么 | 生命周期 |
|---|---|---|---|
| 直接用户 | 决策研究者 / 规划论证者（论文评审、规划前期论证、教学复现） | 方法链 + 可复现管线 + 情景案例 | 论文存续期 |
| 交互用户 | 面试官 / 演示场景 | "假设→参数→结论"完整案例（运河通航港址迁移） | 求职期 |
| 长期资产 | 未来的自己 | 工程能力证明 + 方法论沉淀 + 论文成果 | 入职后仍有效 |

**诚实结论**：这个项目不会有"日常使用者"——接受它。它的价值密度在**方法 + 工程**，不在运营。
"没用户 = 入职即死"的担心，通过"资产化"化解：应用会死，方法、论文、工程不会。

### 1.4 明确不做

- ❌ 大屏数字孪生（动效 > 数据，学生标配，面试贬值）
- ❌ 实时数据流（智慧港口需要港口企业真实系统对接，学生拿不到）
- ❌ 与政府精度竞争（定位不同，不战）
- ✅ 保留：情景推演交互（权重滑块/情景切换/地图联动）——展示思考而非装饰

## 二、技术架构（双后端定型）

### 2.1 三层架构

| 层 | 职责 | 技术 | 对应行业模式 |
|---|---|---|---|
| 业务系统层 | 认证/权限、方案收藏、情景配置、编排、API 治理 | **NestJS**（DI/Module/Guard/Interceptor/Pipe/Swagger） | Java 业务平台（Spring Boot 迁移路径） |
| 计算引擎层 | ARIMA、连通性演算、最短路径、选址评分、航线叠加、海底 DEM 插值 | **FastAPI**（APIRouter/scipy/networkx/statsmodels/geopandas） | Python 算法服务 |
| 数据层 | 空间数据存储与查询 | **PostGIS**（空间 SQL、pgRouting 可选） | 行业标准空间数据库 |

### 2.2 为什么双后端（面试叙事）

1. **职业发展**：NestJS 是 Node 中最接近企业级（Spring 系）的框架——装饰器/DI/模块化概念可直接迁移到 Spring Boot；FastAPI 覆盖算法侧。全栈能力 = 两种后端范式都握过。
2. **行业真实架构**：智慧城市/产业互联网的标准骨架就是"业务平台 + 算法服务"分离，本项目的双后端是这个模式的缩影，面试可直接讲。
3. **职责边界清晰**：业务系统层不碰算法，计算引擎层不碰用户——边界即架构。
4. **已有路线印证**：根基文档 `开发指南与决策.md` §1.5 已计划"后端迁移 NestJS"（routes→Controller、services→Injectable、middleware→Guard/Interceptor/Pipe）。

### 2.3 双后端的成本控制（契约先行）

- **最大成本**：前后端/双后端契约漂移（现 b034：无 OpenAPI、waterLevel/level 参数分裂 b027）。
- **解法**：**OpenAPI 契约先行**——NestJS（Swagger 一等支持）+ FastAPI（自动 OpenAPI）都从同一份契约开发；
  CI 加契约校验（`openapi-diff` 或生成客户端类型）。这本身就是企业级 API 治理能力，从"债"变"技能"。
- **部署**：双容器（业务容器 + 计算容器）或单容器双进程，nginx 内网反代计算服务（沿用现 flood-service 模式）。

### 2.4 迁移路径

1. `git branch archive/express-backend` 存档现有 Express（186 测试资产保留）。
2. NestJS 重写 auth/plans/CRUD（语义照搬，测试断言迁移）。
3. 计算服务逐步迁入 FastAPI（选址评分/预测 ARIMA 先，连通性演算已在）。
4. PostGIS 接入，JSON 文件 → 空间表（repositories 层替换，呼应"暂不用数据库"ADR 5 的必上路线）。

## 三、业务模块 × 数据支撑度矩阵（v3 范围）

| 模块 | 论文价值 | 数据源 | 支撑度 | 风险/备注 |
|---|---|---|---|---|
| 港口选址（多准则） | ⭐⭐⭐⭐⭐ 论文核心 | GlobeLand30（30m 地表覆盖，免费）；OSM+高德路网；工业区多边形（OSM/高德+公开边界人工勾绘） | ✅ 足 | 权重情景化见 §四 |
| 浸没→港口风险 | ⭐⭐⭐⭐⭐ 论文核心 | 陆地 DEM（已有）；**海底 DEM：GEBCO 2023（15 弧秒≈450m，区域尺度）/ 海图水深点数字化（港口尺度）** | ⚠️ 半 | **最大数据风险**：建议"海图水深点 + IDW/克里金插值"做数据融合，论文注明分辨率局限；数据融合方法本身是论文方法点 |
| 最短路径（港口↔工业园） | ⭐⭐⭐⭐ | OSM 广西路网（足）；pgRouting 或 networkx | ✅ 足 | 与选址联动为"可达性因子" |
| 吞吐量预测 | ⭐⭐⭐⭐ 支撑 | 北部湾港月度吞吐量（交通运输部/港口集团公开统计） | ✅ 足 | statsmodels SARIMA；价值在运河情景设定不在模型 |
| 航线分析（密度→新增港口） | ⭐⭐⭐ 支撑 | **AIS 数据国内不公开**；公开聚合源质量参差 | ⚠️ 弱 | 降级方案：公开 AIS 存档（MarineCadastre 等）+ 明确标注；或合成+标注。放最后，深度降档 |
| 城市发展指数 | ⭐⭐⭐ 支撑 | 统计年鉴/城市公开指标 | ✅ 足 | 与吞吐量预测合并为"情景输入"（§四） |

**决策规则：数据拿不到就砍模块，数据审计是 v3 第一周任务。**

### 补充因子（真实感来源，全部可入选址打分）

1. **生态红线**（一票否决）：钦州三娘湾中华白海豚栖息地、儒艮保护区边界公开——评审一眼认的"真实业务"
2. **集疏运体系**：南防铁路/黎钦铁路多式联运因子（不只公路）
3. **风暴潮/海平面情景**：复用淹没模型 + IPCC 情景水位，与浸没模块无缝衔接
4. **船型-水深适配**：航道水深 vs 目标船型吃水，与海底 DEM 同源复用
5. **运河影响量化**："到平陆运河口距离/通航时间"作为选址因子——论文变量落地

## 四、核心交互设计：情景推演闭环（回答"权重变了怎么办"）

### 4.1 数据流

```
城市发展指数 + 吞吐量（ARIMA 区间预测）
        ↓ 分档
情景预设：看好 / 中立 / 看衰   ← 与现有"置信度滑块"同构，可手动覆盖
        ↓ 映射
选址权重预设档（各因子权重随情景变化）
        ↓
选址评分（自然因子 × 情景权重）  ＋  可达性（最短路径时间/距离）
        ↓
双维矩阵输出：适宜性 × 可达性
```

### 4.2 双维矩阵（解决"路不通但很合适"）

| | 高可达 | 低可达 |
|---|---|---|
| **高适宜** | **即用型港址**（直接推荐） | **基建拉动型港址**（不淘汰！标注"需新建 X 公里连接线 + 估算成本"，联动最短路径模块） |
| **低适宜** | 淘汰 | 淘汰 |

- 权重不是死的：情景档位 = 权重预设 + 用户可调（现有置信度滑块是雏形）
- 码头模式分支：**扩建旧码头**（现有港区适宜性评估 + 扩展方向）vs **新建码头**（候选港址排序）；航线密度高 → 倾向新建（航线-选址联动）

### 4.3 演示案例（面试/答辩用）

> **"平陆运河 2026 年通航情景下，北部湾港最优港址迁移分析"**
> 假设：运河通航 + 吞吐量年增 8%（看好档）+ 生态红线不动 → 输出：即用型/基建拉动型港址清单 + 与现状港区的对比 + 港址迁移方向结论。
> 一个完整故事 = "输入假设 → 调参数 → 出结论"，比任何大屏都更能展示思考。

## 五、生命周期与资产策略（回答"没用户是不是致命"）

| 资产 | 载体 | 存续期 |
|---|---|---|
| 学术产出 | 毕业论文（方法链 + 案例分析） | 永久 |
| 方法管线 | 可复现的数据→分析→可视化管线（开源数据 + 文档化流水线） | 论文复现/教学场景 |
| 工程能力 | CI/测试/双后端/PostGIS 作品集 | 求职期高价值 |
| 应用本体 | 平台本身 | 诚实接受：无日常用户，入职后不再迭代 |

**行动项**：若时间允许，把"运河通航情景港址迁移"案例投一个学术会议/期刊——**审稿人就是第一个真实用户**，
"没用户"从缺点变成"已通过学术同行评审"的资历。
