## 做了什么

- `src/common/errors/business-error.ts`——错误码表 **9 项**逐项对齐老 Express `BusinessError.js`（含契约文档漏记的 401002/401003 登录细分码；`satisfies` 防漂移）。
- `src/common/interceptors/envelope.interceptor.ts`——全局成功信封 `{code: <同HTTP状态>, data}`（201 同值携带），对齐 `sendSuccess`；`@Res()` 直操路由自然绕过（health 探针保持手写信封）。
- `src/common/filters/business-error.filter.ts`——全局错误过滤：BusinessError → `{code, error, data:null}`；404 → `{code:404001, error:'接口不存在', data:null}`；429 → 裸 `{error}`（对齐 express-rate-limit message 形状）；未知错误 → 500001（生产隐藏 detail）。
- `src/common/utils/jwt.util.ts`——签发/验签（payload `{id,username,tokenVersion}`、7 天），secret 缺失/长度 <32 fail fast（对齐 Express 强校验）；验签失败返回 null 不抛错。
- `src/modules/auth/`——`AuthGuard`（cookie 优先/Bearer fallback + 用户存在性 + tokenVersion 三重校验，401 三文案逐字节对齐）+ `UsersRepository` 最小版（findById，供 guard 校验 tokenVersion）+ AuthModule。
- 限流：ThrottlerModule 全局 1000/15min（auth 50/15min 在 T3.1 挂路由级，forecast 豁免在 T3.4 加）。
- `main.ts`：cookieParser 中间件 + 全局前缀改 `nest-api`（对齐未来 Vite proxy/nginx 反代路径，与 Express `/api` 平行语义）。
- 测试 33 条全绿：错误码表 11 + jwt 4 + db.config 4 + guard 5（mock 仓储走全五路径）+ health 2 + contract e2e 7（信封 200/201、BusinessError、404、坏 token、守卫 401 两态）。

## 偏离与理由

1. **全局前缀 `nest` → `nest-api`**：T1.1 最初拍 `nest`，与未来反代路径 `/nest-api` 不一致会造成 proxy rewrite 需求；趁路由只有 health 时修正（T1.1 的 health 实测路径随之失效，属预期）。
2. **@SkipThrottle 移除**：@nestjs/throttler 的 named export 在 vitest ESM interop 下丢失（`SkipThrottle is not a function`，inline deps 配置无效）。探针计入全局限流（180 次/15min << 1000），风险可控；已留 `TODO(T6.3)` 部署整合时统一对齐。
3. **UsersRepository 提前建最小版**：guard 校验 tokenVersion 必须查用户表；T3.1 在此文件补全 CRUD。
4. **契约文档欠账登记**：`API契约文档.md` §1.3 错误码表写 7 项，代码实为 9 项（401002/401003 于登录细分上线时加入未回写文档）——以代码为权威，文档补记留待用户裁决（§1-§4 规则改动需谨慎）。
5. **坏 JSON body 行为差异**：Express 侧 malformed JSON → 全局错误中间件 500001；Nest 内建 BadRequestException → 400。前端 useApiRequest 永远发合法 JSON，该路径不可达，记录不处理。
