## 做了什么

- 契约 e2e：`test/swagger.e2e-spec.ts`——AppModule 实例化后 `createDocument` 产出合法 OpenAPI 3.x 文档、health 路由被扫描。该测试常驻 CI，等效守护 docs-json 链路（强于一次性 curl 验收）。

## 选型结论（任务卡要求落日志）

**DTO 注解为单一事实源（Nest 标准路径）+ CI 漂移校验兜底**，否决 zod-to-openapi：

- 前端 zod schema 在 `frontend/types/`（L0 零运行时依赖层），被 Nest 侧跨包引用会破坏前端分层契约（cruise 红线）；反向由 OpenAPI 生成 zod 则引入代码生成链。
- 落地方式：T3.x 各模块 controller 用 DTO 注解（`@nestjs/swagger` 装饰器）→ swagger 自动产出 OpenAPI → CI 脚本拉 `/nest-api/docs-json` 与前端 `types/schemas.ts` 推断形状比对（复用既有 `scripts/gen-api-contract.cjs --check` 思路扩展）。
- 双保险：CI 契约校验（形状漂移）+ T3.x 双后端 diff（行为等价）。契约校验脚本在 T3.1 首个真 controller 落地后编写（当前仅 health 路由，校验无意义）。

## 偏离与理由

- watch 进程二次崩溃（沙箱干扰 nest start --watch 的重载 spawn，两次 "timeout period expired" 后退出）——实机 curl 验收改为 e2e 常驻守护方案（更强）；**本环境下 watch 模式不可用，后续任务改用 build + 一次性进程或 e2e 验证**。
