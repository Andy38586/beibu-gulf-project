**接口契约**：

```ts
POST   /nest-api/task        { domain, params, priority:'high'|'normal' }
                             → { taskId, status, queuePosition, createdAt }
GET    /nest-api/task/:id    → { taskId, status, progress, queuePosition?, retryCount?,
                                 result?, error?, startedAt, finishedAt }
DELETE /nest-api/task/:id    → { taskId, status:'cancelled' }
```

**状态**：`pending` → `running` → (`retrying` →) `done` / `failed` / `cancelled`

**关键动作**：

1. 建 `TaskRecord` 类型 + 内存 `Map`。
2. 队列：数组 + `while` 消费，**并发上限 1**；`priority='high'` 插队首。
3. 重试：300/600/1200ms 指数退避 ×3；期间 `status='retrying'`，写 `retryCount`。
4. TTL：完成任务 30 分钟后回收（`setInterval`）。
5. 队列上限 8，超出直接拒绝。
6. 🔴 **task 端点必须挂 `@SkipThrottle({ login: true, register: true })`**（命名桶会误伤）。
7. 🔴 **内部复用既有 service**（不重写业务逻辑）。
8. 完成后 `node tools/v3-guard/routes-audit.mjs --gen`。

**验收**：

- [ ] `POST /task` 立即返回（< 100ms）
- [ ] `GET /task/:id` 能看到 `progress` 递增
- [ ] 两任务同时提交 ⇒ **串行**（第二个 `queuePosition > 0`）

### S2 — 前端 taskStore + useTaskApi

**目标**：任务状态托管，**按 route 分槽**（不变式 I8）。

**新增**：

| 文件                                            | 职责                                  |
| ----------------------------------------------- | ------------------------------------- |
| `frontend/src/stores/taskStore.ts`              | 状态（按 route 分槽）、轮询、结果托管 |
| `frontend/src/shared/composables/useTaskApi.ts` | task 端点客户端                       |
| `frontend/src/types/task.ts`                    | 类型                                  |

**关键设计**：

```ts
interface TaskState {
  taskId: string
  route: string
  domain: string
  status: 'pending' | 'running' | 'retrying' | 'done' | 'failed' | 'cancelled'
  progress: number
  queuePosition?: number
  retryCount?: number
  result?: unknown
  error?: { message: string }
  startedAt: number
  finishedAt?: number
}

// 按 route 分槽（一个路由同时只 1 个任务）
tasks: Record<string, TaskState | null>
```

**关键动作**：

1. `submit({ domain, params, route })`：调 `POST /task`，**priority = 该 route 是否为当前路由 ? 'high' : 'normal'**。
2. **轮询** `GET /task/:id`（建议 500ms 间隔），更新 `progress`/`status`。
3. 状态进 `retrying` ⇒ `showWarning('服务繁忙，正在重试…')`（🔴 **不暴露第几次**）。
4. 终态 `failed` ⇒ `showError(null, { fallback: '任务超时，请稍后重试' })`。
5. 同 route 再 `submit` ⇒ **旧任务自动 `cancelled`**。
6. `clearAll()` 供登出链调用。
7. 🔴 **store 不得 import 任何 renderer / OL / Cesium 类型**（不变式 I1/I2）。

**验收**：

- [ ] 单测覆盖状态机
- [ ] 分槽：A/B 两 route 互不干扰
- [ ] 同 route 再提交 ⇒ 旧的 cancelled
- [ ] 登出 `clearAll()` 清空
- [ ] 轮询在组件卸载后**不中断**（关键：任务保活）

### S4 — usePanelDrag + GCSPanel.draggable

**新增**：`frontend/src/shared/composables/usePanelDrag.ts`
**改动**：`core/layout/components/GCSPanel.vue`（+`draggable` prop，**默认 false**）

**状态机**：

```
idle ──pointerdown──▶ (待定) ──移动>4px──▶ dragging ──pointerup 命中 dock──▶ docking ──▶ docked
  ▲                      │                     │
```
