> **铁律**：以下 16 项为**用户拍板项**，AI 严禁代选。每个决策列「选项 + 推荐 + 影响」，用户确认后对应批次的相关条目才可实施。未拍板的条目在批次内保持 ⏸️阻塞，**不阻塞同批其他机械条目**。

## D-1 · b031 生产默认数据源（P0）

- **背景**：`main.ts:37` `VITE_DATA_SOURCE || 'mock'`，生产构建未设环境变量即默认 mock。
- **选项**：
  - **A. 默认改 `'api'`（推荐）**：生产安全，未配置时请求真实后端；开发时 `.env.local` 显式设 `VITE_DATA_SOURCE=mock`。
  - B. 保持 `'mock'` 默认：维持现状，仅补 `.env.example` 注释强调生产必须设 api。
- **影响**：A 使"未配置即跑 mock"的静默风险消失，但本地无后端时 npm run dev 前端数据全部失败（需开发环境配 .env.local）。B 改动最小但风险仍在。**建议 A**。

## D-2 · b025 预测热力图 `Math.random()` 造假（P0）

- **背景**：`forecastEngine.js:101-140` 用随机数生成 120 散射点；berth/traffic 指标 `INDICATOR_SOURCE` 硬编码 mock。
- **选项**：
  - **A. 叙事改"趋势外推 + 情景模拟"并 UI 标注合成数据（推荐）**：工作量小（0.5 天），把造假嫌疑转成诚实标注，符合 z041 叙事修复方向。
  - B. 后端补真实 berth/traffic 数据端点 + 前端核密度渲染：工作量数天，且需要真实数据源（当前无）。
- **影响**：A 解决面试风险（诚实化）但功能仍是模拟；B 解决功能但依赖不存在的真实数据。**建议 A，B 列入演进路线**。

## D-3 · b029 `getDEM()` 恒 mock（P0）

- **背景**：`floodAdapter.ts:308-311` 无论数据源均返回 `{source:'mock'}`；但 08-02 已接入真实 DEM 管线（`tools/dem-pipeline/`，floodArea.json 13 万行）。
- **选项**：
  - **A. 先实码核实 DEM 管线产物是否可被 getDEM 消费，可接则接（推荐）**：DEM 数据已存在，接通即可；若产物格式不匹配则退 B。
  - B. 改叙事"预设水位档位 3D 水面可视化"：放弃高程，工作量最小。
- **影响**：A 让三维淹没具备真实高程，面试叙事最强，需 0.5~1 天核实+接通；B 快但叙事降级。**建议先核实 A 可行性再定**。

## D-4 · b032 `getWaterArea()` api/mock 同实现（P0）

- **背景**：`floodAdapter.ts:181-187` 两模式都调 `_fetchMockWaterArea()`，后端无 `/flood/water-area` 端点。
- **选项**：
  - **A. 后端补 `/flood/water-area` 静态水域坐标端点（推荐）**：数据是静态配置，后端加一个读 JSON 的只读端点即可，0.5 天。
  - B. 前端显式标注"静态配置数据"：不接端点，文档化。
- **影响**：A 让 api 模式数据链路真实完整（面试加分）；B 保留前后端口径割裂。**建议 A**。

## D-6 · z042 核心渲染器去 @ts-nocheck（P0）

- **背景**：CesiumRenderer.ts（1036 行）/ OLRenderer.ts（625 行）第 1 行 @ts-nocheck，strict 失效。
- **选项**：
  - **A. 渐进补类型（推荐）**：按 D-6 已有策略，两个渲染器各拆 Part，逐个函数补类型，每补一块跑 typecheck，周期 3~5 天。
  - B. 一次性全量重写类型：风险高、周期长，不推荐。

## D-7 · z045 运行时校验方案（P0）

- **背景**：6 处外部数据边界 `as T` 断言，类型与运行时一致性零保障。
- **选项**：
  - **A. 引入 zod（推荐）**：`z.infer<>` 推导类型，schema 单一事实源，顺带服务 b034 契约同步。新增 1 个运行时依赖。
  - B. 手写轻量守卫函数（isXxx 谓词函数）：零依赖但每个 schema 手写，后续维护成本高。
- **影响**：A 是生态标准做法，依赖体积 ~13KB gzip；B 零依赖但 b034 想要的"单一事实源"打折。**建议 A**。

## D-8 · d064 回滚机制（P1）

  - **A. 镜像保留多版本 + 回滚脚本（推荐）**：docker-compose 用 tag 而非 latest，`scripts/rollback.sh` 切上一版本镜像重启。
