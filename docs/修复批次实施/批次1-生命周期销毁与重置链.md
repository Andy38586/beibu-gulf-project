## Part 1 · a023（P0）UnifiedMap 卸载清理不完整

### 现状（实码核实）
`UnifiedMap.vue:386-398`：
```ts
onUnmounted(() => {
  loadAbort.abort()
  _pendingRafIds.forEach((id) => cancelAnimationFrame(id))
  _pendingRafIds.clear()
  if (currentRenderer.value) {
    currentRenderer.value.destroy()
    currentRenderer.value = null
  }
})
```
- 只销毁 `currentRenderer`，**缓存渲染器** `olRenderer`（:44）/`cesiumRenderer`（:45）ref 未销毁、未置空。
- 未调 `mapStore.setCurrentRenderer(null)` → store 残留悬空引用（业务组件经 BLM 拿到的 currentRenderer 是死引用）。
- 未置空 `cesiumInitialized`（:46）——若组件被复用（严格模式下组件卸载重挂），Cesium 容器 v-if 仍判定已初始化。

### 目标改动（`UnifiedMap.vue` onUnmounted）
```ts
onUnmounted(() => {
  // z024: 卸载时 abort，阻止未完成的异步回调继续写 ref
  loadAbort.abort()

  // 取消所有待执行的 rAF 回调，防止组件卸载后仍操作 DOM
  _pendingRafIds.forEach((id) => cancelAnimationFrame(id))
  _pendingRafIds.clear()

  // a023: 停止可能排队的引擎切换（卸载后不再执行异步 initRenderer）
  switching.value = false
  pendingSwitchType.value = null

  // a023: 遍历销毁两个缓存渲染器（而非只销毁当前渲染器），销毁后 ref 显式置空
  const cachedRenderers = [olRenderer.value, cesiumRenderer.value]
  cachedRenderers.forEach((r) => {
    if (r) {
      try {
        r.destroy()
      } catch (e) {
        if (import.meta.env.DEV) logger.warn('[UnifiedMap] 渲染器销毁失败:', e)
      }
    }
  })
  olRenderer.value = null
  cesiumRenderer.value = null
  currentRenderer.value = null
  cesiumInitialized.value = false

  // a023: store 悬空引用清除
  mapStore.setCurrentRenderer(null)
})
```

### 为什么这么改 / 明确不改
- **销毁两个而非一个**：渲染器实例是 v-show 复用的，任何时候都有 1 个缓存实例存活，只销毁当前会漏掉它（WebGL 上下文/OL Map DOM 引用泄漏，Cesium 上限 16 个上下文）。
- **加 try/catch**：Cesium destroy 内部已有 30s idle 兜底（a029 前），个别情况下可能抛错，单渲染器失败不应阻断其余清理。
- **置空 `cesiumInitialized`**：保证严格模式下组件重挂（HMR/测试）时 Cesium 容器 v-if 重新判定。
- **明确不改**：不动 `CesiumRenderer.destroy()` 内部实现（a029 批次6）；不为每个请求补 abortController（b041 批次2）；不处理 layerCatalog（引擎切换时由 `BusinessLayerManager.reapplyAll` 按 registry 重建，卸载场景无需清）。

3. 手工：dev 下 2D↔3D 切换 3 次后刷新页面，无 WebGL 上下文警告。

## Part 3 · a025（P1）UnifiedMap setupEvents 匿名回调不可移除

### 现状（实码核实）
`UnifiedMap.vue:252-265`：
```ts
function setupEvents() {
  const renderer = currentRenderer.value
  if (!renderer) return
  renderer.on('click', (event: CustomEvent<MapRendererEventMap['click']>) => {
    ...
  })
}
```
匿名箭头函数未保存引用 → `MapRenderer.off`（接口已存在，`MapRenderer.ts:178-180`）无从调用。虽当前引擎切换复用分支（initRenderer :154-166）不重复调 setupEvents，重复注册风险低，但**卸载/未来复用场景无法解绑**，且接口契约要求"注册与移除配对"。

### 目标改动（`UnifiedMap.vue`）
1. 将回调提取为模块级具名函数（放在 setupEvents 之前）：
```ts
// a025: 具名回调，保存引用供 off 解绑（MapRenderer 事件注册/移除配对契约）
function handleRendererClick(event: CustomEvent<MapRendererEventMap['click']>): void {
  const { featureType, data, coordinate } = event.detail
  if (featureType === 'port' && data) {
    mapStore.setSelectedPort(data as unknown as Port)
  } else {
    mapStore.clearSelectedPort()
  }
  emit('click', { featureType, data, coordinate })
}
```
2. setupEvents 改为引用具名函数：
```ts
function setupEvents() {
  const renderer = currentRenderer.value
  if (!renderer) return
  renderer.on('click', handleRendererClick)
}
```
3. 新增 teardown 并**在 onUnmounted 中调用**（与 Part 1 合并同一处）：
```ts
// a025: 引擎切换/卸载前解绑 click 监听
if (currentRenderer.value) {
  currentRenderer.value.off?.('click', handleRendererClick)
}
```
（放在 Part 1 的 onUnmounted 中、销毁渲染器之前；`off?.` 防御旧接口无 off 的实现——但本仓基类已有 off，可直调。）

### 为什么这么改 / 明确不改
- 具名函数 + 保存引用是 Vue/EventEmitter 标准配对实践，同时让 `emit('click', ...)` 逻辑可单测。
- **明确不改**：不改 `renderer.on/off` 的事件名（'click' 是既有契约）；不新增 `pointer-move` 处理（那是 a026 批次6）。

## Part 4 · b037（P1）mapStore 无统一 reset 机制

### 现状（实码核实）
`mapStore.ts:58-410` composition store（无 `$reset`），state 分散：map/mapType/selectedPort/layerCatalog/baseLayerKey/currentRenderer/analysisHandler/lastAnalysisResult/activePanel/selectedXiaoqu（:60-76）。无统一重置 action。登出/业务切换无法一键回到初始态。

### 目标改动（`mapStore.ts`）
在 `closePanel`（:372-375）之后新增 action，并在 return（:381-409）中导出：
```ts
/**
 * b037: 统一重置地图业务交互状态（登出/业务切换时调用）
 *
 * 设计边界（@arch-note）：
 * - 清：selectedPort / activePanel / selectedXiaoqu / analysisHandler / lastAnalysisResult
 *   （含 sessionStorage 持久化，b035 要求）/ layerCatalog 业务条目
 * - 保留：mapType / baseLayerKey（用户偏好，审计明确要求保留）
 * - 保留：currentRenderer / map —— 渲染器由 UnifiedMap 组件持有生命周期，
 *   登出时组件未卸载，清空会造成 BLM._getRenderer() 返回 null 与业务图层失效；
 *   layerCatalog 同理（引擎切换时由 BLM.reapplyAll 按 registry 重建，登出无切换则永久空白）。
 */
function resetMapState(): void {
  selectedPort.value = null
  layerCatalog.value = []
  analysisHandler.value = null
  lastAnalysisResult.value = null
  activePanel.value = 'none'
  selectedXiaoqu.value = null
  try {
    window.sessionStorage.removeItem(ANALYSIS_RESULT_STORAGE_KEY)
  } catch {
    // 隐私模式等写入失败场景
  }
}
```
> ⚠️ `layerCatalog.value = []` 与上面"保留 layerCatalog"注释矛盾——**二选一**，推荐**清空**（登出后 LayerControlPanel 条目随账号业务状态一起复位，下次引擎切换/业务注册时由 BLM 重建；`layerCatalog` 里 base 底图条目由 `UnifiedMap.setupLayers` 在引擎切换时重建）。若担心登出后（无引擎切换）面板永久空白，可改为**只清 category==='business' 条目**：
> ```ts
> layerCatalog.value = layerCatalog.value.filter((e) => e.category !== 'business')
> ```
> **推荐后者**（保留 base 底图条目，最小影响）。

### 为什么这么改 / 明确不改
- 只加一个 action，不动既有 14 个 action 语义（零回归面）。
- **明确不改**：不拆分 store（b038 → D-13）；不清 currentRenderer/map（理由见注释）。

## Part 7 · z067（P2）window storage 监听未移除

### 现状（实码核实）
`useAuth.ts:144-148` `initAuthStorageListener` 注册 `window.addEventListener('storage', handleStorageChange)`，无对应 remove。SPA 中 App 不卸载实际影响小，但违反"监听配对"原则（审计定性 p2）。

### 目标改动（`useAuth.ts`）
1. `initAuthStorageListener` 之后新增导出函数：
```ts
/**
 * z067: 解除多标签页 storage 监听（与 initAuthStorageListener 配对）
 * 由 App.vue onUnmounted 调用
 */
export function removeAuthStorageListener(): void {
  if (!storageListenerRegistered) return
  storageListenerRegistered = false
  window.removeEventListener('storage', handleStorageChange)
}
```
2. `App.vue`：import 增加 `removeAuthStorageListener`（:10 现有 import 行），onUnmounted 内调用（与 Part 2 的 destroy 合并到同一钩子）：
```ts
onUnmounted(() => {
  businessLayerManager.destroy()          // a024
  removeAuthStorageListener()             // z067
})
```

### 为什么这么改 / 明确不改
- `storageListenerRegistered` 标志复位，保证 HMR/重挂后可重新注册（当前为 true 后永不重置，重挂场景监听丢失——顺手修复同一变量语义）。
- **明确不改**：不改 handleStorageChange 逻辑（跨标签页登出同步已正确）。
