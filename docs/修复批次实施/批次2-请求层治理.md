## Part 2 · z049（P1）useApiRequest 无重试机制

### 现状（实码核实）
`useApiRequest.ts:61-62`：仅 10s 超时 AbortController，无重试。`useBoundaryLayer.ts:29-103` 有 3 次重试+线性退避，但主力请求工具没有。

### 目标改动（`useApiRequest.ts`）
在 `apiRequest` 内部增加重试循环（只包 fetch 段，不包调用方逻辑）：
```ts
const MAX_RETRIES = 3
const RETRYABLE_CODES: ErrorCodeValue[] = [ErrorCode.TIMEOUT, ErrorCode.NETWORK_ERROR]
const RETRY_DELAY_MS = 800

async function apiRequest<T = unknown>(path: string, options: RequestOptions = {}): Promise<T> {
  // ...现有 headers/params 构造不变...
  let lastError: unknown
  for (let attempt = 1; attempt <= MAX_RETRIES; attempt++) {
    try {
      return await _singleRequest<T>(path, options)   // 现有 fetch/解包逻辑整体移入
    } catch (error) {
      // 仅 GET + 可重试错误码 + 非外部取消 才重试
      const isGet = (options.method ?? 'GET').toUpperCase() === 'GET'
      const code = error instanceof ApiError ? error.code : null
      const isRetryable = code !== null && RETRYABLE_CODES.includes(code)
      const isExternalCancel = error instanceof ApiError && code === ErrorCode.REQUEST_FAILED && options.signal?.aborted
      if (!isGet || !isRetryable || isExternalCancel || attempt === MAX_RETRIES) {
        throw error
      }
      lastError = error
      await new Promise((r) => setTimeout(r, RETRY_DELAY_MS * attempt)) // 线性退避 0.8s/1.6s/2.4s
    }
  }
  throw lastError
}
```
> 说明：`_singleRequest` 是现有 `apiRequest` 函数体原样抽出的内部函数（headers/params/超时/fetch/解包/错误映射全部不变），外层只加重试循环。**不要**把重试放到 `_singleRequest` 内部（超时 controller 每轮重新创建，天然支持重试）。

### 为什么这么改 / 明确不改
- 重试仅限 GET（幂等）+ 网络/超时类错误，POST 默认不重试（避免重复写操作）——符合审计要求。
- **明确不改**：不改超时值、不改信封解包（z063 在 Part 3 统一）、不增加指数退避复杂度。

### 验证
1. `npm run typecheck` exit 0。
2. 补测试 `useApiRequest.test.ts`（若已存在则追加）：mock fetch 失败 2 次后成功 → 断言 fetch 调用 3 次且返回成功；POST 失败不重试。

/** 统一信封解包：{ code, data } → data；非信封对象原样返回 */
export function unwrapEnvelope<T = unknown>(raw: unknown): T {
  if (raw && typeof raw === 'object' && 'code' in raw && 'data' in raw) {

  }
  return raw as T
}

## Part 5 · b042（P1）sessionStorage 持久化无版本机制

### 现状（实码核实）
`mapStore.ts:35-56`：`readStoredAnalysisResult` 直接 `JSON.parse`，无版本号。schema 变化后刷新回放 `analysisHandler` 可能抛错（虽有 try/catch 兜底 :110-113，但旧数据会污染新结构）。

### 目标改动（`mapStore.ts`）
1. 写入端 `writeStoredAnalysisResult`（:45-56）改为：
```ts
const ANALYSIS_RESULT_VERSION = 1
function writeStoredAnalysisResult(result: Record<string, unknown> | null): void {
  if (typeof window === 'undefined') return
  try {
    if (result) {
      window.sessionStorage.setItem(
        ANALYSIS_RESULT_STORAGE_KEY,
        JSON.stringify({ version: ANALYSIS_RESULT_VERSION, data: result })
      )
    } else {
      window.sessionStorage.removeItem(ANALYSIS_RESULT_STORAGE_KEY)
    }
  } catch { /* 忽略隐私模式等写入失败 */ }
}
```
2. 读取端 `readStoredAnalysisResult`（:35-43）改为：
```ts
function readStoredAnalysisResult(): Record<string, unknown> | null {
  if (typeof window === 'undefined') return null
  try {
    const stored = window.sessionStorage.getItem(ANALYSIS_RESULT_STORAGE_KEY)
    if (!stored) return null
    const parsed = JSON.parse(stored)
    // b042: 版本校验——旧格式（无 version）或无 data 字段一律丢弃
    if (
      !parsed ||
      typeof parsed !== 'object' ||
      parsed.version !== ANALYSIS_RESULT_VERSION ||
      !('data' in parsed)
    ) {
      window.sessionStorage.removeItem(ANALYSIS_RESULT_STORAGE_KEY)
      return null
    }
    return parsed.data as Record<string, unknown>
  } catch {
    return null
  }
}
```
> 注：Part 5 与批次1 Part 4（resetMapState 清 sessionStorage）无冲突——写/读格式升级，清空逻辑不变。

### 为什么这么改 / 明确不改
- `{version, data}` 包装是标准做法，版本不匹配即丢弃（旧 session 数据本来也只活一个会话，丢弃无损失）。
- **明确不改**：不给 localStorage 的 `beibu-gulf-user`/`beibu-gulf-base-layer` 加版本（审计只要求分析结果；user/base-layer 结构稳定，加了扩大范围）。

## Part 6 · z050-FE（P1）前端缓存无大小上限

### 现状（实码核实）
① `loadStatic.ts:15` `cache: Map`（TTL 5min，无上限）——Part 4 后 mapDataService 也走这里；② `useBoundaryLayer.ts:27` sessionStorage 缓存（24h，无上限）；④ `ForecastPage.vue:60` `requestCache = new Map()`（会话内无限增长，仅 onMounted/unmount 清空）。

### 目标改动
1. **`loadStatic.ts`**：加 `MAX_CACHE_SIZE = 100`，`cache.set` 前若 `cache.size >= MAX_CACHE_SIZE` 删除最旧项（Map 迭代序即插入序，`cache.delete(cache.keys().next().value)` 即 LRU 近似淘汰）：
```ts
function setCache(url: string, data: unknown): void {
  if (cache.size >= MAX_CACHE_SIZE) {
    const oldestKey = cache.keys().next().value
    if (oldestKey !== undefined) cache.delete(oldestKey)
  }
  cache.set(url, { data, cachedAt: Date.now() })
}
```
