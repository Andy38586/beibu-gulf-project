## Part 2 · d061（P1）Dockerfile 以 root 运行

### 现状（实码核实）
`Dockerfile:27-56` production 阶段无 `USER` 指令，容器以 root 运行（nginx + node 进程）。

### 目标改动（`Dockerfile`）
1. production 阶段新增：
```dockerfile
# d061: 最小权限运行——容器逃逸时不以 root 获得宿主机权限
RUN adduser -D -u 1000 nodeapp \
  && mkdir -p /app/backend/data /var/log/nodeapp \
  && chown -R nodeapp:nodeapp /app/backend/data /var/log/nodeapp
USER nodeapp
```
2. 确认写入路径权限：
   - `backend/data/`（users.json/plans 等 JSON 文件存储）必须可写 → 上面的 chown。
   - nginx 需要 root 或专用用户：nginx alpine 包默认以 nginx 用户运行 master，但 `EXPOSE 80/443` 与 entrypoint 启动 nginx 需 root 或 capability。**实施重点**：docker-entrypoint.sh 中 nginx 启动若需特权，方案为「entrypoint 以 root 启动 → nginx 启动后降权」，或保留 entrypoint 阶段 root、仅 node 进程以 nodeapp 运行（docker-entrypoint.sh 内 `su-exec nodeapp node backend/server.js`）。实施时以 entrypoint 实际脚本为准做最小改动。
3. HEALTHCHECK 不受影响（wget 无写权限需求）。

### 为什么这么改 / 明确不改
- 审计核心诉求 = node 后端进程不以 root 运行。nginx 与 entrypoint 的权限保持可用即可（最小改动）。
- **明确不改**：不改端口/健康检查/多阶段构建结构。

### 验证
1. `docker build` 成功（如有 Docker）。
2. 容器启动后 `ps aux` 确认 node 进程为 nodeapp 用户；users.json 写入（注册接口）成功。

### 完成检查
- [ ] production 阶段有 USER 指令且数据目录可写

## Part 6 · d065（P2）无日志脱敏中间件

### 现状
d043 已解决操作审计不记密码；但无统一脱敏中间件，未来请求日志有敏感字段泄漏风险。

### 目标改动
1. 新增 `backend/middleware/logSanitizer.js`：
```js
/** d065: 请求日志脱敏——password/token/secret/cookie 字段打码后输出 */
const SENSITIVE_KEYS = ['password', 'token', 'secret', 'authorization', 'cookie']
export function sanitize(value, key = '') {
  if (SENSITIVE_KEYS.some((k) => key.toLowerCase().includes(k))) {
    return typeof value === 'string' ? `${value.slice(0, 2)}***` : '***'
  }
  if (Array.isArray(value)) return value.map((v) => sanitize(v))
  if (value && typeof value === 'object') {
    return Object.fromEntries(Object.entries(value).map(([k, v]) => [k, sanitize(v, k)]))
  }
  return value
}
```
2. `app.js` 挂载请求日志中间件（dev 下输出方法/路径/耗时，body 经 sanitize）：
```js
import { sanitize } from './middleware/logSanitizer.js'
app.use((req, res, next) => {
  const start = Date.now()
  res.on('finish', () => {
    if (isDev) logger.debug(`[req] ${req.method} ${req.originalUrl} ${res.statusCode} ${Date.now() - start}ms`, sanitize(req.body))
  })
  next()
})
```
> 注意：本中间件**只打日志、不修改请求**；`isDev` 守卫复用 logger 语义（生产 debug 静默）。审计说"未来引入请求日志时"，当前引入即附带脱敏。

### 验证
1. `node --test` 全绿（补 sanitize 单测：password/token 打码、嵌套对象、数组）。
2. 手工：dev 下 POST /auth/login 日志中 password 显示 `pa***`。

### 完成检查

```yaml
  deploy:
    needs: build
    runs-on: ubuntu-latest
    if: github.ref == 'refs/heads/main'

      - uses: actions/checkout@v4
      - name: Login to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}

      - name: Build & push image

          docker push ghcr.io/${{ github.repository }}:${{ github.sha }}
      - name: Trigger server deploy
        run: |
          curl -fsS -X POST \
            -H "Authorization: Bearer ${{ secrets.DEPLOY_WEBHOOK_TOKEN }}" \
            https://your-server/deploy-hook
```

### 目标改动（`floodAnalysisController.js`）

const READ_CACHE_MAX_SIZE = 20  // z050-BE: 上限 20 条目（flood 数据文件数量 << 20）
function setReadCache(filename, data) {
  if (_readCache.size >= READ_CACHE_MAX_SIZE) {
    const oldestKey = _readCache.keys().next().value
