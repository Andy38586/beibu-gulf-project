## Part 1 · a026（P1）pointer-move / camera-changed 事件声明未实现

### 现状（实码核实）
`types/renderer.ts:109-123` `MapRendererEventMap` 声明 `'pointer-move'`/`'camera-changed'`，全仓无 emit 调用。OLRenderer 仅注册 `map.on('click')`；CesiumRenderer 仅 `ScreenSpaceEventType.LEFT_CLICK`。接口契约与实现脱节。

### 目标改动（推荐：补实现，保留接口契约）
1. **OLRenderer**（`addXxxLayer` 初始化处或 `init()` 内，与现有 click 注册并列）：
```ts
this.map.on('pointermove', (evt) => {
  this.emit('pointer-move', {
    lng: evt.coordinate[0],
    lat: evt.coordinate[1],
  })
})
```
2. **CesiumRenderer**：注册 `ScreenSpaceEventType.MOUSE_MOVE`：
```ts
this._screenSpaceEventHandler.setInputAction((movement) => {
  const cartesian = this.viewer.camera.pickEllipsoid(movement.endPosition, this.viewer.scene.globe.ellipsoid)
  if (cartesian) {
    const carto = Cesium.Cartographic.fromCartesian(cartesian)
    this.emit('pointer-move', { lng: Cesium.Math.toDegrees(carto.longitude), lat: Cesium.Math.toDegrees(carto.latitude) })
  }
}, ScreenSpaceEventType.MOUSE_MOVE)
```
3. **camera-changed**：OLRenderer 用 `map.on('moveend', ...)` 防抖 emit `exportState()`；CesiumRenderer 已有 `camera.changed` 监听（`_cameraChangedHandler`，:1127-1128 用于视口裁剪），在其回调内**防抖**（复用 `_cameraDebounceTimer`）后 `emit('camera-changed', this.exportState())`。
4. **移除场景**：`destroy()` 中 `off('pointer-move'/'camera-changed')` 对应监听（OL: `map.un('pointermove')`；Cesium: `removeInputAction(MOUSE_MOVE)`）。

### 为什么这么改 / 明确不改
- 补实现让接口契约与实现一致（审计两选项之一），未来业务层可订阅（如鼠标坐标展示）。
- **明确不改**：不为这两个事件新增任何业务订阅方（本批只补契约，不加消费）；camera-changed 必须防抖（每帧触发会刷爆订阅方）。

### 验证
1. `npm run typecheck` exit 0。
2. 渲染器测试全绿（若 mock 未实现 pointermove 需同步 mock）。
3. 手工：2D/3D 移动鼠标无报错、相机拖动无卡顿（防抖生效）。

## Part 3 · a029（P2）Cesium Viewer destroy 不真正销毁

### 现状（实码核实）
`CesiumRenderer.ts:1121-1156` `destroy()` 仅 `cesiumViewerManager.unmount()`（DOM 卸载），不调 `viewer.destroy()`；有 30s 空闲销毁兜底（`_clearIdleDestroyTimer`）。注释明确"不销毁Viewer单例"（v-show 复用设计）。

### 目标改动（`CesiumRenderer.ts` + `cesiumViewerManager`）
1. `cesiumViewerManager` 增加真正销毁接口：
```ts
/** a029: 真正销毁 Viewer（释放 WebGL 上下文），与 unmount（仅卸载 DOM）区分 */
destroyViewer() {
  this._clearIdleDestroyTimer()
  if (this.viewer && !this.viewer.isDestroyed()) {
    this.viewer.destroy()
  }
  this.viewer = null
  this.isMounted = false
  // 移除残留容器（若 unmount 未清）
}
```
2. `CesiumRenderer` 增加转发：
```ts
/** a029: 真正销毁 Viewer 实例（仅测试/HMR/应用退出场景使用；常规卸载走 destroy() 保留复用） */
destroyViewer() {
  cesiumViewerManager.destroyViewer()
  this.viewer = null
}
```
3. `destroy()` 保持现状（unmount 保留复用语义），**不改为 destroyViewer**——与 idle-destroy 机制协调：idle 30s 到期时已有兜底；destroyViewer 是显式退出通道。

### 为什么这么改 / 明确不改
- 审计要求"增加 destroyViewer() 真正销毁接口 + 与 idle-destroy 机制协调"——按字面实施，不改 destroy() 语义（v-show 复用是设计，a022 已证明 registry 持久依赖渲染器复用）。
- **明确不改**：不把 UnifiedMap 的卸载路径改调 destroyViewer（那会推翻复用设计）。

### 验证
1. `npm run typecheck` exit 0。
2. 补测试（若 cesiumViewerManager 有测试）：destroyViewer 后 viewer.isDestroyed() 为真、二次调用幂等。
3. 手工：切 3D → 等 30s idle → 再切 3D 正常重建。

### 完成检查
