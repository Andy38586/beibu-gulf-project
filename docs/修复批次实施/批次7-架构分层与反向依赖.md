## Part 1 · z044（P0）errorHandler ↔ router 循环依赖 —— 机械项，先做

### 现状（实码核实）
`shared/utils/errorHandler.ts:69-78`：
```ts
export async function handleAuthError(router?: unknown): Promise<void> {
  ...
  const r = (router || (await import('@/router')).default) as Router
  ...
}
```
**router 参数已存在**（部分修复已做），但 `:74` 仍保留 `(await import('@/router')).default` 动态 import 兜底——这是循环链（errorHandler→router→business→errorHandler）的根源。dependency-cruiser 报 10+ 条循环。

### 目标改动（`errorHandler.ts`）
```ts
export async function handleAuthError(router: Router): Promise<void> {
  const { useAuth } = await import('@/shared/composables/useAuth')
  const auth = useAuth()
  await auth.logout()

  if (router.currentRoute.value.path !== '/') {
    router.push({ path: '/', query: { showLogin: '1' } })
  }
}
```
1. `router` 从可选参数改为**必选参数**（去掉 `|| await import` 兜底）。
2. **更新全部调用方**（grep `handleAuthError(`）：现有调用无 router 参数的改为 `handleAuthError(router)`（调用方需能访问 router 实例——`useRouter()` 或模块导入）。
3. **z056 联动**（批次8）：若 eslint 开 no-floating-promises，`handleAuthError` 调用处加 `void`/`.catch`。

### 为什么这么改 / 明确不改
- 循环根源 = 动态 import 兜底；删掉后 errorHandler 不再依赖 router，循环链断裂（业务→errorHandler→router 变成业务→errorHandler，router 由调用方传入）。
- **明确不改**：不把 errorHandler 移到别层（shared 合理）；不改 `isAuthError`/`showError`。

2. `npx depcruise --config .dependency-cruiser.cjs` 循环 warn 数显著下降（no-circular 仍 warn，z055 升级 error 后必须清零）。
3. 全仓测试全绿。
