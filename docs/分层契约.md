# 前端分层契约(Layer Contract)

> 定位:10 个顶层目录的依赖顺序与边界。`npm run cruise`(dependency-cruiser)守护
> 规则层,本契约守护语义层——规则没写到的,以本契约为准。
> 架构审查收口产物(2026-08-04):此前 dc 规则只防"谁都不许引 business"+ no-circular,
> 未定义 core/types/services 的层级顺序,导致反向依赖无规则可依。

## 1. 层级顺序(低 → 高)

| 层级 | 目录 | 职责 | 可依赖(低层) |
|---|---|---|---|
| L0 | `types/` | 纯类型声明 | **零运行时依赖**(纯类型) |
| L1 | `shared/` | 通用工具/composable/常量/基础组件 | types(type-only) |
| L2 | `stores/` | 全局状态(Pinia) | shared、types |
| L3 | `services/` | 数据访问(adapter/API 封装) | shared、stores、types |
| L4 | `visualization/` | 通用图表资产 | shared、types |
| L5 | `core/` | 地图核心 + 布局基座 | stores、services、shared、types |
| L6 | `business/` | 业务模块(**互不依赖**) | core、stores、services、shared、types |
| L7 | `views/` | 页面装配 | business、core、shared、types |
| L8 | 入口(`main.ts`/`router`/`App.vue`) | 应用装配 | 全部 |

**核心铁律**:
- 低层**不得**依赖高层(如 shared 不得依赖 core/stores/business)
- `types/` 零运行时依赖(纯类型;运行时常量/工具放 shared)
- 业务模块之间禁止互引(manifest 驱动注册,非直接 import)

## 2. 已知的设计确认依赖(不禁,但必须知悉)

以下依赖**形式上"反向"**(低层引高层),但为架构有意设计,dc 不拦、本契约明示:

| 依赖 | 位置 | 理由 |
|---|---|---|
| core → stores | `UnifiedMap.vue` / `useLayerManager.ts` / `provideKeys.ts` | mapStore 是跨层共享的地图状态,core 消费属设计使然 |
| core → services | `usePortLayer.ts` → mapDataService | core 需要数据服务加载 ports 等静态数据 |
| core → visualization | `AppLayout.vue` → RadarChart | 布局基座展示图表组件 |

> 若未来 core 希望完全独立,需将 mapStore 下沉或引入依赖注入;当前**明确接受**这些依赖,
> 代价是 core 不是零依赖内核,但每个依赖都有真实使用场景且方向稳定。

## 4. dc 规则清单(与契约对应)

- `shared-not-import-core` / `shared-not-import-stores` / `stores-not-import-business`(error)
- `core-imports-business` / `services-imports-business` / `visualization-should-not-import-business`(error)
- `types-not-import-shared`(error,2026-08-04 新增)
- `business-cross-import-*`(warn,模块互引)
- `no-circular`(error)
- cruise 覆盖范围: `frontend/src backend`(2026-08-04 起 backend 入守护)
