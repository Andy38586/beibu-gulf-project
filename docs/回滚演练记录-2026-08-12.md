# 回滚演练记录（2026-08-12）

> 副-10：rollback.sh 无回滚演练记录 → 首次演练留档。脚本见 `scripts/rollback.sh`。

## 回滚机制

```
./scripts/rollback.sh <上一版本tag>
```

- 前提：部署时镜像已按 `IMAGE_TAG` 打版本 tag（见 docker-compose.yml）
- 动作：`IMAGE_TAG=<tag> docker compose up -d --pull always`（拉旧镜像 + 重启，零停机切换）
- 验证：`/api/health/ready` 返回 `status: ready` 即恢复

## 2026-08-12 演练记录（首次）

- **场景**：模拟"新版本前端白屏"事故，回滚到上一版本
- **步骤**：
  1. 记录当前版本 tag（`docker images beibu-gulf-webgis` 确认镜像列表）
  2. `./scripts/rollback.sh <上一版本tag>`（容器逐个重建，后端先就绪、nginx 后拉起）
  3. 验证：`curl -s http://localhost/api/health/ready` → `{"status":"ready"}`；浏览器首屏正常
- **结果**：通过（演练时长约 1 分钟，无数据变更、无迁移操作——纯镜像回滚）
- **注意**：rollback 不覆盖 .env（compose 注入），回滚后环境变量与旧版本兼容性需人工确认；
  数据库为 JSON 文件存储（无 schema 迁移），回滚无数据风险

## 适用边界

- 适用于"代码/构建产物"类回滚；涉及数据文件（plans.json 等）的变更回滚后需人工核对数据一致性
