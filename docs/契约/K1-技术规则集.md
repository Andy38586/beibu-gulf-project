## A. 渲染与地图

### A1 有注册必有注销，且必须在同一作用域

**规则**：任何 `addEventListener` / `.on(` / `setInterval` / `requestAnimationFrame` / `new ResizeObserver` / `subscribe`，必须在**与其注册同级的生命周期**内有对应注销路径。注册在 renderer 级、注销在 mount 级（或反之）视为不合格。
**依据**：a003 / a025（同类 12 条化身：注册与注销不同作用域、匿名回调不可注销；原编号列已随 2026-09-19 归并重排失效，故改记语义）
**自检**：`grep -c 'addEventListener\|\.on('` 与 `grep -c 'removeEventListener\|\.off('` 在同一文件内数量应匹配；匿名回调一律视为不可注销。

### A2 访问可能已销毁的对象前必须判 `isDestroyed()`

**规则**：Cesium/OL 的 `viewer` / `map` / 子对象可能被空闲销毁或引擎切换置空。任何 `viewer!.xxx` 形式的非空断言都是债。访问前一律短路判断，`destroy()` 内部用 `try/finally` 保证"清表 + 置空"必达。
**依据**：a003（30s 闲置销毁后 destroy 后半段整体跳过）
**自检**：`grep -n 'viewer!\|\.viewer!\.'` 的每一处，上一个语句必须能证明非空。

### A3 引擎切换必须走互斥序列，early-return 要保留并重放

**规则**：`switching` 期间禁止并发初始化；任何"类型相同 → 提前返回"的分支，必须把目标类型记入 `pendingSwitchType` 并在初始化结束后重放。
**依据**：a008（`mapStore.mapType` 被 App 提前更新 ⇒ 误判短路；直进 3D 白图）
**自检**：切换相关 early-return 分支有没有对应的 pending 变量。

### A4 图层状态只能有一个事实源

**规则**：图层的注册 / 更新 / 显隐 / 移除**只能**经 `BusinessLayerManager`。禁止：面板绕过 BLM 直调渲染器、业务图层自建 registry、`layerCatalog.visible` 与渲染器实例状态双写。权威状态 → 渲染器应为**幂等单向同步**（任何时刻可重跑）。
**依据**：a030（含 a002 a014 a033；`isLayerVisible` 三级读取链零生产调用）——另有 9 条化身的原编号已随 2026-09-19 归并重排失效
**自检**：新增图层显隐路径前，先问"这条路径在 reconcile 时能被重放吗"。

### A5 CRS 守卫必须有生产者；坐标出口必须显式转换

**规则**：坐标系纪律的两道防线——① 类型守卫（判定 `input.crs`）**必须真的有人写这个字段**，否则守卫永不触发；② 任何从存储读出的几何，出口必须显式 `ST_Transform(4326)`，不得依赖"两套 SRID 恰好同为度制"。
**依据**：a004（守卫零生产者）/ SRID 混用致浸没设施恒 0（该条原编号已失效）
**自检**：新建守卫时，先 grep 它的判据字段有几处写入。

### A6 禁止用 `(0,0)` / `0` / `''` 作缺失哨兵

**规则**：缺失值必须显式为空档（`null` / `undefined` / 显式错误态），**不得**回退成看起来合法的值。地理坐标的 `(0,0)` 是"几内亚湾"，`score: 0` 是"评分最差"，二者都会伪装成真实数据。
**依据**：a009 / 淹没要素坐标 0 哨兵伪装 / 选址坐标哨兵与 as 硬转（后两条原编号已失效）
**自检**：`grep -n '?? 0\|?? \[\]\|?? ""\|?? '"` 的每一处，问"0 是真值还是缺失"。

### A7 空间查询必须走索引；图层更新必须增量

**规则**：rbush 空间索引是既定设施——新增空间筛选（视口裁剪 / POI 粗筛 / 碰撞检测）必须复用它，禁止逐元素 `booleanPointInPolygon`。图层 `updateData` 走增量 diff，禁止全量重建（会闪）。
**依据**：a001（含 a016 a019）/ 全量重建闪烁（该条原编号已失效）/ d021（设施筛选未复用空间索引）
**自检**：新增 O(n·m) 循环前先问"rbush 能不能用"。

### A8 大资产与外部依赖必须标注来源、可复现

**规则**：DEM / hillshade / 瓦片 / 模型文件等大资产，必须 ① 标注来源与用途；② 进归档（获得校验和）；③ 不得依赖 gitignored 的本地文件（换机即不可复现）。
**依据**：a027（含 a035 a037）；其余 3 条化身的原编号已随 2026-09-19 归并重排失效
**自检**：新增大文件时问"换台机器还能跑吗"。

### A9 渲染器契约单一权威；能力守卫必须判全部成员

**规则**：同一角色的契约**只能有一处定义**（interface 或 class，不能双源）。基类禁止用 no-op stub 满足接口——那会让能力检查恒真。类型谓词（`isXxxCapable`）必须判定该能力接口的**全部成员**，不能只判一个。
**依据**：a005（含 a006 a007 a010 a011 a012 a026 a036；`as unknown as` 桥接 + "对必填成员做存在性判断"死分支）——末条化身原编号已失效
**自检**：写出 `renderer is X & Y` 时，数一下 `Y` 有几个成员、你判了几个。

### A10 未知字段/未知组件的类型必须收窄，禁止开放索引

**规则**：核心数据缝上禁止出现 `[key: string]: unknown` / `Record<string, unknown>` 作为"暂未定义"的逃生舱；能力契约禁止写 `Record<string, ComputedRef<string>>` 这类抹平已知键的写法（拼错键会编译通过、运行时 undefined）。
**依据**：a005 / 已被多轮重复发现（z 系类型族）
**自检**：写 `Record<string, T>` 前问"我能枚举键吗"。

### A11 销毁与移除链必须逐项容错，且"摘账"与"释放"的顺序不能反

**规则**：`destroy()` / `removeLayer()` 这类遍历释放的循环，**每一项都要独立容错**——一项抛错不得让后半条销毁链不执行。且必须先证明资源已释放、再摘登记（`_layers.delete` 在 `_doRemoveLayer` 之后 = 抛错时条目留存，而"缺实例即补建"的判据此后恒不成立，该对象再也建不出来）。同一操作在双引擎两侧的防御强度必须一致：一侧 `viewer!` 裸取、一侧可选链，等于三套口径。
**依据**：924/专项2 新-1、新-2、新-4（`MapRenderer` 的 `destroy`/`removeLayer` 无逐项 try + 43 处 `viewer!`，而 `addGeoJsonLayer` 已自带"渲染器存活但 viewer 已失效"的防御）
**自检**：把循环里第 1 项改成抛错，后面的释放还会执行吗？两侧引擎的同一个方法，取值方式一样吗？

### A12 能力守卫的"设计内跳过"必须与"失败"可区分，且面板按能力呈现

**规则**：能力守卫不得 `warn + return`——那让"不支持"和"加载失败"在数据与界面上同形，图层开关变成一个可点亮的死按钮。能力判定必须有**三态**（支持 / 不支持 / 失败并带原因），面板据此呈现（不呈现 / 置灰并说明 / 可点并在失败时上报）。适用性（`engines` 之类）必须在**每个**创建入口参与判定，不得只在一处。
**依据**：922 专项4 H-04、R2-02-03、a035；被测试断言"设计内跳过"钉成契约，属"测试在掩护"
**自检**：把这个图层在不支持的引擎下点一次，屏幕、面板、日志三处各自说了什么？

### A13 静态瓦片/资源的缓存策略必须成文且单一来源

**规则**：瓦片与静态资源的缓存头策略只允许有一个**成文口径**（现状：地形瓦片在
`backend/src/main.ts` 设 `Cache-Control`；生产 nginx 侧属外部配置，改动走指令单）。
代码与 nginx 不得各写一套互不知情的策略；"某类资源故意不设缓存头"必须写出来（默认 = 随数据
更新变化，设了缓存反而发陈旧数据的是事故）。
**依据**：c024（仓库内只有一处 `Cache-Control`，图例/瓦片策略无成文 ⇒ 改产出节奏时无人知道要同步什么）
**自检**：这次改动改了瓦片的产出/更新节奏吗？缓存头的唯一口径在哪、要不要同步？

### A14 两引擎「同构」必须能说清相位差异；共享参数必须单源

**规则**：OL/Cesium 两侧出现"看起来一样"的调度/兜底代码时，先答一个问句：**它们服务同一相位吗？**
同一相位 ⇒ 抽到引擎无关模块（参数推导与数学一律单源）；不同相位 ⇒ 允许各自内联，但要在注释里
点名**对方那一处在哪、为什么不能合并**。已单源的例子：呼吸动效全部参数在 `core/config/breathing.ts`
（此前 6 处逐行复制 ⇒ 「同一界面两种呼吸节奏」）；允许保留的例子：Cesium 的「挂载后双 rAF 补
resize」与「布局滞后兜底双 rAF」是**两个相位**的兜底，各自带句柄与 destroy 取消，不合并。
**棘轮**：再出现第三处"同相位重复调度" ⇒ 收口，不许再内联一份；体量由
`tools/v3-guard/structure-check.mjs` 的棘轮冻结（z016）。
**依据**：a026（两引擎 rAF/兜底同构判定悬而未决）；breathing.ts 头注释（6 处复制的实测教训）
**自检**：这段兜底为什么不能和另一引擎的那段合并？答"因为引擎不同"不算答案，要答相位差在哪。

## B. 数据与契约

### B1 HTTP 边界 100% zod 校验；无 schema 不得当业务类型用

**规则**：**每一个** HTTP 响应消费点都必须传 `schema`。`apiRequest<T>` 的泛型不得成为"免校验通行证"——网关签名应做到"没传 schema 就拿不到业务类型"。
**依据**：b033 / 已被 4 个专项独立发现（当前实测某新通道 3 处调用零 schema）
**自检**：新增调用点时，`schema` 是否为必填参数？

### B2 同一实体只能有一处类型定义

**规则**：响应类型从 schema `z.infer` 派生，禁止手写平行 interface。`*Parsed` 派生类型必须**有消费者**——生成"零消费者类型"等于制造死代码。
**依据**：b033 / 已被独立发现 2 次（含"26 个 Parsed 零消费"）
**自检**：新增类型前 grep 是否已有同名字段集。

### B3 跨端/跨层常量必须单源 + 断言覆盖全部副本

**规则**：凡"必须同步"的常量（阈值表 / 上限 / 权重 / 错误码 / 枚举），① 副本数 ≤1，或 ② 有生成物 + CI 比对，或 ③ 有守卫**覆盖全部副本**。**半覆盖的守卫比没有守卫更危险**——它把漏检变成"已检查"。
**依据**：b020 / d013 / 已被 3 个专项独立发现（风险档表 6 档 vs 5 档，两侧注释都声称有守卫，实际守卫只比一个标量）
**自检**：写"必须同步"的注释前，先确认守卫覆盖面 == 副本数。

### B4 单位必须在产生处与消费处都声明

**规则**：跨层传递的数值量，单位不能只写在注释里。`ST_Area(geometry)` 是平方度不是平方公里；后端下发的 `unit` 不得在中途被丢弃；多套量纲不得共用同一 Y 轴。
**依据**：b020（淹没统计字段单位混淆）/ 已被多轮发现
**自检**：新增数值字段，问"这个数字的单位是什么、谁在消费"。

### B5 时间格式必须单一解析函数，按粒度收口

**规则**：同一语义的时间串（"当前时间点"）只能有一个归一函数，且必须**按粒度**决定键格式。禁止各消费方自行 `split('-')`。缓存键必须包含全部维度（含 granularity）。
**依据**：已被 2 个专项独立发现（年模式柱状图恒空 + 空结果按共享键污染月模式；两条原编号均已失效）
**自检**：看到 `split('-')` / `slice(0,4)` 处理时间，先找有没有收口函数。

### B6 缓存必须带上限、失效、身份、版本键

**规则**：任何模块级缓存（Map / sessionStorage / localStorage）必须有：① 容量上限 + 淘汰；② TTL 或显式失效入口；③ **失效入口必须被调用**（零调用的清理函数是假防线）；④ 键含版本/身份（换账号不得命中上一账号）。
**依据**：b005 / b035 / 已被独立发现 7 次（`clearMapCache` / `clearAll` / `clearStaticCache` 全为零调用）
**自检**：新写 `new Map()` 缓存时，问"谁清它、什么时候清"。

### B7 禁止伪造字段填孔

**规则**：为满足类型而填 `score: 0` / `breakdown: {}` / `statistics: undefined` 属于**伪造数据**。类型不匹配时应改类型或补真实取数，不得用默认值缝合。
**依据**：b025 / b044（浸没设施列表伪造 score:0 并写入收藏快照）
**自检**：写 `field: 0` 时问"这真是 0，还是我没有数据"。

### B8 缺失即缺失，空与错必须分离

**规则**：空结果（合法的零）与错误（取数失败）**必须**在类型与 UI 上都可区分。禁止把"未取到"渲染成"零风险 / 0 个 / 0 元"。
**依据**：b044 / b020 / 已被 2 个专项独立发现（报告面板无 error 态）
**自检**：面板有没有 `error` 分支？还是只有 `v-if="data"`？

### B9 报告分辨率不得高于数据有效分辨率；阶梯量不得给逐档导数

**规则**：任何对外展示的分辨率（滑块步长、档位表间隔、"每升 1 单位变化 X"这类导数表述）必须 ≤ 数据本身的有效分辨率，否则是**伪精度**（spurious precision）。数据被量化（如栅格以整米入库）时，中间档全部是复制品：产物体积、响应大小、请求次数都在为不存在的信息付费，而曲线是阶梯函数、逐档导数在数学上无对象。必须显式披露量化步长，或把档位收敛到有效分辨率。
**依据**：923 专项9 S-01（251 档实测只有 26 个不同值、非零跳变全落在整米）、S-02（声明"向上取档=宁可高估"，复合规则实为 `⌊ceil₀.₁(r)⌋` ⇒ 90% 量程系统性低淹，加权期望误差 −0.40 m）、S-07（7 级台阶的曲线无法支撑"每升 1 m 增加 X"）、S-05（未披露垂向误差：全量程 = 1.17σ）
**自检**：把输入按步长微调一遍，输出真在变吗（`count(DISTINCT 输出列)` 够不够）？"向上取档"在有量化噪声时还是保守吗？

### B10 对外自述的模型设定与口径，必须在实现里存在且可复核

**规则**：数据产物 metadata、README、注释里写出的**模型设定**（含哪个因子、哪个基准、什么口径、训练区间）必须与运行侧实现逐字一致；不一致时改文档要改到"能拿实现复算"的程度。合成/降级数据必须带来源标记，且标记不得反向说谎（合成点挂最高可信标签、把真数据说成合成，都是不实）。
**依据**：923 专项9 S-03（`lossAssumption` 声明含水深因子，运行侧与生成侧均无该因子 ⇒ 零水深按 85% 计全损）、专项8 N17（README 5 处叙事与实值脱钩）、922 专项8 R2-15-02（模型溯源逐请求算出、四个出口一个都不下发）
**自检**：文档里每个"含 X 因子 / 按 Y 口径"，能否在代码里指到那一行并跑出同值？

## C. 状态与生命周期

### C1 状态只能有一个写入口

**规则**：store state 只能经 action 修改。禁止 `storeToRefs` 解构后 `v-model` 直写、禁止组件直接赋值 state、禁止 `$patch`。若确实允许直改，就必须删掉那个 action 并承认。
**依据**：b005 / `setDebugMode` 零调用而实际写入走 `v-model` 直改 state（另两条原编号已失效）
**自检**：`v-model="someStoreRef"` 是直改 state 的信号。

### C2 登出/切换必须覆盖全部 store 与模块级缓存

**规则**：登出（含切账号、切路由重置）的清理清单必须**枚举全部持久化状态**并逐项有对应清理动作，且必须有断言测试（登出后各 store 为空）。清单遗漏 = 跨账号数据串。
**依据**：b035（含 b036 b037）/ 已被 2 个专项独立发现（漏 taskStore + 两个模块级缓存）；其余 3 条化身原编号已失效
**自检**：新增 store 或模块级缓存时，同步更新登出清单。

### C3 请求必须可取消，取消与失败必须可区分

**规则**：① 每个在途请求必须能取消（signal 真接线，不是形参空转）；② 取消不得被当作失败弹 toast（引入 `isCancelError()` 谓词，禁止用中文文案比对判定）；③ 组件卸载必须 abort。
**依据**：d011 / 已被 3 个专项独立发现（取消判定靠 `message === '请求已取消'` 字符串相等）；另一条化身原编号已失效
**自检**：`catch` 里有没有区分取消与真失败？

### C4 竞态必须有代次/序号守卫

**规则**：任何"可连续触发"的操作（滑块 / 切路由 / 切引擎 / 连点）必须有 ① 代次比对 或 ② 序号守卫 或 ③ 显式取消，保证"最后一次生效"。
**依据**：b039 / 已被 2 个专项独立发现（另一条化身原编号已失效）
**自检**：连续拖滑块 10 次，最终显示的是第几次的结果？

### C5 抢占必须补跑，不得静默丢弃

**规则**：在途期间的新状态不得被 `if (requesting) return` 静默丢弃——必须置 pending 并在终态后补跑，或按契约取消旧的再发。
**依据**：b005 / 已被 2 个专项独立发现（预测在途期间的参数变化被整轮丢弃）
**自检**：`requesting` 早退分支里有没有 pending 变量？

### C6 跨路由存活的等待器必须绑定等待方；清理动作不得被读它的判据误解释

**规则**：两种具体形态：① 供 `await` 使用的轮询/定时器，其生命周期属于**等待方**——要么接 `AbortSignal`，要么返回 `{promise, stop}` 并在 `onScopeDispose` 里停；"有上界自清"不是绑定的替代。② 清理钩子（`onModuleDestroy` / `dispose` / `logout`）一旦改了某个集合，所有"读该集合判断状态"的判据必须能区分**已清理**与**未发生**——`map.get(id)?.status === 'cancelled'` 在清表后恒为 false，等于把"已取消"读成"继续跑"。补 shutdown 钩子必须同批改这类判据。
**依据**：924/专项2 今-2（`waitForResult` 的 interval 不绑等待方）、N-5（`dispose()` 清表后在飞 handler 判"未取消"，与 `enableShutdownHooks` 缺失互为暗礁）、N-6（`running` 记录无回收 ⇒ 与终态容量上限叠加后"无 victim 可淘汰"双重锁死）
**自检**：这个 promise 被谁 await？它的主人卸载时谁替它停？清理之后，读这个集合的判据还成立吗？

### C7 恢复态字段必须分区列明：快照字段 vs 活状态字段

**规则**：`consumeState`（或任何"恢复保留态"入口）必须能把字段分成两区并写明：**快照字段**
（跨刷新要保留，进持久化 schema）与**活状态字段**（由本轮查询产生，恢复态不承担）。新增字段
先答它属于哪一区；不写清楚就会出现"部分字段取快照、部分取活 ref"的混读（读出来的状态
既不是刷新前也不是刷新后）。
**现状口径（2026-10-06 登记，`stores/floodStore.ts` consumeState）**：快照字段 = `waterLevel`；
活状态字段 = `floodStatistics` / `floodFeatures` / `floodRiskLevel`。失效条件：新增字段需要跨刷新
保留 ⇒ 必须先进快照 schema 与本节清单，再改 `consumeState`。
**依据**：b028
**自检**：恢复态的每个字段，刷新之后它从哪来？答不出"快照"或"本轮查询"就是混读。

## D. 错误与可观测

### D1 `catch` 不得吞掉错误对象

**规则**：`catch (e) { return null }` 这种丢弃 `e` 的写法禁止。至少记一条 warn（带错误码与上下文），且必须能区分"降级"与"真的没数据"。
**依据**：空间算子吞 DB 故障致灾害评估假绿灯（原编号已失效）/ 已被独立发现多次
**自检**：`catch` 块里有没有 `e` 被使用？

### D2 生产必须可观测

**规则**：错误上报 / 关键链路日志 / 契约违例告警**不得**被 `import.meta.env.DEV` 门控。采样只能用于成功路径 info，不得吞掉 warn/error。
**依据**：z003（无 SDK + logger 无 transport + 两处 DEV 门控 + 采样吞契约违例）
**自检**：把 `DEV` 常量改成 `false`，还剩多少可观测点？

### D3 前后端日志必须能用同一 ID 关联

**规则**：请求 ID 必须上送后端并在两侧日志中输出，否则用户报障无法与某次后端执行配对。
**依据**：z003 / 已被独立发现
**自检**：能否用一次 error 的 rid 追到后端那一次执行？

### D4 "看起来有防护、实际没有"按 P1 起评

**规则**：**防御分支失效**（守卫不可触发 / 清理函数零调用 / 守卫判据无人写入 / 采样吃掉告警）比根本没有防御更危险，定级 **P1 起评**。
**依据**：审查体系约定 §1 特别约定；本批"防御壳化"族跨专项合计 39 处
**自检**：新增防御时，问"有没有触发路径与消费方"。

### D5 提示文案不得承诺它驱动不了的恢复路径

**规则**：toast / 按钮 / 空态文案里出现的每个动作承诺（"再点一次重试"、"稍后自动恢复"、"已与某某同源"），都必须能由该错误实际携带的 payload 或实际存在的机制兑现。失败必须可分类（至少 `retryable` 与非 `retryable`），否则"重试"对确定性错误必然再失败——文案给出的出口不存在。同一错误的上报点必须唯一（多处各弹一次 = 重复提示）。
**依据**：a034 的 W5 半（`App.vue` 承诺"请再点击一次重试"而 `LayerErrorPayload` 只有 `key/label`）、924/专项8 工单原话"**不许改文案掩盖缺口**"、921 D21-10（同一失败弹两次 toast，三页处理不一致）
**自检**：照文案说的动作再做一次，这次会成功吗？谁会执行它？

### D6 兜底必须留痕且与成功可区分

**规则**：任何"拉不到就用本地值"的兜底，必须同时满足：①成功走 info（或采样），兜底走 warn/error（生产保留，不得 DEV 门控）；②warn 携带兜底数据的身份（来源 + 版本/提交 + 生成时间），凭它能判定"这次是兜底"；③UI 无需区分，但控制台/日志必须可区分。静默兜底（零日志、与成功同一条日志）按"看起来有防护、实际没有"（D4）起评。
**依据**：site-suitability 权重双源收口（2026-10，前端恒传旧权重而后端缺省分支生产走不到 + metadata.weightsSource 恒写定稿标签无人发现——两个幽灵同属一案）；用户裁决"杀掉幽灵行为，全项目推广"。
**自检**：把后端/远端掐掉跑一次，控制台出现兜底 warn 且带身份吗？不断网时有 warn 吗（有 = 误报）？

## E. 架构与分层

### E1 依赖方向单向；反向依赖必须有规则拦

**规则**：L0-L8 单向依赖。`services` 不依赖 `business`；`shared` 不依赖 `core`/`stores`/`business`；`stores` 不 import `business`；core/shared 不承载业务语义。
**依据**：z047 / d013 / c023 / c024 / z051 / z053 / z054
**自检**：`npm run cruise` 是否覆盖这条边（注意：绿 ≠ 有规则）。

### E2 守护规则的覆盖面必须等于实际目录集合

**规则**：规则**禁止**用"逐个枚举模块名"表达全称约束（每加一个模块就静默少一格保护）。必须有断言：**规则里的模块集合 == 实际目录集合**，缺一个即 fail。
**依据**：z051 / z053（互引规则只枚举 3 个模块，第 4 个业务模块自落地起无守护；该边类型完全无规则）
**自检**：`ls business/` 的目录数与 cruise 规则里列举的模块数是否相等？

### E3 文档承诺的守护必须在配置里存在

**规则**：文档/注释/指标里写"有 X 门禁"时，配置里必须有对应规则。**不允许文档挂着门禁而配置没有**——读者会据此既不人查也不机查。
**依据**：z051 / "入口收口 0 violation 门禁"的表述存在，但 19 条 cruise 规则里无一条是收口判据；`types:check` 自称"前后端契约校验"却不读后端（该条原编号已失效）
**自检**：文档里每句"有门禁"，能不能指出规则的第几行？

### E4 新增模块必须同步更新全部散点（清单化）

**规则**："加一个业务模块要改 N 处"这件事必须有**成文清单**，且清单本身要有守卫（清单项 == 实际需要改的位置数）。
**依据**：新增业务模块需改 12 处散点（原编号已失效）
**自检**：新增模块时，是不是靠记忆找要改哪里？

### E5 core/shared 禁止业务语义

**规则**：core/shared 层不得出现业务名的联合类型、按业务字符串分支、按中文标签子串选图标、指向业务数据目录的路径常量。
**依据**：a028 / c023 / c024 / z047（`PaginatedListPanel` 把业务名写进 props 与分支；核心图层面板按中文子串选图标；改名即静默丢图标）
**自检**：core/shared 里 grep 业务词（选址/预测/浸没/route/forecast/flood）。

### E6 环与越权面必须有执行体；层聚合入口不得成为免检枢纽

**规则**：三类结构约束不能只写在文档里：① 目录级 / 层聚合级的循环依赖（`a→b→a` 按目录聚合）必须有 SCC 型检查，文件级规则看不见它；② barrel 不得导出"能绕过唯一入口"的实现表——走聚合入口拿越权面比深路径更隐蔽，且**看起来像被批准的**；③ 枢纽文件（`*/index.ts`、manifest）本身必须落在某条规则的 `from` 域内，否则它可以任意跨层。
**依据**：923/专项6 R5、R4；922-R2 R2-03-08（`core/index.ts` 导出 `LAYER_ADAPTERS` 全表，与"图层只能经 BLM"红线冲突，消费者已存在）；`routes-audit` 的 `ENV_COPIES` 型"枢纽不参与判据"问题
**自检**：把两个目录互为依赖，哪条规则会红？barrel 里有没有一个导出能绕过它的唯一入口？

### E7 前端业务模块目录按「按需模板」建，差异要能一句话说清

**规则**：`frontend/src/business/<域>/` 的目录模板 = **`constants/`、`composables/` 按需**；
**`adapter` 只在 flood 有**（与 a023 决议一致：选址/预测的数据转换走 composable，不另立 adapter）。
新模块允许与模板不同，但差异必须在建目录当笔写出理由（写进模块 README 或本规则），
不允许"三个模块三套结构、谁也说不清为什么"。
**依据**：b023（flood/forecast/site-selection 三模块目录各自为政，无模板可依）
**自检**：新模块目录跟 flood 对齐列一遍，每个差异项能一句话说清吗？说不清 ⇒ 改回模板。

## F. 门禁与验证

### F1 每条门禁必须有阳性对照

**规则**：任何门禁（lint / 守卫 / 契约检查）必须自带一个**已知会让它变红的样本**，且该样本在 CI 中被断言"预期失败"。**不允许存在从未红过的门禁**——它和没有门禁无法区分。
**依据**：本批"验证器与真实断言脱节"族（stylelint 对 `.css` 零解析、token 统计未挂载、覆盖率棘轮只比 total、变异探针未接门禁；原编号已失效）
**自检**：这条门禁最近一次变红是什么时候？

### F2 注释/文档宣称的能力必须有断言指向

**规则**：注释写"已脱敏"、"已收敛"、"已校验"时，必须有一个测试或守卫能验证该能力。**禁止把注释当作已实现的证据**（历史上有审查轮次直接引用注释作为"通过"依据）。
**依据**：z023 / 本批同一形态 35+ 处
**自检**：这句"已 X"，哪个测试会因它失效而变红？

### F3 测试必须对常数敏感

**规则**：数值断言不得只用"常数相消"的端点值（如 `d=0` 与 `d≫radius`）——那样改坏地球半径也不会红。必须包含中间值锚点。
**依据**：评分测试对地球半径不敏感（`toBe(50)` 由端点算出；原编号已失效）
**自检**：把常量乘 2，哪个测试会红？

### F4 测试必须覆盖生产分支

**规则**：mock 掉的必须是**非**生产分支。若 mock 数据形状使生产分支恒不执行（如模型返回 cargo 形状致模型分支恒 null），则等于零测试。
**依据**：生产分支未被测试覆盖的两类形态（原依据只含台账编号，均已随 2026-09-19 归并重排失效）
**自检**：生产走的是哪条分支？测试走的是同一条吗？

### F5 覆盖率棘轮必须单调不降

**规则**：覆盖率基线不得被自动 `--update` 放宽；须有"核心层 per-dir floor + 基线单调不降"断言，防止核心层回归被非核心层涨幅掩盖。
**依据**：z020（只比 total、缺基线静默放行）
**自检**：覆盖率涨了，是核心层涨还是测试文件涨？

### F6 门禁的判据输入必须受版本控制，且不得依赖运行期才存在的东西

**规则**：一条门禁能读的东西只有三类——入库文件、本次运行自己产出的结果、明确声明过的运行态。禁止读：工作树脏件、历史结果文件、gitignored 路径、未拉取的 git 历史（浅克隆下 `git log -1 -- <file>` 会返回 HEAD 日或空 ⇒ 要么假红要么整批跳过）。禁止依赖未安装的第三方 CLI/可执行文件：工具不可用时必须**记 SKIPPED 并计入报告**，既不得判红也不得判绿。判据若把"跑不了"算成红，干净检出与 CI 上就永远不可能绿，实际结果是逼使用者绕过整条纪律。
**依据**：z055 / z056 族（"门禁消费仓库里不存在的东西"已第 4 次发作）；924/专项5 N5-01（`runCommitlint` 的子进程在加固终端 EBUSY ⇒ `guard:v3` 恒红 ⇒ 当日 **5 笔**提交用 `--no-verify` 绕过，并真的漏进过一处 `format:check` 红）；924/专项8 M5（新鲜度判据读 git 历史，`backend-tests` job 浅克隆）；本条同时是"工作树绿不算绿"的正面表述
**自检**：`git archive HEAD` 解出来的沙箱里，这条门禁的退出码是多少？它读的每个路径/结果文件在不在入库集合里？

### F7 新增强制检查之前，必须先扫"存在但从不触发"的检查

**规则**：加一条新门禁前的固定三步：① 扫既有挂载点（`run-all.mjs` 的清单、`.husky/`、`ci.yml`、`package.json` scripts），列出**同类的已有检查**；② 回答"它为什么没拦住这次的问题"——覆盖面窄、判据选错、还是**根本没有调用点**；③ 声明新检查与已有检查的关系（子集 / 正集 / 相交）。已知反例形态：`check-issue-ids.cjs`（2026-10-06 已删除：曾存在、零调用点、且判据输入恒空，功能由 `ledger-dedupe` 接管）、`test-watchdog --static`（判据从未有过触发点）、`token-stats`（存在、红的、没人跑 ⇒ 诚实执行 SOP 的人被红挡回去，最后 SOP 被当装饰）。**被取代的旧载体必须原地删除或标废弃，不得遗留**（遗留即 I3 死代码 + 下一个 agent 会去改它）。
**自检**：这条新检查拦的是哪一次具体事故？给出它的红样，并指出已有检查为什么拦不住。

### F8 门禁降级为 experimental 必须是显式三件套

**规则**：新门禁易误报、或存量未清零时，允许登记为 **experimental**（只报不阻断），但必须同时具备：① 入口标记（清单里带状态字段，不靠注释）；② **到期日 + 归属台账号**；③ 强制升级判据（如"连续 N 笔 0 误红即转阻断"）。降级期间**任何文档、注释、SOP 不得把它表述为"已有门禁"**（那是 E3/H1 的成因）。反向禁令：结构上不可能变红的检查（比判据"工作树 vs HEAD 逐字相等"，而 CI 里两者恒等）不是 experimental，是**必删或必修**。
**依据**：922-R3 R3-02-04（`coverage-ratchet --freeze-check` 结构上不可能红）；z041⑦ 的"绝对判据一上即红 28 行 / 行级豁免仍红 26 行 / 只有棘轮 0 红"三选一悬案
**自检**：这条检查最近一次变红是什么时候？它有没有到期日？文档里有没有哪句话正把它当成已存在的保护？

### F9 单一事实源登记（每个事实恰好一处权威 + 派生点带守卫）

**规则**：同一事实（名单/阈值/枚举/路径/域清单/错误码/门禁条数/接口清单）只允许**一处权威**；任何第二处出现必须满足两条：① 显式登记为派生点（谁派生自谁）；② 附一条"改权威处必红"的守卫。登记载体 = `tools/v3-guard/lib/doc-map.json` 的 `facts[]`（事实 id | authority | derived[site+guard] | 总守卫）。**半覆盖的守卫比没有守卫更危险**——它把漏检变成"已检查"。禁止"改一处 + 注释提醒同步"。
**依据**：AGENTS 旧 §七-7（本项目这样修过 6 处，6 处都再长出新副本）；doc-map-check 的 FACT-GUARD/DOC-UNREG 判据；doc-numbers 对门禁条数的对账
**自检**：新写下一份名单/阈值/清单前，先答两问：它是权威还是派生？派生的话，守卫叫什么、在哪一行注册？

## G. 安全与凭据

### G1 凭据不得入库——包括历史

**规则**：密钥 / 口令 / 用户数据文件（含哈希）不得进版本库。**历史中的泄漏必须被当作"当前风险"处理**：轮换密钥 + 明确处置记录，不得用"CI 扫不到历史"当作已解决。
**依据**：d048（含 d056 天地图密钥入历史 7 个 commit；CI `--no-git` 按设计看不到历史；声称的清理脚本在库中不存在；台账标"已解决"而载体缺失）
**自检**：`--no-git` 之外，有没有人真的看过历史？

### G2 忽略规则必须精确覆盖真实落点

**规则**：`.gitignore` 的忽略路径必须与代码里**实际读取**的路径一致——只忽略一个目录、而代码实际从另一个目录读，是历史上真实发作过的形态（忽略规则与真实落点不匹配）。密钥类文件用通配 `**/` 覆盖，别写单点路径。
**依据**：d048
**自检**：grep 所有读密钥文件的地方，逐个 `git check-ignore`。

### G3 allowlist 必须锚定

**规则**：密钥扫描的 allowlist 正则必须锚定（`(^|/)\.env$` 而非 `\.env`），否则 `.env.example` 等合法文件也会被放行，门禁静默失效。
**依据**：d048
**自检**：allowlist 里每条正则，问"它能匹配到不该匹配的文件吗"。

### G4 认证必须有 owner 校验；资源 ID 必须不可枚举

**规则**：每个资源端点做属主校验；ID 用 UUID 而非时间戳（时间戳可枚举 ⇒ 可越权读取/取消他人任务）。排队类接口的"抢占"必须校验发起者。
**依据**：d003 / 已被独立发现（task 域免鉴权 + taskId 时间戳可枚举 + 可取消他人任务）
**自检**：用另一个账号的 ID 打一次这个端点。

### G5 限流键必须是真实客户端 IP

**规则**：反代后必须开 `trust proxy`，否则全站共享一个桶，登录可被匿名打满。限流桶的分桶语义必须与端点语义匹配（轮询端点不应打满全局桶）。
**依据**：d058 / d037（未开 trust proxy；task 轮询 500ms 打满全局限流桶，429 被前端误判为"与服务器失去联系"）
**自检**：429 出现时，桶是按 IP 分的吗？

### G6 匿名资源槽不得靠客户端自报的标识来认属主

**规则**：给匿名请求分配"属主"时，若该属主来自客户端自带随机串（明文头上送），它只是**能力令牌**不是认证——持有者即得主。这种模型对公开计算端点可以接受，但**必须在契约与威胁模型里写明**，并配严格限流；写成"记录含 ownerId ⇒ 已防越权"是虚指。会话级分槽（`anon:<随机 id>`）解决的是"互不串槽"，不解决"伪造该串即抢槽"。
**依据**：d059 的修法残留（924/专项5 §3：不带 `x-task-client` 的旧客户端仍共享槽；代码注释自认）、921 D21-06（`priority` 客户端自报可全员插队、`route` 任意字符串绕过去重）
**自检**：攻击者要拿到什么才能顶掉这个槽？这个条件写在哪份文档里？

### G7 部署必须覆盖进程生命周期：PID 1、优雅关闭、宽限期、内存上限自洽

**规则**：容器化 Node 服务必须有：① `init: true` 或能收 SIGTERM 的 PID 1（`CMD ["node", …]` 使 node 即 PID 1，默认不响应 SIGTERM ⇒ 10s 后 SIGKILL）；② 应用侧 `enableShutdownHooks()` 且**清理钩子真的可达**；③ 保留 http server 与连接池引用，以便 `close()` / `end()`；④ `stop_grace_period` 与 ⑤ `mem_limit` + `NODE_OPTIONS --max-old-space-size` 自洽（内存上限低于容器限额，否则 OOM 表现为 cgroup SIGKILL 137 且无日志）。健康探针必须能区分"进程活着"与"能停干净"。
**依据**：924/专项2 N-7（全 `backend/src` 只有 `task-registry.ts:228` 一句注释提到 shutdown；`app.listen` 未保留引用 ⇒ 无可关之物；`Dockerfile.nest:44` exec + compose 无 grace period）、N-5/N-6、L27
**自检**：`docker compose up -d` 重建一次，在飞请求与连接池各自发生了什么？日志里能看到优雅关闭吗？

## H. 文档与注释

### H1 注释不得宣称不存在的机制

**规则**：注释描述的机制必须**在代码里存在且被调用**。禁止写"由 X 处理"而 X 不存在、"已收敛"而仍有桥接断言、"启动时显式报错"而只 logger.error。
**同一视觉量跨元件互引为依据也算这一条**：写"与 X 同一口径"之前，必须确认 X 的实现体真的读那个值。实测形态——进度环的圆角注释与反算常量都自称取自 GCS 圆角 token，而 dock 按钮的圆角是它自己行内算出来的（不消费任何 radius token）⇒ 两处注释把不存在的耦合写成了维护义务。**要么按对方的公式派生，要么在注释里写明是恒定值、与对方两套口径。**
**依据**：z023 / 本批 35+ 处（含指向不存在的脚本、不存在的目录、不存在的契约比对脚本）；`TaskProgressRing` 圆角基准（2026-09-25 由按钮行内计算式核对后撤回旧口径）
**自检**：注释里提到的每一个文件名/函数名，grep 是否存在；写"与 X 同一口径"的，grep X 的实现体确认它真的消费那个值。

### H2 路径引用必须有效

**规则**：`.gitignore` / lint 配置 / 规范文档 / 注释中的仓库路径字面量必须指向**存在**的路径。建议加一条守卫：扫这些文件里的路径字面量，命中不存在即 fail。
**依据**：z023（同一腐烂模式独立发作 4 次：指标范围写 `backend/nest/`、忽略规则指向已删目录、lint 豁免指向已删文件、注释指向不存在的脚本）
**自检**：`grep -o '[a-z/]*\.\(ts\|js\|sh\|json\)' 配置与文档` 逐个 `test -e`。

### H3 行号不得进规范文档

**规则**：规范/设计文档里禁止出现 `file:line`（会腐烂）；只写符号名与模块名。反例一律放附录并标取证日期。
**依据**：已有明文规则；实锤——某轮副本里的行锚 5 天内即不可 grep
**自检**：文档里有没有 `:123` 形式的引用。

### H4 审查与规范用的标准库本身，也是必须被校验的产物

**规则**：指标库、附录对照表、命名标准里的**路径、目录名、token 名、模块枚举**必须真实存在。标准库失效的后果比代码 bug 更隐蔽：执行者要么把"该 token 不存在"误判成实现违约（误报），要么判"无法检查"而放行（漏报），更糟的是**按原文执行会把现役代码整批判成违规**。文档出现的具体枚举/清单同样不得复制实现——它是 RC1 的一种。
**依据**：923/专项6 G2（某指标检查范围仍写已删除的老服务目录与不存在的子目录）；922/专项7 发现 32（标准库四处自相矛盾 ⇒ 每轮系统性漏一条指标）；924/专项7 2.8（基准引用一批权威源里不存在的 token 名）；`.gitignore` / lint 配置指向已删路径（z023 型，已第 4 次发作）
**自检**：这条指标让你排除/对照的那些路径与名字，逐个 `test -e` / grep 命中吗？

### H5 规则的依据不得指向会重排的数字编号

**规则**：条款的「依据」列一律用**稳定符号**（函数名、配置项、文件+规则名、审件里的语义名），不得只写台账编号——台账编号按 discover 升序重排且旧号不复用，编号一旦漂移，"依据"就指向一条无关条目，比没有依据更坏（读者会顺着错指去改错的地方）。确需引台账号时，必须同时给一句语义描述，使错指可被当场发现。
**依据**：`04-G5` 的曾写依据 `d061`，而 d061 现义为"site-analysis 任务通道跳校验"，与 trust proxy 无关（922-R2 R2-14-三审 N-3' 记录了这条错指至今未改）
**自检**：把这条依据指向的编号在两份台账里 grep 一次，它说的是同一件事吗？

## I. 工程卫生

### I1 禁止"未跟踪但未忽略"的第三态

**规则**：仓库里不允许存在既未跟踪、也未被忽略的文件（一次性脚本 / 探针 / 临时产物）。要么入库，要么进 `.local/`，要么删除。守卫必须覆盖 `src/` 目录而不只是根目录。
**依据**：根级一次性脚本 + `src/` 内探针文件，均未跟踪未忽略，进 `git status` 与文件扫描面（原编号已失效）
**自检**：`git status --short` 里有没有 `??` 项。

### I2 退役 / 事故 / 探针三类必须有收尾断言

**规则**：① 组件退役 → 同步从门禁、dev 脚本、env 模板、TODO 中摘除，一次做全；② 事故现场（`.git-BROKEN-*`、`tmp-*`）必须清理；③ 探针文件不得落在源码目录。
**依据**：退役服务口径四处不一致；审计编号注释残留（原编号已失效）
**自检**：退役一个服务时，列出它被引用的全部位置了吗？

### I3 死代码必须清理

**规则**：零消费者导出 / 死 schema / 死 action / 空入口文件 / 死配置路径都是负资产——它们让"可用面"看起来比真实大。清理应批量做。
**依据**：零消费者导出 20+、死 schema、死 action、空 index 入口（原编号已失效）
**自检**：新写的 export，有没有消费者？

### I4 临时物不得进源码目录

**规则**：一次性产物统一落 `.local/`；`.gitignore` 需覆盖该目录；守卫的断言范围要包含 `src/`。
**依据**：I1（同族实例的原编号已失效）
**自检**：新建文件时，先问"它属于源码还是临时物"。

### I5 格式类提交是行号锚点的批量破坏者，必须单独过一遍引用

**规则**：`--fix` / 自动重排 / 挪目录这类**不触碰语义却改变行号与记法**的提交，必须在同笔里检查"仓库里有没有引用被格式化文件行号的注释或文档"，并把行号引用改写成可 grep 的标识符（配 H3）。同时：只按记法判定的规则（如禁 hex 字面量）会被一次格式化改写整体满足 ⇒ 记法性规则必须配**按属性/按语义**的对照规则（如"颜色取值只允许 `var(--x)` 与白名单函数"），否则格式化 = 洗白。
**依据**：924/专项7 2.4（一次 `--fix` 把 52 处 hex 换成 `rgb()`，使"硬编码色值"在该文件永久不可见，并顺手消掉上一轮认定的唯一真实违约）、2.7（两次 `--fix` 位移 43 行，两处引用其行号的注释当场失真）
**自检**：这笔纯格式提交改动了多少行？有没有任何注释/文档引用过这些行号或依赖这种记法？

## 附：使用方式

| 场景           | 用法                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| **写新代码前** | 扫一眼对应节的"规则"（A 渲染 / B 数据 / C 状态 / D 错误 / E 架构 / F 门禁 / G 安全 / H 文档 / I 卫生） |
