## 一、数据流总览

```
业务组件 → 取数入口（useApiRequest / loadStatic）
  ├─ flood         → floodAdapter       （services/adapters/）
  ├─ forecast      → useForecastRequest （业务 composable，事务/竞态管理）
  ├─ route         → useRouteApi        （业务 composable）
  ├─ site-analysis → useSiteAnalysisApi （业务 composable，直连 useApiRequest + zod 校验）
  └─ 数据源: 静态 → loadStatic（public/data 契约桩）
             接口 → fetch → Nest /nest-api/*
后端：modules → controllers → services → repositories（PostGIS）+ data-files.service（静态 JSON）
```

**取数铁律**：请求唯一入口、信封唯一、边界 zod 校验、数据源归属统一管理（详见下文规则）。业务组件**不直接**判断数据源、不裸 fetch。

## 二、前端取数规则（R1-R5）

| 规则                | 内容                                                                                                                                                                                  | 违反后果                        |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| **R1 请求唯一入口** | API 一律走 `useApiRequest`；静态资源一律走 `loadStatic`。禁止裸 fetch/axios                                                                                                           | 报错口径/重试/超时/解包全部失效 |
| **R1.1 跨服务例外** | 免信封端点（如 route 路径计算返回裸结果对象）经 `apiRequest` 传 `envelope: false`，仍在统一入口内                                                                                     | 同 R1                           |
| **R2 信封统一**     | 响应契约 `{ code, data }`，前端解包唯一走 `unwrapEnvelope`，禁止手写 `res.data`                                                                                                       | 解包逻辑重复、漂移              |
| **R3 静态资源**     | `loadStatic`（超时 / TTL / in-flight 去重 / LRU 上限）                                                                                                                                | 缓存/超时/校验缺失              |
| **R4 数据源归属**   | 业务组件不得直接判断数据源；数据源差异一律收敛在 adapter / composable 内（FastAPI 退役后为单模式，无需运行期分流）                                                                    | 数据源语义散落                  |
| **R5 取数统一收口** | 业务组件取数一律经 `useApiRequest`/`loadStatic` 统一入口；跨业务复用的取数封装放 `services/adapters/`（当前仅 floodAdapter）；业务专属取数逻辑（事务/竞态/校验）放业务模块 composable | 中间层不一致、统一入口被绕过    |

## 三、后端响应规则（R6-R8）

| 规则              | 内容                                                                                                                   | 违反后果       |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------- | -------------- |
| **R6 成功出参**   | controller 一律 `sendSuccess(res, data)`，信封 `{ code, data }`                                                        | 前端解包失效   |
| **R7 错误出参**   | 错误抛 `BusinessError(code, message)` → 全局错误中间件统一映射 HTTP 状态码；禁止 controller 裸 `res.json`/`res.status` | 错误口径不一致 |
| **R8 读文件缓存** | 后端读 JSON 文件缓存统一 `createReadCache`（TTL + LRU + 上限），禁止自研 cache Map                                     | 缓存实现重复   |

### 4.2 预测分析（Forecast）

```
控件变化（指标 / 置信度 / 时间 / 播放）
   │   三值合并 watch + 300ms 防抖（拖动不逐次发请求，停手才发起）
   ▼
doForecastUpdate → startTransaction（新事务启动即取消旧请求，事务 ID 存 store）
   │   Promise.all 并发三个请求，共享 signal
   ├─ GET /forecast/timeseries        → 折线图（按月数据，12 点窗口截取）
   ├─ GET /forecast/indicator/:type   → 柱状图（cargo+container 两指标 × 三港）
   └─ GET /forecast/map               → 地图图层（heatmap / geojson）
   ▼
图表写页面本地 ref；图层经 BLM updateData（key: forecast-{indicator}，切换指标自动显隐）
```

**事务语义**：指标/时间/置信度任一变化 → 新事务 → 旧请求被 abort。播放模式 500ms/tick，每 tick 重置防抖。**当前行为是"取消旧请求重新发"**；"快速重放不丢动画"是期望改造项（未定，见台账方向）。

**已知边界**：cargo 为模型基线（无置信度滑块）、container 为确定性趋势外推；播放中 429 限流静默降级不弹 toast。

**预测数值自洽（应然契约，审查比对基准——专项8 3.4/3.8/3.12/4.1 的标尺）**：

- 确定性：同一输入必须同一输出——随机源必须显式种子（`seededRandom`），禁止 `Math.random` 直接参与业务数值
- 数值合理性：预测值不得为负、不得发散到荒谬值（10 年外推 2031 边界闭合）；置信度 0.8-1.2 对结果的影响单调且有界
- 双通道口径一致：模型产物（cargo）与引擎外推（container 确定性趋势外推）在拼接点无跳变；年→月聚合口径统一（12 个月均值 vs 年值）
- 回测可复现：README 宣称的 MAPE ≤ 2.3% 必须能用回测脚本重跑复现，口径（窗口/公式）有文档
- 合成/模拟处必须诚实标注（UI/注释/README 三处一致）——叙事与行为不符是面试翻车点

### 4.3 浸没分析（Flood Analysis）

```
水位滑块（展示域 0-10m，step 0.1；刻度 0/2.5/5/7.5/10 可点击；后端档位域 0-25m）
   │   100ms 防抖
   ├─ triggerFloodAnalysis  → floodAdapter → Nest /flood/*
   │      查 PostGIS flood_levels（0.0-25.0 共 251 档），返回 requested + actualWaterLevel
   └─ triggerImpactAssessment → 受影响设施评估
   ▼
渲染三层：水面（3D-only）+ 淹没范围多边形（双引擎）+ 受影响设施点（双引擎）
```

**档位语义（向上取档）**：请求 2.5m 时返回 3.0m 档数据——**故意为之**：宁可高估风险不可低估，前端通过 requested/actual 感知差异（当前仅日志，不弹警告）。

**真 DEM**：演算基于陆地真 DEM（填洼产物）；**海底 DEM 尚未获取**（当前海洋区域按海平面处理）——这是浸没分析真实性的最大短板，也是新选址分析的铺垫工作之一。

**淹没语义（应然契约，审查比对基准——专项8 3.5/3.6/4.5 的标尺）**：

- 水位 0 → **无淹没**（海面种子正确性的验证点）；淹没面积随水位**单调不减**（低水位面积 > 高水位面积 = 数据错）
- 档位取整语义：`flood_levels` 共 251 档（0.0-25.0，0.1m 步）**一律向上取档**（`find(档 ≥ 请求)`）——宁可高估风险；请求与返回差异经 `actualWaterLevel` 透传（前端至少可感知）
- 档位表边界（请求超出最高档）语义明确（拒绝或取顶档，不得静默）；设施评估与淹没范围必须同档同源，不得跨档混配
- 水深例外：平均 / 最大水深源数据无 251 档，仍取 6 档 DEM 反演参考表，经 `depthRefLevel` 标注所属档位（面板以 `*` 提示参考档位与实际档位不一致）；未指定水位路径保持 6 档兼容
- 设施评估（受影响设施/损失）与淹没范围必须同源（同一水位档的演算产物），不得跨档混配

### 4.4 快照恢复（保留态）

```
业务页（选址/预测/浸没）→ 跳 /profile 前 saveState（内存快照）
   │   路由切换本身不重置任何 store；只有登出触发 resetStores
   ▼
返回业务页 → onMounted consumeState（一次性消费）→ 恢复控件状态与结果图层
   │   离开业务页但不走 /profile → clearState（清空）
   ▼
快照是内存级：同标签页路由导航之间存活，刷新/关闭即失（设计如此）
```

## 五、关键机制

### 5.1 Renderer 生命周期

- 渲染器实例**复用不销毁**；3D→2D 切换必须 `unmount()`（暂停渲染 + 空闲销毁）；30s 内切回由 mount 取消销毁。
- 能力缺失（如 2D 上调用水面）由调用方检查跳过，禁止空实现 stub。
- 引擎切换后图层由 BLM `reapplyAll` 按 registry 重建。

### 5.2 图层管理（BLM）

| 语义                | 行为                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------- |
| 注册即占位          | `register`：数据未就绪也可注册（visible 控制），重复 key 忽略                             |
| updateData          | 未注册则 throw；不可见只缓存；可见且无实例 → 补建，有 → 更新                              |
| registry vs catalog | **registry 是可见性唯一权威**（实例内 Map）；catalog 只是面板元数据（引擎切换会清空）     |
| reapplyAll          | 引擎切换后按 registry 重建全部图层，单层失败不拖垮整批                                    |
| 特殊图层            | 水面（不在 \_layers）经 adapter `setVisibility` 分派，禁止落入 pendingVisibility 失效路径 |

### 5.3 水面 vs 淹没多边形（容易混淆，明确区分）

|        | 水面（flood-water-surface）                                               | 淹没多边形（flood-area）                 |
| ------ | ------------------------------------------------------------------------- | ---------------------------------------- |
| 是什么 | **水平面片**，高度 = 当前水位                                             | **被淹区域**（DEM 演算出的不规则多边形） |
| 回答   | 水位涨到几米（三维位置）                                                  | 哪些地方被淹了（受灾范围）               |
| 渲染   | **仅 3D**（能力接口 Water3DCapability，Cesium 实现；2D 下注册但跳过创建） | 2D/3D 均可                               |
| 数据   | 水域坐标文件                                                              | 真 DEM 演算产物                          |

**注意**：水面是 3D-only 是设计；但 2D 下"图层控制面板有条目却无法控制"是已知交互缺陷（台账）。

### 5.4 GCS 布局三档

- 档位 1（≥960px）：桌面等比例布局，面板原位显示
- 档位 2（640-959px）：抽屉模式，面板收进 MobileDrawer，底部 nav 出现「菜单」键
- 档位 3（<640px）：抽屉紧凑，底部 nav 收敛为 3 键
- 断点判定在 `useGCS`（showPanels / showTopArea / navCompact），组件用 computed 消费，**禁止组件内重复判定**。

### 5.5 store 重置链

- 登出（user → null）→ `resetStores`：清业务快照 + 地图状态 + 业务 store（保留 mapType / baseLayerKey 等用户偏好）。
- 路由切换不触发重置；保留态走快照工厂（见 4.4）。
- store 职责单一；多 store 协调重置放应用层，不放"壳 store"。

### 5.6 数值与防御不变量（全局应然，专项8 的比对标尺）

> 审查/开发时以上述各流程语义 + 以下不变量为"应然"，比对代码"实然"。历史教训：防御分支静默失效比没有防御更危险（曾实锤 `isEmpty?.()` 调不存在方法、`||` 兜底被优先级绕过，均已在 45df38a 修复）。

1. **确定性**：同输入同输出；随机源必须显式种子；无对象遍历顺序依赖。
2. **防御可触发**：防御分支必须证明在真实输入下可达——`?.()` 调用的方法必须存在；`||`/`??` 兜底必须覆盖整个分母表达式（`a / (b || 1)` ≠ `a / b || 1`）；`Math.cos(π/2) = 6.12e-17 ≠ 0`，不能用 `|| 0` 兜底；`parseFloat(x) || 0` 会把坏数据伪装成 0（应显式处理）。
3. **粗筛保守**：rbush bbox 粗筛必须是精确结果的超集（宁大勿漏）；`kmToDegreeOffset` 需纬度修正且保守扩张；粗筛漏配 = 结果错误。
4. **缓存 = 重算**：缓存命中结果必须等于清缓存重算结果；key 必须覆盖全部参数维度（indicator/time/confidence/waterLevel），缺维度 = 串数据。
5. **NaN 禁传播**：计算链入口 `Number.isFinite` 守卫；展示层 `NaN → '--'` 兜底；任何路径不得把 NaN 静默算进结果。
6. **单位一致**：空间算子现主要在 PostGIS（`ST_Buffer`/`ST_DWithin` 走 geography 或投影米，
   面积 `ST_Area` 平方米）；仍在前端的 turf 调用半径用千米（`units: 'kilometers'`）；
   展示换算（m²→km² 除 1e6）集中在展示层；常量带单位注释。⚠️ 旧版「@turf 全面在用」的表述
   已过期——后端已于 v3 收口时全面移除 `@turf/turf`，任何 `package.json` 都不再依赖它。
7. **浮点比较用 epsilon**：禁止 `score === 100` / `area === 0` 直接比较。
8. **空与错误分离**："业务空结果"（无重叠区域/无匹配）走合法 `data`，错误走 `error` 信封——前端两态 UI 语义不同。

## 一、编码规范

### 1.1 核心原则

```
1. 地理术语优先于通用术语
   lng/lat（不是 lon/lat）｜ elevation（不是 altitude）｜ feature（不是 item）｜ crs（不是 coordSystem）

2. 代码自解释，注释写"为什么"和"地理背景"
   不写 "// 遍历数组"
   写 "// 北部湾区域存在大量凹多边形，turf.union 可能返回 MultiPolygon，需降级处理"

3. 双引擎思维渗透到命名
   凡是可能同时存在 2D/3D 两种实现的，必须用策略模式命名（Renderer / Adapter / Strategy）
```

### 1.2 命名规范

**地理术语词汇表**（节选，全表见各业务 types 定义）：

| 场景       | 使用                       | 弃用                 |
| ---------- | -------------------------- | -------------------- |
| 经纬度     | `lng`, `lat`               | `lon`, `latitude`    |
| 海拔高程   | `elevation`                | `altitude`, `height` |
| 坐标数组   | `coordinates`              | `points`, `path`     |
| 单个要素   | `feature`                  | `item`, `data`       |
| 要素集合   | `featureCollection`        | `list`, `array`      |
| 渲染器实例 | `olRenderer`, `csRenderer` | `map1`, `map2`       |

**文件命名**：Vue 页面 `XxxPage.vue`、面板 `XxxPanel.vue`、组件 `Xxx.vue`；TS 模块 `camelCase.ts`；Store `xxxStore.ts` + 导出 `useXxxStore`；类型 `camelCase.ts`；测试 `原文件名.test.ts`。

**函数命名**：`动词 + 地理对象 + 动作细节`（`queryFacilitiesByPolygon`、`flyToCoordinate`）。

**类型与接口**：无 I/T 前缀，业务语义优先（`MapRenderer`、`SiteSelectionParams`）。

**常量**：模块级 + 语义分组 + `as const`；带单位注释（`DEFAULT_BUFFER_RADIUS = 3000 // 米`）。

**GCS 书写铁律**：`GCS`（Global Component Style）只允许全大写；`Gcs`/`gcs` 一律违规。`CGCS2000`（坐标系术语）豁免。

### 1.3 注释规范

- **不写**"做什么"（代码自解释）。
- **要写**"为什么"：坐标系选择、Turf.js 已知坑、性能决策、数据档位设计意图。
- **标记约定**：`FIX:`（Bug）、`TODO:`（计划功能）、`@arch-note`（架构有意为之，与 TODO 同级）。
- 不写 JSDoc 八股文（`@param`/`@returns` 重复类型信息）。

### 1.4 Vue 组件规范

- `<script setup lang="ts">`，顺序：类型导入 → 组件导入 → composable → Props/Emits → 响应式 → 方法 → 生命周期。
- Props 用 `withDefaults` + 泛型 + 元组坐标（`[lng, lat]`）；Emits 用类型化 `defineEmits<{...}>`。
- 禁止 `v-for` 与 `v-if` 同级；禁止 `$refs`（用模板 ref）。
- 样式全部走 `var(--GCS-*)`，禁止硬编码色值；尺寸经 `useGCS` 的 `v-bind()` 计算。
- `pointer-events: none` 在页面根元素 → `:deep(.GCS-panel) { pointer-events: auto }` 恢复面板交互。

**组件拆分标准（2026-08-10 定稿）**——目标不是让文件变小，而是**让变化被隔离**：

- **核心判断**：这个东西未来修改，我希望它影响其他地方吗？**不希望 → 拆**；它只是某组件内部实现细节（永远不单独存在）→ 不拆。
- **按"业务单位"拆，不按 HTML 标签拆**：UserCard 是一个整体；只有当某片段成为独立能力（多处出现：首页/评论/聊天头像）才抽成 Avatar。
- **有独立状态/生命周期/事件 → 拆**；纯展示无状态（如 PanelTitle）→ 不拆。
- **复用等级**：强复用（Button/Modal/Input）与业务复用（LayerControl 多页使用）→ 拆；页面私有但降低复杂度 → 可拆；一次性小片段 → 不拆。
- **行数经验值**：<100 行通常不拆 / 100-300 看职责 / 300-500 大概率拆 / 500+ 基本拆（地图等复杂模块例外——千行地图组件可能合理）。
- **修改测试法**：需求变更只需改一个文件 = 拆对了；需连带改多个页面 = 耦合了。
- **拆太细的代价**：文件爆炸、props 多层穿透（为显示一个数字传 5 层）、新人找不到业务入口——200 个碎片文件比一个 500 行文件更糟。
- **GCS 视角**：按"功能模块 + 状态管理 + 业务职责"拆，不按"div + css 块"拆。
- **口诀**：能独立描述功能 / 有独立状态 / 未来可能复用 → 拆；只为减少行数 → 不拆。

### 1.5 后端规范

- **模块化分层**：`modules/<域>/{controllers,services,repositories,dto}`；controller 只做请求解析 + 响应组装，service 写业务逻辑，repositories 收口 DB 访问。
- **错误统一**：`throw new BusinessError(ErrorCode.XXX, detail)`，错误码表见 K3 §1.3；禁止裸 `throw new Error`。
- **缓存统一** `createReadCache`（`common/cache/read-cache.ts`），禁止自研 cache Map。

### 1.6 Git 提交规范

```
格式：<type>: <正文>

正文写清"做了什么 + 为什么"；精简，不当日志用。
禁止 <type>(<scope>): 括号写法（scope 不值得单独突出时强制括号很难看）。

口径单源即本段；`AGENTS.md` §六 与 `CLAUDE.md` 引用之，`package.json` 的
`commitlint.rules.scope-empty` 是它的机器判据（口径写"禁"而配置不拦 = 零判据的空宣称）。
```

| Type       | 使用场景         |
| ---------- | ---------------- |
| `feat`     | 新增业务功能     |
| `fix`      | 修复 bug         |
| `refactor` | 重构，不新增功能 |
| `perf`     | 性能优化         |

commitlint + husky 强制；lint-staged 对暂存文件跑 eslint + prettier。

**fix 提交必须附测试**（副-27 定）：修复类提交（`fix:`/`refactor:`）必须同时提交或说明对应的回归测试（单测/集成）；纯文档/配置/样式修复可豁免并在提交说明注明。抽查历史 15 个 fix 仅 2 个带测试，此约定收口。

**推送门禁（显性化）**——push 前本地必须全绿，与 ci.yml 同集，任一红不得推。**一条命令跑全套**（顺序与 ci.yml 一致，coverage 阈值/build 全带上）：

```
npm run ci:local
```

> 教训二（2026-08-29 三连败复盘）：门禁清单"存在"不等于"被执行"——三连败里两条是环境差异（本地永不复现），一条是过程竞态，规则必须收敛为单条可执行命令才靠得住。

## 三、GCS 布局规范

> GCS（Global Component Style）设计系统是本项目视觉层的单一事实源：规则（§三.1）+ 资产清单（§三.2）+ 组件规格书（§三.3）。审查体系专项7 以此为"应然"基准，专项7 不再承载设计内容。

### 三.1 布局规则

- **网格单元**：`CELL_PIXEL` 按视口分级（≥1920 → 90 / ≥960 → 80 / <960 → 70）；所有面板尺寸 = 整数个 Cell，禁止硬编码 px。
- **间距**：`GAP = 10px`；面板间距 `PANEL_SPACING = 2×GAP`；安全边距 `SAFE_MARGIN`。常量在 `shared/layout/config.ts`。
- **四条铁律**：① 尺寸整数 Cell；② 锚点定位（禁绝对像素）；③ 禁止硬编码（走 `config.ts` / `--GCS-*` 变量）；④ 间距统一只用 GAP/PANEL_SPACING/SAFE_MARGIN。
- **交互契约**：容器 `pointer-events: none`、面板内 `auto`；面板分常驻/业务/临时三类，由业务页自行管理显隐。
- **响应式**：三档断点见本文 §5.4；断点判定只在 `useGCS`，组件消费 computed，禁止重复判定。
- **颜色体系**：全部 `--GCS-*` 变量（`shared/constants/colors.ts` 等）；渲染层颜色走 `LAYER_DEFAULTS`/调色板。

### 三.2 GCS 资产清单（审查定位用）

**布局常量**（`shared/layout/config.ts`）：

- CELL_PIXEL = 80（档位：≥1920 → 90 / ≥960 → 80 / <960 → 70）
- GAP = 10 / PANEL_SPACING = 20 / SAFE_MARGIN = 20 / GRID_SIZE = 100
- LAYOUT_DESKTOP_MIN = 960 / LAYOUT_DRAWER_MIN = 640

**布局 composable**（`shared/layout/useGCS.ts`）：

- useGCS()：showPanels / showTopArea / navCompact / cellPixel / panelPosition（模块级单例 + resize 150ms 防抖）

**标准组件**（`core/layout/components/`）：

- GCSPanel：面板容器（w/h/anchor/offset，pointer-events 契约）
- GCSButton：悬浮按钮（定位 + 图标）
- NavButton：导航按钮
- BottomNavBar：底部导航（三档：7 键 / 3 键）
- MobileDrawer：抽屉容器（<960px 渲染）
- TitlePanel：标题面板
- DebugToggle / GCSDebugOverlay：调试开关与覆盖层

**颜色语义分组**（`shared/constants/colors.ts`）：

- functional：primary / success / warning / danger / info
- text：primary / secondary / muted / placeholder / disabled
- bg：page / panel / elevated / hover / active / selected
- border：default / subtle / strong
- chart：c1-c6（多分类色板）
- overlay：遮罩 / 聚焦环 / 暗色专属

**已知违约点**（状态以台账为准，此处仅审查定位）：

- `style.css:102` / `:108`：硬编码色值
- 历史已修：`Gcs`/`gcs` 大小写违规（2026-07-30 全量改正）
- 历史已修：MobileDrawer 断点注释漂移（768 vs 960）

### 三.3 GCS 标准组件规格书（审查对照基准）

> 每个标准组件的职责、样式契约、常见误用。审查时以本表为基准判断"复用 vs 伪实现"（专项7 指标 3.2）。

**GCSPanel（面板容器）**

- **职责**：GIS 浮动面板的容器——尺寸（Cell 整数倍）+ 锚点定位 + 内容插槽。
- **Props**：`w`（Cell 宽）/ `h`（Cell 高）/ `anchor`（top-left/top-right/bottom-center 等）/ `offsetX` / `offsetY` / `title?`。
- **样式契约**：背景 `var(--GCS-bg-panel)`；圆角 `var(--GCS-radius-lg)`；阴影 `var(--GCS-elevation-2)`；`pointer-events: none` 容器 + `:deep(.GCS-panel) { pointer-events: auto }`。
- **常见误用**：业务组件手写同结构面板（伪实现）；`w` 传非整数（`w="3.5"` 绕过网格）；面板内再套 absolute 定位（应使用锚点 offset）。

**GCSButton（悬浮按钮）**

- **职责**：地图上的圆形悬浮操作按钮（定位 + 图标 + 点击）。
- **样式契约**：圆形（radius pill）；背景 `var(--GCS-bg-elevated)`；图标 `currentColor`；hover/active 状态走 token；z-index 走层级常量。
- **常见误用**：手写圆形按钮（重复实现）；按钮内 SVG fill 写死；多个悬浮按钮手工排布（应组件内管理间距）。

**NavButton（导航按钮）**

- **职责**：顶部/底部导航的按钮（label + icon + active 态）。
- **样式契约**：active 态 `var(--GCS-primary)` 高亮；禁用态灰化；尺寸 token。
- **常见误用**：业务页自绘导航按钮（active 态各写各的）。

**BottomNavBar（底部导航）**

- **职责**：底部导航栏，三档行为（≥960 隐藏 / 640-959 7 键含菜单 / <640 3 键紧凑）。
- **样式契约**：背景 `var(--GCS-bg-panel)`；顶部 border `var(--GCS-border-subtle)`；z-index 层级常量。
- **常见误用**：业务组件自绘底部导航；在组件内重复判定断点（应消费 useGCS navCompact/showPanels）。

**MobileDrawer（抽屉容器）**

- **职责**：档位 2/3 下面板收进抽屉（<960px 渲染）。
- **样式契约**：宽度 token；滑入动画（duration-medium + ease）；遮罩 `var(--GCS-overlay)`；z-index 高于面板低于 modal。
- **常见误用**：断点判断漂移（注释与代码不一致——历史事故）；抽屉内面板脱离 GCS 布局。

**TitlePanel（标题面板）**

- **职责**：顶部标题/城市切换区域（showTopArea 控制）。
- **样式契约**：字号 `var(--GCS-font-20)`；text-primary；背景透明或 panel。
- **常见误用**：标题字号散落（页面各自定义标题样式）。

**DebugToggle / GCSDebugOverlay（调试开关与覆盖层）**

- **职责**：开发调试（网格叠加层、开关）。
- **样式契约**：仅 dev 构建加载；z-index 最高层（调试覆盖）。
- **常见误用**：生产构建误打包；覆盖层 z-index 污染正常层级。

### 三.4 组件复用判定流程（对应专项7 指标 3.2）

```
发现疑似伪实现（手写面板/按钮/导航）
  → 对照 §三.3 规格书：职责是否与标准组件重叠？
  → 是 → 检查能否直接复用（props 是否覆盖需求）
  → 能 → 迁移复用，伪实现删除
  → 不能 → 评估：扩展标准组件（加 props）还是新组件立项（判定流程见本文 §1.4）
  → 新组件 → 进 core/layout/components/ 或 shared/components/
```

### 三.5 Token 变更 SOP（S7-10 定）

1. **改前先查**：新增/改色前 `grep -rn -- '--GCS-' frontend/src` 确认现有引用与同值 token（防重复与撞名）。
2. **改名留映射**：token 改名必须留映射注释（旧名 → 新名）至少一个版本，同步更新 §三.2 资产清单。
3. **双份同步**：`shared/constants/colors.ts` 与 `style.css` 同值色（如 #409eff）属渲染/DOM 双通道，改一边必须同步另一边（S7-01/11 绑定规则）。
4. **删除先验**：删 token 前跑 `node tools/token-stats.mjs` 确认无真实引用；仅注释提及视为未消费。
5. **验收**：`npm run stylelint` + `node tools/token-stats.mjs` 死 token ≤5%、硬编码清零后合入。
