## §2 任务流程细则（原 AGENTS §三）

**A 修 bug**
定位 → 找**根因**（自检同族能否一次修完）→ 查 K1 对应节 → 最小改动 → 验证 → 提交

**B 新增功能/模块**
读 C1 §4 + K2 §6 → **列出本次要同步改的全部位置**（清单化，禁止靠记忆）→ 先写两侧类型/契约 → 实现 → 补测试（含阳性对照）→ 查守护规则是否随之扩张 → 验证 → 提交

**C 审查/审计**
全文读不抽样 → 每条含 `file:line` + 证据 + 触发条件 + 失效机理 + 后果 + **作废条件（"若 X 成立则本条作废"）** + 等级 → 与前轮副本去重（禁止复读）→ **写不出可复跑钩子的结论不进问题册** → 按「审查体系约定 §4.1」归并后才立编号 → 六节交付（标准库见 `docs/根基文档/审查体系专项/审查体系约定.md`）
**交付前自检**：`node tools/audit-kit/verify-window.mjs <件>` —— §0 必须是可执行 bash 围栏、每条命令紧跟 `# 期望:`；抽不出块或期望对不上，按**未交付**退回（不是"部分通过"），契约见 `tools/audit-kit/README.md`。四轮审查里 5 份真实件有 4 份栽在这（含一份当时被评为"最可复算"的）——窗口自述不是交付凭据，复算才是。

**C′ 复查"修完了没"**
派回原窗，**只准看四类**（承重闭合／影响面内新引入／同批落地纪律／规则候选取证），其余一行进待立案池；每条新发现必须打归属标签（`引入`｜`收口不足`｜`取证漏`｜`流程`），**承重闭合必须给"删掉修复会不会红"的实跑输出，不得只读代码形态**；批末算膨胀率决定是否还能继续下发新工单（见本文「工单与膨胀率」）。

**D 部署/运维**
先确认对镜像/env/端口/探针/日志的影响 → 按本文「部署与运维」节与 `docs/archive/部署历程记录-2026-08-09.md` 执行 → 变更前后都有可验证状态 → 不动生产数据

**E 文档/台账**
读 `docs/文档地图.md` 定位置 → 规则进契约、状态进台账 → 台账 4 列、编号不复用 → 归并/重排必出「旧编号 → 新编号」映射

## §3 记录义务（原 AGENTS §六）

- commit 格式 **Conventional Commits**（由 `.husky/commit-msg` 的 commitlint 强制，配置 `@commitlint/config-conventional`）
  - 形式 `type: 中文说明`；type 取 `feat｜fix｜docs｜chore｜refactor｜perf｜test｜ci｜build｜style｜revert`
  - **禁 `type(scope):` 括号写法**——口径依据 K2 §1.6（scope 不值得单独突出时强制括号很难看）
  - 正文写清「做了什么 + 为什么」；标题 ≤100 字符、不以句号结尾
  - **正文每行 ≤100 字符**（commitlint `body-max-line-length` 实测会拦）。因此贴 stdout 必须**折行或截断**并注明"…（截断，全文见 <路径>）"；长证据落 `.local/` 并在正文指路，**不要为了提交而 `--no-verify`**
  - 例：`fix: 穷尽派生 TASK_DOMAINS，修复 forecast-map 域恒 400`
- **每修一项即提交**；禁 squash；禁 `--no-verify` / `--no-gpg-sign`
  - **一单元一笔，一批 ≤5 个修复单元**。混合多单元的大提交按"未结算"处理——实测一批 17 个单元混提，最终整条可判闭的只有 2 个；一笔 8 单元/46 文件混提 ⇒ 要退只能整块退，退了同时丢掉另外三条。
- **修 + 测 + 台账回写 = 同一笔提交**。三者分笔是本项目坏钩子（15 例）、"测件根本没进仓库"、和"代码已修但账面写'尚未尝试'"的唯一成因。
- **commit 标题只允许声明 diff 里真有的东西。** 写了"收敛单一事实源"却没动那一侧的文件 = 过度宣称；危害不是文字不准，是**下一个人据此不去查那处真没锁的地方**。复查时按 `git show --stat` 对账。
- 修复完：从 `待解决问题.md` 移入 `已解决问题.md`（按原编号），移条必须带**依据（产物级）+ 它在什么情况下失效**。
- 新发现：先归并筛选，再分配编号。禁止给症状级问题编号。
- 注释只写「为什么」；不写行号、清单、"已 X"。
- **废弃要成文**：任何"读侧不再消费"的字段/端点/分支，收口的同笔里必须留一行明文声明 + 一条能红守卫。不声明的废弃 = 等着被下一个人当权威源读回去的活字段。
- **范围和口径的决定也要有权威源**：删某模块、排除某目录、某类条目的判据口径，必须写进 C1/C2 或 K1/K4 或台账头部，不得只活在某一轮审件里——否则后续每一轮都会继续往已排除的地方派单。

## §4 交付前自查（原 AGENTS §八；**打勾无效，必须挂产物**）

> 旧版这里是 10 个复选框。实测结论：复选框被逐条打勾的那一批（09-22，61 笔提交）交工时**整批 0 条带判据输出、台账 0 记账、4 处过度宣称**——打勾不能证伪，所以改成每格挂一个可核对的产物。

| 格子                           | 必须挂的产物                                                                                |
| ------------------------------ | ------------------------------------------------------------------------------------------- |
| 读了 C1/C2 与 K1 对应节        | 写出实际读了哪几份、哪几行，并列出**抄到的已有编号**（接手不改号）                          |
| 只做要求的事，没顺手重构       | `git diff --stat` 逐文件对账，超出范围的须点名并说明为什么必要                              |
| 跨端/跨层两侧都改且有断言      | 两侧文件路径 + 那条跨边界断言的 `file:line` + 变异四式 stdout                               |
| 新增守卫/清理/schema 有调用点  | 调用点 `file:line`，或一条"直调它仍测不到接线"的反省（若是，按 `AGENTS.md` §七-2 判未完成） |
| 新增监听/定时器/请求有配对注销 | 注册与注销两处 `file:line`，且同作用域                                                      |
| 注释的"已 X"有断言、路径存在   | 该断言的 `file:line`；被引用路径逐条 `test -e` 的实测输出                                   |
| 验证跑了                       | 命令原文 + 实际 stdout（**贴在 commit body 里**，不只在对话里）                             |
| 失败项归属已说明               | 本次引入 / 既有 flake / 环境问题，三选一并给证据；"红得对但没有证据通道"要写出来            |
| commit message 写清根因        | 标题与 `git show --stat` 对得上；不声明 diff 里没有的东西                                   |
| 台账已更新、编号未复用         | 该行的新状态词 + 新钩子，并**当场跑一遍新钩子**贴输出                                       |
| **影响面自陈（E3）**           | 本次改动新造的面清单；**没有新面也要显式写"无"并给判据**                                    |
| 落地的提交可指认               | 报出 SHA；工作树必须干净（`git status --porcelain` 空）                                     |

## **做不到任何一格：不许提交，也不许静默跳过——在 commit body 或台账里写一行"未做 + 原因 + 谁能补"。上一轮最贵的就是"默默跳过"。**

## §5 工单与膨胀率（原 AGENTS §十二；防"修一个冒出无数个"）

- **工单不是报告**：每条必须给「修前钩子（期望＝问题仍在）→ 修后判据（具体输出）→ 必须附的阳性对照 → 碰哪些文件 → 谁卡在谁前面」，**件首要有一个 bash 块能在 5 分钟内核对整份工单**。施修方开工前先整块跑一遍，确认每条都报"问题仍在"。
- **归属标签四态**：`引入`（阻断，**必须在同一条目内消解，不许另立"待修"号**——分开修必然再来一次）｜`收口不足`（阻断，扩同一条目范围一次做完）｜`取证漏`（不阻断，进池）｜`流程`（不阻断，进池）。**汇总方判据写窄造成的 `收口不足` 记在汇总方账上，不算施修方引入。**
- **膨胀率 =（引入 + 收口不足）÷ 本轮修复条目数**：`>1.0` 停止下发新工单、先回退修法；`>1.5` 判本轮修复整体不合格、回滚重做；**同一条目产生 ≥2 个 `引入`** ⇒ 判**修法错误**（回退改法，不是继续加补丁）；**同一形态在不同条目第 3 次出现** ⇒ 停止逐条修，升级为一条门禁规则。字面口径与去重后口径**两个数并列报**，不挑对自己有利的那个。
- **关闭分级**（治"账永远红着"）：**✔闭** = 现象在 HEAD 上不存在 **且**有能变红的执行体；**◐半修** = 现象改了但判据或回归闸缺一；**✘未修** = 现场原样。**只有 ✔闭 才准移条**；不许用"降级验收标准"来提高关闭率——尺子不动，削范围。
- **待立案池是缓冲区不是垃圾桶**：批末统一归并，归并到在册号优先，独立且要改不同文件的才新开号，且必出「旧编号 → 新编号」映射。

## §6 构建与性能（原 03 §二）

### 6.1 分包策略（设计意图）

- `manualChunks` 按依赖来源分组：vue-vendor / openlayers / cesium / echarts / ui-vendor。
- 目的不是"切得越细越好"：① 高频业务代码与稳定依赖分离，最大化缓存命中；② 大体积依赖独立成块便于按需加载。
- 具体配置以 `frontend/vite.config.js` 为准（本文档不抄）。

### 6.2 懒加载架构（原则）

| 模块           | 策略                                   | 意图                              |
| -------------- | -------------------------------------- | --------------------------------- |
| Cesium 库      | 构建时静态复制 + 运行时动态注入 script | MB 级主库不进首屏，仅切 3D 时加载 |
| CesiumRenderer | `await import()` 动态导入              | 2D-only 用户不下载 3D 渲染器      |
| ECharts        | 页面级异步化                           | 仅预测页加载                      |
| OpenLayers     | 首屏静态导入                           | 2D 地图是首屏核心                 |

判定标准：**是否首屏必需**。

## §7 部署与运维（原 03 §五）

### 7.1 当前部署形态

- 阿里云轻量应用服务器（1.6Gi 内存 / 40G 磁盘 / Ubuntu 24.04），Docker Compose **三容器**：`beibu-gulf-webgis`（nginx + 前端 dist）、`beibu-nest`（业务 API:3000）、`beibu-postgis`（PostGIS:5432）；镜像由 CI 构建推送 GHCR，服务器部署只 `pull`（不在服务器 build）。
- `beibu-gulf-webgis` 内 nginx（80/443）→ 前端 dist + 反代 `/nest-api`→`nest:3000`（`/api` 兼容重写同向）、`/static/` 直发静态、`/tianditu/` 天地图同源代理。
- 部署目录 `/opt/beibu-gulf/`（git 仓库 = CI 部署目标）：compose / Dockerfile / entrypoint / nginx.conf / .env / backend（data + static：dem、terrain）/ frontend / certs / scripts。
- 数据卷：backend/data、static/dem、static/terrain、certs 均为 volume，构建不覆盖。

### 7.2 自动化链路

- CI（GitHub Actions，8 job，job 名以 `.github/workflows/ci.yml` 为准）：changes →（audit / static-checks /
  frontend-tests / commit-discipline / backend-tests）→ build-push-images → deploy（仅 main：preflight →
  `git pull --ff-only` → `docker compose pull` → `docker compose up -d --remove-orphans`；服务器不 build）。
- 密钥走仓库 Secrets（TIANDITU_KEY / SERVER_SSH_KEY / SERVER_HOST / SERVER_USER）。

### 7.3 HTTPS 与证书

- Let's Encrypt + duckdns DNS-01，**自动续期**两条链路已验证：certbot.timer 每天检查（到期前 30 天自动续期）+ deploy hook 自动同步新证书到容器并 reload。
- 唯一前提：**duckdns token 不要动**。排查命令：`sudo systemctl list-timers | grep certbot`。

### 7.4 排雷要点

- 小内存机器：CI 增量构建没问题，全量 `--no-cache` 构建注意内存。
- 生产 3D 真地形依赖镜像内 dist 与 terrain volume 同步（历史教训：镜像旧 dist 导致 3D 无真地形）。
- 生产服务器禁做事项（含**禁「重置系统」**）见 §10.9；线上探测固定 `curl -k --noproxy '*'`。
- 详见台账中部署相关条目；历史部署历程见 `docs/archive/部署历程记录-2026-08-09.md` 与
  `docs/archive/排查-部署失败-2026-09-17.md`。

## §10 工作红线（原 03 §十一，全量承接）

> 本节是原 03 §十一 11 条的现行承接件（2026-10-05 更正：KP-095 目标由 K1 改为 K4，K1 未落内容）。
> 历史来历与实测代价的原文见 `docs/日志/快照/工作红线来历-源自旧03-2026-10-05.md`（日志层，只读）。

1. **git 历史与远端判据**：禁 squash / 重写历史；禁 `git rm`（删除走普通 delete）。大操作前
   `git bundle create` 备份，备份件只保留最新 1 份；删旧备份前必须证明其内容为 0（临时裸库 +
   `git fetch <bundle> +refs/*:refs/p/*` + `git cherry main <sha>` 数无上游等价补丁）。判远端只信
   `git ls-remote origin refs/heads/main`——本地 `origin/*` ref 曾据此误判，不可信。
2. **提交绕过禁令**：禁 `--no-verify` / `--no-gpg-sign`。钩子红到推不动 = 门禁缺陷：停下报错，
   不改道绕行（细则见 §3 与 AGENTS §5.5）。
3. **依赖与样式**：不新增 npm 依赖（作为决策项获批除外）；色值改动集中 `shared/constants/colors.ts`。
4. **改造面**：`core`/`shared`/`stores` 不可被 `business` 引用；business 模块结构 =
   页面 + `components` + `composables` + `constants`（K2 §六）。禁止跨文件重构——改动限定在任务面内，
   重构需单独立项。
5. **数据来源**：mock / 合成 / 未标记来源数据严禁入库；只接受合法来源 + 显式 source 标记
   （K1 §A8、B7/B8）。
6. **审计口径**：结论挂 `file:line` 实证；无法确认标「无法确认，需读 X」；判第三方库行为必须实跑或
   读源码；引用路径先核对存在（AGENTS §一）。
7. **本机测试入口**：前端 `npm test`；后端 `npm --prefix backend test`。端口等会漂移的环境细节以
   S3 §7 为准，不进本节（AGENTS §5.2）。
8. **push 流程**：环境无凭据时由用户在终端 `git push origin main`；pre-push 会跑双端 typecheck +
   `guard:v3` + 后端测试。不许因推送不便绕过任何门禁。
9. **生产服务器**：阿里云单机 + Docker Compose（规格见 §7.1）。**禁「重置系统」**——PG 数据卷会全丢；
   线上探测固定 `curl -k --noproxy '*'`（本机代理会伪造 502）。部署只拉镜像，不在服务器 build。
10. **Windows 中文编码**：写文件一律 UTF-8；提交信息用 `git commit -F <文件>`；Python 调用加
    `-X utf8`（PowerShell 5.1 默认 OEM 代码页，GBK 会把中文/符号打成 UnicodeEncodeError）。
11. **留痕**：架构性妥协打 `@arch-note`（K2 §1.3）；文档产出进 `docs/`，新增 tracked 文档需在
    `.gitignore` 逐份放行（C1 §6）。
