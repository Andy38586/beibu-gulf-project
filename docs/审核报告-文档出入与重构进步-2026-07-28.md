## 一、文档与代码的出入（按严重度排序）

### 🔴 严重（诚信 / 第一印象级）

**1. `README.md` 仍是老项目描述（P0 诚信雷，原样未修）**
- README 描述的是「港口选址分析平台」：BufferPage / OverlayPage、Bearer token、localStorage 持久化、方案管理、3 条路由、Vite 代理 `localhost:3000`。

- 附带的细节错误：
  - env 表写 `VITE_API_BASE` 默认 `http://localhost:3000/api`，代码实为 `import.meta.env.VITE_API_BASE || '/api'`（`useApiRequest.ts:72`），默认 `/api`（由 Vite 代理转发），并非完整 URL。

- 结论：面试报告 P0-1 已点名但未修。这是当前最该修的文档。

**2. "双通道认证（Cookie + Bearer）"是假文档（代码实为 Cookie-only）**
- `项目根基.md` §8.4、`API契约文档.md` §1.3 都写"JWT + HttpOnly Cookie 双通道，前端同时发 `credentials:'include'` 和 `Authorization: Bearer` header"。
- 实际代码：`useApiRequest.ts:103` 注释"认证统一通过 HttpOnly Cookie（credentials: 'include'），不发 Bearer header"，`:118` 仅 `credentials:'include'`，**全文件无任何 Bearer 发送逻辑**。
- 代码方向是对的（对应 D04 决策：Cookie-only 防 XSS）。**应改文档，不应改代码**——把"双通道"改为"HttpOnly Cookie 单通道（Bearer 已废弃）"。
