# C2 · 质量不变量与根因守则

> **层级**：宪法（无时效、罕改、改动需用户批准）
> **定位**：把"这个项目里什么叫质量好"压缩成六条不变量 + 四条根因守则（RC1–RC4）+ 判据四要求。所有规则、守卫、工单都从这里派生。
> **拥有的权威事实**：六不变量 / RC1–RC4 / 判据四要求 / RC 计数与升级规则。
> **读者**：所有 agent 与维护者；写规则、立门禁、开工单、判"修完了没"的人。
> **何时读**：B（新功能）、C/C′（审查/复查）、F（机制与门禁变更）之前；任何"要不要再立一条规则"的取舍。
> **何时回写**：不变量修订（需用户批准）。细则进 K1/K4，状态进台账；本文不装案例。
> **最近复核**：2026-10-05

## §1 六条质量不变量

| #   | 不变量         | 一句话判据（违反即不合格）                                                             | 机器承接体（示例）                                           |
| --- | -------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| 1   | **单一数据源** | 同一事实（名单/阈值/枚举/路径/域清单/错误码）只允许一处权威，其余必须派生              | `doc-map-check` facts[]；`doc-numbers`；跨端 `types:check`   |
| 2   | **闭环**       | 有注册必有注销、有写入必有消费、有多点必一次收全；半覆盖的收口按未修计                 | `guard:v3` 生命周期类；K1 §A/§C；审查 C′ 的"承重闭合"        |
| 3   | **守恒**       | 单位/口径/量纲在产生处与消费处都声明；缺失即缺失，不得用 `0`/`''`/伪造字段填孔         | K1 §B（B4/B6/B7/B8/B9）；`anchor-check`                      |
| 4   | **对称**       | 双端/双引擎/双实现的同一条规则强度一致，禁止一侧裸取、一侧可选链                       | K1 §A/§E；`csp-sync`；两侧 `typecheck` + 跨边界断言          |
| 5   | **可观测**     | 生产失败必须可观测且与成功可分；`catch` 不得吞错误；兜底必须留痕                       | K1 §D；台账行内钩子的 stdout 口径；`guard:mutation` 的红样   |
| 6   | **受控**       | 门禁/脚本/agent 的写入面受登记与审批约束：新门禁先登记入口与到期、权威源改动须用户批准 | 停问清单（`AGENTS.md` §四）；`run-all` SEPARATELY_RUN 登记表 |

六条不变量是**判据的判据**：新立一条规则/守卫前，先回答它服务哪条不变量；答不出就不立。

## §2 四条根因守则（RC1–RC4）

| 代号 | 根因                   | 形态                                                                      | 治法（优先机器判据，其次流程）                                         |
| ---- | ---------------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| RC1  | **无权威源的多份副本** | 同一事实 ≥2 处手抄；"改一处 + 注释提醒同步"；半覆盖守卫                   | 指定权威源并派生 + 一条"改一处必红"的守卫（K1 F9）                     |
| RC2  | **判据不红**           | 门禁/断言从未红过；判据只认一种记法；判据输入不可控（脏件/历史件/未拉取） | 变异四式（AGENTS §5.3）；输入受版本控制；新门禁带红样才能入库          |
| RC3  | **通过不带失效条件**   | 结论只有"已修/已绿"，没写什么情况下会被推翻；负结果无阳性对照             | 每条结论=依据（产物级）+失效条件；负结果附同形态能命中的对照（K1 F10） |
| RC4  | **改动不带影响面自陈** | 修 A 用 B、B 成新问题；新守卫自己变成下一次合法改动的绊线                 | 每次改动自陈新造出的面，每条附能红判据（AGENTS §5.1 E3）               |

**计数与升级规则**（每轮审查收口必答）：

- 本轮新长出的条目里，属于 RC1–RC4 的各有几条；为 0 ⇒ 守则生效。
- **>0 且同一 RC 的化身数连续两轮不降** ⇒ 不是审得不够细，是那条守则没进门禁：**改门禁或改协议，不要再加审查窗口**。
- 同一形态第 3 次出现 ⇒ 停止逐条修，升级为一条门禁规则（`AGENTS.md` §十）。

## §3 判据四要求

任何门禁、守卫、断言、台账行内钩子，必须同时满足：

1. **能红**——存在一条让它变红的样本，且红样入库（从未红过的门禁 = 不存在）；变异四式（删字面/停用/等价重构/同义改写违约）的 stdout 进 commit body。
2. **名实一致**——标题/注释宣称什么就断言什么；宣称"全量"就必须由扫描派生覆盖面，不得硬编码数组当全覆盖；被取代的旧载体必须同笔标废弃或删除。
3. **输入受控**——判据能读的只有：入库文件、本次运行自产的结果、明确声明过的运行态。禁止读工作树脏件、历史结果文件、gitignored 路径、未拉取的 git 历史；外部 CLI 不可用时记 SKIPPED，不得判红也不得判绿。
4. **带失效条件**——每条"通过/已修/达标"必须同时写「依据（产物级）+ 什么情况下它失效」；夹具不得与生产输入取同值（否则等于零测试）。
