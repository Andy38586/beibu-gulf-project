## 三、五维度详解

### 3.1 技术栈健康度 — 42/50 ⭐⭐⭐⭐

**加分项**
- TS `strict: true` + `noImplicitAny` + `noUnusedLocals/Parameters` 全开（`frontend/tsconfig.app.json:22-26`），类型纪律过硬。
- 状态层规范：8 个 Pinia store + 1 个 `createPersistedState` 工厂，职责清晰。
- 路径别名 `@/*` 统一，依赖方向（core/shared → business 禁引）有约束。

**扣分项 / 风险**
- **领先版本过激**：Vite 8、TypeScript 6、vue-tsc 3 均为发布不久的大版本。生态插件（unplugin-*、vite-plugin-cesium）需紧跟适配，存在隐性兼容成本。当前构建已出现 `@vueuse/core` 的 `INVALID_ANNOTATION` 警告（第三方库 pure 注释位置问题，不影响产物，但提示工具链前沿）。
- **类型覆盖缺口**：`allowJs:true` + `checkJs:false`（`tsconfig.app.json:18-19`），导致 `config.js / useGCS.js / CesiumRenderer.js / renderers/index.js / OLRenderer.js / router/index.js` 共 6 个核心 `.js` 不受类型保护（已知债 D-6）。

### 3.2 架构设计模式 — 43/50 ⭐⭐⭐⭐

**加分项（本次重点核查的登录/个人中心）**
- **全局登录态为真·单例**：`useApiRequest.ts:24,38` 的 `token`(ref) 与 `isAuthenticated`(computed) 均为**模块级单例**；`useAuth.ts:47` 的 `user` 亦为模块级 `ref`；三者跨组件共享，登录即全局生效——`v-if="!user"` 切换（`ProfilePage.vue:269`）正是你要的"全局变化驱动 UI"。
- **启动恢复链完整**：`App.vue:112` `onMounted` 调 `restoreAuth()`，始终以 HttpOnly Cookie 为权威（`/auth/me` 校验），与后端 `backend/routes/auth.js:10` 的 `GET /me` + `authenticate` 闭环。
- **后端鉴权真实存在**：`plans.js`、`siteAnalysis.js:8`、`floodAnalysis.js:54` 均挂 `authenticate` 中间件；`middleware/auth.js` 强制 `JWT_SECRET≥32` 位、缺失即 FATAL。前端全局态不是摆设。
- **Adapter/Mock 隔离**、**BusinessLayerManager 写入/读取双端**、**GCS 网格布局引擎**均为良好解耦实践。

**扣分项 / 注意**
- `useAuth` 在 composable 顶层调用 `onMounted/onUnmounted`（`useAuth.ts:194-207`），意味着它**只能在组件 setup 内调用**；若未来在路由守卫/工具函数里误用会抛错。建议把 storage 监听收敛到 `App.vue` 单点注册。
- `profileStore`（选址方案选中态）与 `useAuth.user`（登录态）命名相近但职责不同，新人易混，建议注释明确边界。

### 3.3 工程化成熟度 — 33/50 ⭐⭐⭐

**加分项**
- 构建：Vite 8，实测 4.62s 完成 2571 模块；`useAuth`/`echarts`/`Cesium` 均独立分包，首屏不含重型懒加载块。
- 质量门禁：ESLint 10 + Prettier + Husky + lint-staged + dependency-cruiser 齐备。
- 测试：161 测试绿，分层（单元/集成）已有基础。

**🔴 P0 失分点（部署面）— 详见第四节**
- `.dockerignore` **未排除 `.env*`** → `backend/.env`（含 JWT_SECRET、NODE_ENV=development）被 `Dockerfile` `COPY backend/ ./` 烤入生产镜像。
- `docker-compose.yml` **无 `environment` / `env_file` 注入**，容器直接跑烤进去的 dev 配置。
- 后果双重：① 密钥随镜像泄露；② 容器内 `NODE_ENV=development` → `backend/app.js:81` 在生产返回 `err.message` 明文错误，且 `auth.js` 强度校验降级为开发态。

**扣分项（均为 P3，非阻塞）**
- `dist/stats.html` 每次 `vite build` 无条件生成（rollup-plugin-visualizer 无 `ANALYZE` 守卫），随产物部署浪费 ~1.3MB。

- 6 个 `.js` 无类型保护（D-6，同 3.1）。

### 3.5 综合评分 — 39.5/50 ⭐⭐⭐⭐

架构与代码质量已达实习/校招作品里相当靠前的水平；唯一把整体拉到"四星下半"的是**部署安全面的一处 P0**。该 P0 修复成本低、收益极高，修完后综合可稳居 42+。
