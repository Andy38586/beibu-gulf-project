## 四、高程与参考系要求（核心节，逐条落实）

### 4.1 平面基准

CGCS2000 / WGS84 经纬度。项目口径：库内 EPSG:4490 存储、源数据 4326 直接赋值
（中国区域厘米级一致，见 `docs/v3-施工手册.md` 坐标系口径节）。两者不作区分。

### 4.2 高程基准（⚠ 最重要的一条）

**必须采样与 Web 端 CTB 地形同一 DEM、同一处理链路的产物**——即
`tools/dem-pipeline` 的管线输出（01 镶嵌 GLO-30 → 02 填洼 → 03 重投影 4326；
`07-heightmap-reslice` 切片用的就是这份 DEM）。

- ❌ **不要**自行下载新 DEM、不要做 EGM2008↔椭球高的自行换算——那会引入第二套高程
  口径（04-B3：半覆盖的口径比没有更危险）。
- ✅ **要**：与 `07-heightmap-reslice.ps1` 的**输入 DEM 文件**（处理链末端的 4326 栅格）
  逐顶点采样。同源 ⇒ 同口径 ⇒ 模型贴住 Cesium 里的地形。
- GLO-30 原始高程为 EGM2008 正高口径；CTB 切片如何解释该口径以管线实现为准——
  **执行者不需要关心，采样同源文件即自动一致**。

### 4.3 分辨率与采样方式

- DEM 分辨率 30m（GLO-30）。逐顶点**双线性插值**采样。
- 同一结构平台（闸室底板、坝顶、场地）内的顶点**共享同一采样值**（取平台中心点采样），
  避免平台内出现 DEM 噪声锯齿。
- 采样点距 < DEM 网格距（30m）时允许多点共值——这是特性不是缺陷。

### 4.4 精度与验收容差

- GLO-30 标称垂直精度 ≤4m（LE90），丘陵山区实测放宽；叠加切片重采样误差。
- **验收容差：模型底面与地形高差 ∈ [−5m（埋）, +2m（浮）]**，≥5 个采样点全部达标。
- **宁埋勿浮**：底面统一再下压 2m 缓冲（浮空的模型比埋入的模型难看得多——
  与项目"宁可高估"的口径一致）。

### 4.5 设计高度保留

闸墙、闸门、墩柱等**结构顶点** = 所在位置 DEM 高程 + 模型内部相对高度。
即：只把模型的"基准面"贴到地形，结构自身的几何设计（闸室深度、墙高等）原样保留。

### 4.6 已知局限（诚实标注，答辩口径）

- GLO-30 是工程前地表；天地图正射是 2026 施工后地表——枢纽区"模型贴地形但不贴影像"
  属预期，口径沿用数据清单的"规划前期宏观适宜性评价"。
- 闸室设计水位未建模（需枢纽设计资料），水面暂按几何位置，标注"待校准"。

## 五、几何与输出要求

1. **文件名与结构不变**：`madao-low.glb`、`madao-z1-terrain.glb` 等 31 个内容文件
   同名替换——`tools/v3-guard` 的 tiles3d-check 守卫断言 31 内容节点，改名即红。
2. **transform 约定不变**：root.transform 沿用现有矩阵（本地 z-up + 锚点平移 +
   per-vertex ellipsoid drop 与 corridor 同法）；定位偏差通过重烘顶点坐标解决，
   **不要**靠改 transform 硬挪。
3. **逐顶点椭球降落**：与 corridor 相同的处理——顶点高度写入 WGS84 椭球高
   （= 4.2 采样高程按管线同款口径），保证与 CTB 地形逐点吻合。

## 六、验收标准（交付后由 ZCode 会话执行，全部可复跑）

1. 每组瓦片 `statistics.numberOfCommands > 0` 且 `geometryByteLength > 0`（防静默零渲染）。
2. ≥5 个采样点：模型底面与 `scene.globe.getHeight` 高差 ∈ [−5m, +2m]。
3. 斜视角（pitch −30°）目检：无悬浮断层、无穿模断裂。
4. `npm run guard:v3` 全绿（tiles3d-check 31 节点断言过）。
5. 探查方法与脚本要点：`.local/calib-3dtiles-2026-09-26.md` §四
   （DevTools 桥 → pinia → mapStore.currentRenderer → statistics / getHeight）。
