# 故障复盘:生产3D真地形无起伏(2026-08-10)

> **定位**:生产 3D 真地形"贴图无起伏"故障的完整复盘(现象/排查链/根因/修复/教训)。
> **现象一句话**:服务器 3D 模式下地形是"贴图"(无 z 起伏),本地 dev 正常,手机正常。
> **根因一句话**:nginx 对 `layer.json` 误标 `Content-Encoding: gzip`(内容未压缩却声明 gzip)→ 浏览器 `ERR_CONTENT_DECODING_FAILED` → CesiumTerrainProvider 加载失败 → 整个真地形静默失效。
> **关联**:台账已解决 `z054`(本故障);`a025`(真地形实现)、`z050`(镜像旧 dist 无瓦片方案)为同主题历史条目。

---

## 一、现象与影响

- **现象**：生产 `https://112.74.32.206` 3D 模式（Cesium）地形完全平坦；2D 模式（OL）本就是 hillshade 贴图（设计如此）。
- **干扰项**：本地 dev 3D 有起伏、手机 3D 有起伏、IP 直连有起伏——**同一份代码、同一批瓦片**，唯独生产浏览器侧平。
- **影响**：真 3D 地形（DEM 金字塔瓦片方案）在生产从未生效过——上线时即存在，被"贴图"表象掩盖。

## 三、根因

`nginx.conf` 与 `docker-entrypoint.sh`（https.conf 模板）中 `/static/terrain/` location：

```nginx
location /static/terrain/ {
    alias /app/backend/static/terrain/;
    add_header Cache-Control "public";
    add_header Content-Encoding gzip;   # ← 无条件对所有响应加 gzip 头
}
```

- **设计意图**：`.terrain` 瓦片本身是 gzip 压缩流（CTB 输出），nginx 直发需补 `Content-Encoding: gzip` 供 Cesium 解压（2026-08-09 修 `RangeError: Invalid typed array length` 时的方案）。
- **副作用**：`add_header` 无条件生效，**`layer.json`（普通 JSON）也被声明 gzip**。当请求**不带** `Accept-Encoding: gzip` 时 nginx 不压缩内容，但头仍声明 gzip → 浏览器按 gzip 解码普通 JSON → `ERR_CONTENT_DECODING_FAILED` → `CesiumTerrainProvider.fromUrl` 加载失败（Cesium 吞掉异常，仅 console warn）→ **真地形整体静默降级为椭球面**。
- **为什么本地正常**：本地 dev 的 `/static/` 由 Express 服务，后端只对 `.terrain` 加 gzip 头、layer.json 原样返回。
- **为什么之前"筛 terrain 全 200"被骗**：`layer.json` 200 但不代表解析成功——**HTTP 200 ≠ 内容可用**；且早期页面有缓存，瓦片 200 是缓存命中，掩盖了 provider 根本没工作的事实。

## 四、修复（commit `2f55a3f`）

gzip 头**只对 `.terrain` 生效**（嵌套正则 location；内层需重声明 Cache-Control，add_header 继承中断）：

```nginx
location /static/terrain/ {
    alias /app/backend/static/terrain/;
    expires 30d;
    add_header Cache-Control "public";
    location ~ \.terrain$ {
        add_header Cache-Control "public";
        add_header Content-Encoding gzip;
    }
}
```

- `nginx.conf`（HTTP 分支）与 `docker-entrypoint.sh`（https.conf 模板，HTTPS 分支）**两处同步**——2026-08-09 部署教训："HTTP/HTTPS 两套配置同步维护"。
- 部署验证：`curl -sI .../layer.json | grep -i content-encoding` 无输出（不再误标）；`.terrain` 仍有 `Content-Encoding: gzip`。

## 五、教训（面试可用）

1. **HTTP 200 ≠ 内容可用**：`ERR_CONTENT_DECODING_FAILED` 这类"解码失败"比 4xx/5xx 更隐蔽——响应头与内容不一致是 nginx 配置类故障的典型形态，先查响应头。
2. **add_header 是"无条件"的**：nginx 的 `add_header` 对匹配 location 的**所有**响应生效，与 `gzip` 模块自动压缩相互独立——**手动声明编码头时务必确认与内容一致**。
3. **"本地正常"是强线索**：同一代码/数据在 dev 与生产行为不同 → 差异几乎必然在**部署层**（nginx/环境/数据卷），优先对比响应头而非代码。
4. **静默降级的双刃剑**：`_setupTerrain` 失败静默降级（保持椭球面）是健壮性设计，但生产无日志可见性（logger.debug 生产静默）导致故障无感知——排查时靠浏览器 Console 的 Cesium warn 定位。
5. **缓存会掩盖故障**：`max-age=30d` 的瓦片缓存让早期验证"全 200"，误导排查方向——**验证故障修复必须用无痕窗口/强刷**。
