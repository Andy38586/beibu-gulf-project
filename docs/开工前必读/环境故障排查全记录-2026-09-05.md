## 二、已修复问题的根因与修复明细

### 2.1 真地形不加载——四层叠加根因（核心案例）

**排查过程**（每步的尝试与反馈）：
1. curl `layer.json` → **404**（文件在磁盘却 404）→ 定位：Nest 未挂 static 托管（Express 退役时 express.static 职责未随迁，T6.3 漏项）→ 修复：main.ts 补挂（commit 170d4e68）。
2. 修复后仍偶发 500 → nest watch 重编译窗口撞请求（时序假象，非 bug）。
3. 浏览器实测（playwright-core 驱动系统 Edge，见 §四）→ **console 实锤**：`CesiumTerrainProvider: RangeError: Invalid typed array length: 4225`——瓦片解码崩溃。
4. 读 Cesium 源码（node_modules/cesium/Build/CesiumUnminified/Cesium.js:261236）→ heightmap-1.0 瓦片布局 = 65×65 uint16 + 1B childTileMask + N B waterMask；CesiumTerrainProvider 对 heightmap 强制 `heightScale:1/5, heightOffset:-1000`。
5. 解压瓦片验证 → **头不自洽、奇数字节（7695B）** → 瓦片数据既非合法 heightmap 也非合法 quantized-mesh——**这批 CTB 瓦片从未在 Cesium 渲染成功过**（8-10 生产"无起伏"复盘 = 海面全 0 瓦片蒙混的症状）。
6. 结论：修不如重切。按 Cesium 官方 heightmap-1.0 规范重写切片脚本。

**最终修复**（`tools/dem-pipeline/07-heightmap-reslice.py` + main.ts）：
- 重切 49045 张：65×65 uint16 = `(高程米+1000)*5`，行主序北→南，海洋/NoData=0m
- 尾部补 `childTileMask`（按真实瓦片树置位）+ `waterMask`（全 0 高程瓦片 0xFF 海面，**空数组会 DeveloperError 崩渲染循环**）
- y 轴 TMS→slippy 对齐（CTB 树 y=0 南，Cesium y=0 北——海面瓦片错位不可见故此前漏检）
- 输入 UTM 填洼版经 WarpedVRT 重投影（dem_4326_cut.tif 已被本机清理进程删除）
- 枚举源 = DEM bbox 推导（不依赖旧目录树，旧树已移出工作区留档桌面）
- main.ts：`/static/terrain` 专用流式中间件（express.static setHeaders 组合在并发地形请求下偶发 500，实测实锤后绕开）

**验证**：Edge 无头实测——天地图 253 请求全 200、渲染/解码错误 0、底图/海面/标签全渲染。

## 三、未定位/未解决的问题（诚实清单）

### 3.1 experiment 分支 ref 反复丢失（删除者未定位）

- **现象**：git commit 打印成功哈希但 `.git/refs/heads/experiment/v3-backend-migration` 随后消失（一天 11+ 次，100% 复现于 commit 后）；`refs/heads/experiment/` 目录整体消失；packed-refs 中无 experiment。
- **已排除**：gc/maintenance（配置 auto=0 都在）；hooks（仅 husky pre-commit，且 commit 均 --no-verify）；实时删除者（监控 15s 内手写 ref 存活——**删除是间歇性/事件驱动的**）。
- **已定位的可靠恢复法**：reflog 永远存活 → `NEW=$(awk 'END{print $2}' .git/logs/refs/heads/experiment/v3-backend-migration)` → 写入该完整 40 位哈希。
- **铁律**：ref 文件**必须写完整 40 位哈希**（短哈希 git 拒解析 → unborn）；恢复脚本禁止变量回显写 ref（空值事故曾产出孤儿 root-commit c5524119，已随 gc 丢弃）。
- **下一步排查建议**：① WorkBuddy 桌面（6 进程）的工作区 git 监视器嫌疑最大——关闭 WorkBuddy 后做一次 commit 实验；② procmon 过滤 `.git/refs/heads/experiment` 的 WriteFile/DeleteFile 调用栈；③ 检查 OneDrive 是否覆盖 C:\workspace（本机 OneDrive.exe 在跑）。

### 3.2 bash 长命令静默失败/SIGTERM

- **现象**：多段组合命令（heredoc 双段、长管道）输出丢失或整个进程被 SIGTERM（push×2、agent-browser install、重切×1、format:check×1）。
- **已固化对策**：①关键命令输出**落盘文件再读**（`.tmp-xxx.log`），不信管道回传；②常驻进程**严禁** `| head -N`（写满即 SIGPIPE 杀进程——vite/Nest 各死过一次）；③后台长任务用 run_in_background + 日志文件；④npm 装包加 `--registry=https://registry.npmmirror.com`。
