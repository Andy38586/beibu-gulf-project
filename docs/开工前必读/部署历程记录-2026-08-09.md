## 六、经验教训（面试可用）

1. **npm ci 是严格模式**：lock 缺 optional/peer 条目（如 macOS 的 fsevents）在 Linux 上必然 EUSAGE——生产构建用 `npm install` 更务实
2. **国内服务器三板斧**：apt 源 / docker-ce 源 / 镜像加速器，缺一不可
3. **NODE_ENV=production 会触发生产特有行为**：cookie Secure、ETag 304、限流——本地 dev 永远不会暴露，必须部署后逐项验证
4. **改 nginx 配置先分清生效分支**：HTTP/HTTPS 两套配置（本次改错到 HTTPS 分支浪费一轮）
5. **304 不等于 2xx**：前端 fetch 需处理或禁止缓存（API 一律 no-store）
6. **静默输入（read -rsp）的 key 会损坏**：粘贴时重复/截断，配置后要 `cat` 验证

### 1. HTTPS 上线（Let's Encrypt + duckdns DNS-01）

| 坑                                                  | 根因                                                                                                                                                                                     | 修复                                                                                                                                                               |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ACME webroot 认证失败（`Connection reset by peer`） | 阿里云云防护重置海外 IP 对 80 端口的访问——本机 curl 200 是回环、浏览器 502 是本地代理海外节点，均绕过防火墙，现象反复误导                                                                | 换 **DNS-01**：`certbot-dns-duckdns` 插件（duckdns TXT 记录验证，零 80 依赖）；certbot 2.9 对 `--dns-duckdns` 前缀歧义 → 用 `--authenticator dns-duckdns` 显式指定 |
| 浏览器 ERR_CONNECTION_CLOSED                        | ①compose 端口是 `8443:443`，nginx 301 跳转到标准 443 断链；②阿里云防火墙未放行 443；③Safari 走本地代理 → 海外节点访问国内服务器被重置                                                    | compose 改 `443:443` 直通 + 防火墙放行 443；换手机流量验证（排除代理干扰）                                                                                         |
| nginx emerg `shared memory zone "SSL" conflicts`    | 官方 nginx 主配置 `ssl_session_cache shared:SSL:2m` vs entrypoint 模板生成 https.conf `10m`，同名 zone 大小不一致 → 容器启动即崩（容器 Up(healthy) 是假象：healthcheck 探的是后端 3000） | entrypoint 模板统一 2m（本地+服务器双份，commit 69e4cca）                                                                                                          |
| 证书续期会断                                        | certbot 自动续期只更新 `/etc/letsencrypt/live/`，不会同步到 `/opt/beibu-gulf/certs/`                                                                                                     | `renewal-hooks/deploy/beibu-gulf-cert-sync.sh`：续期成功 → copy 证书 + reload 容器；`certbot renew --dry-run` 验证通过（证书 2026-11-08 到期）                     |
