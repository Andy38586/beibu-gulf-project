## 一、项目身份

- 面向**智慧港口场景**的 WebGIS 业务应用,验证"可扩展的 GIS 系统架构"而非单纯可视化 Demo
- 三类核心业务:选址分析(2D 空间运算)、预测分析(趋势可视化)、浸没分析(3D 淹没演算)
- 技术底座:Vue 3 + OpenLayers(2D)+ Cesium(3D)+ Express(API)+ FastAPI(在线演算)

## 二、分层原则

- **单向依赖**:shared(基础设施)→ stores/services(状态/数据)→ core(地图+布局基座)→ business(业务)→ 应用层装配;层级顺序与例外(如 core→stores 设计确认)见 `docs/分层契约.md`(L0-L8)
- **依赖方向由 dependency-cruiser 强制**(`npm run cruise`,含 backend,0 violation 为门禁)
- **types/ 是纯类型层**(零运行时依赖);运行时常量/工具归 shared
- **业务模块互不依赖**,经 manifest(`business/manifest.ts`)注册路由/导航,新增模块只改 manifest + 建模块目录

## 三、Renderer 抽象原则(双引擎)

- **问题**:2D/3D 引擎 API 完全不同,业务不能绑死某引擎
- **方案**:`MapRenderer` 抽象接口,OL/Cesium 各一实现;业务经接口操作地图,引擎切换业务零改动
- **能力边界**(关键):
  - 双引擎公共能力(图层增删/视图控制/呼吸动画)放基类
  - **单引擎专有能力(水面)拆独立能力接口 `Water3DCapability`**,调用方能力检查后使用——基类不为 2D 背负 3D 契约(ISP 违反即架构债)
  - 引擎标识 `getType()` 返回 `'2d'/'3d'`(与 MapType 一致,禁止返回引擎名 'ol'/'cesium')
- **生命周期**:渲染器实例复用不销毁;3D→2D 切换必须 `unmount()`(暂停渲染 + 空闲销毁);30s 内切回由 mount 取消销毁
- 能力缺失(如 2D 上调用水面)由调用方检查跳过,禁止空实现 stub

## 四、图层管理原则(BusinessLayerManager)

- 业务图层**统一**经 BLM 注册/更新/显隐/移除,禁止直接操作 renderer 图层
- **注册即占位**:`data` 未就绪也可注册(visible 控制),数据到达后 `updateData`
- **updateData 语义**:图层实例缺失时补建,已存在则更新(保证"先占位后填数据"永远生效)
- **可见性唯一权威**:registry(非 catalog);引擎切换后 `reapplyAll` 按 registry 重建
- 特殊图层(如水面,存于 `_waterSurfaces` 而非 `_layers`)经 adapter `setVisibility` 分派,禁止落入 pendingVisibility 失效路径

## 五、GCS 布局原则

- **问题**:GIS 应用浮动面板多,布局易失控
- **方案**:80px 网格单元(Cell)驱动全部面板尺寸与定位,禁止硬编码 px
- 哲学:布局是"网格约定"不是"组件库"——任何面板 = 整数个 Cell + 锚点定位
- 具体规则(PPS 定位/锚点/显隐)见 `docs/开工前必读/工程规范与性能参考.md`

## 六、状态管理原则

- 只有**跨组件/跨页共享**的状态进 Pinia store;页面内临时状态用组件 ref
- **命名统一**:全部 `useXxxStore`(Store 后缀),禁止 State/Store 混用
- store 职责单一;协调多个 store 的重置逻辑放应用层(App.vue 注入),不放"壳 store"
- 业务状态持久化(如登录回跳恢复)用显式快照工厂(createPersistedState),版本号 + zod 校验防旧数据污染

## 七、数据流原则

- **请求唯一入口**:`useApiRequest`(API)/ `loadStatic`(静态);跨服务(FastAPI)用 `envelope: false` 仍走入口;禁止裸 fetch
- **信封唯一**:`{code,data}`,解包唯一走 `unwrapEnvelope`
- **边界校验**:HTTP 响应 zod `schema` 必传(全量覆盖);mock 数据带 `_contractVersion` 契约版本
- 数据源三模式(mock/api/online)是**数据演进路径**而非平行实现:mock 契约桩、api JSON 过渡、online 真演算,最终归空间数据库;adapter 隔离保证演进时业务零改动
- 后端读文件缓存统一 `createReadCache`(TTL + LRU + 上限),禁止自研 cache Map
- 细节见 `docs/数据流契约.md`

## 八、工程红线(不变量)

- 架构契约 `npm run cruise` 0 violation(含 backend)
- 前后端测试全绿(测试数为动态状态,以 `npm test` 为准,不写死);HTTP 边界 100% zod 校验
- **禁止**写会过时的信息进规范文档(具体清单/行号/覆盖率数字/版本)——规则进文档,状态进 `待解决问题.md`/`已解决问题.md`
- 面试口径:分层/数据流/类型安全是可讲的硬能力;合成指标、@ts-nocheck 是已定性的诚实项(主动讲,不回避)
