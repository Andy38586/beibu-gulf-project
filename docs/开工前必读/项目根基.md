### 2.2 依赖规则（不可违反）

**规则 1: core 不依赖 business**

如果 UnifiedMap.vue 的 import 里出现了 `@/business/`，这是违规。

```ts
// ❌ 违规 — core 层不该知道业务层的存在
// src/core/map/UnifiedMap.vue
import { useAnalysisLayer } from '@/business/site-selection/composables/useAnalysisLayer'

// ✅ 正确 — 业务层自己注册，通过 mapStore 注入
// src/business/site-selection/SiteSelectionPage.vue
const updateHandler = createUpdateHandler(businessLayerManager)

```

**规则 2: shared 不依赖 business**

通用组件只能通过 props / slots / emits 接收业务差异，不能 import 业务常量或 composable。

```ts
// ❌ 违规
// src/shared/components/PaginatedListPanel.vue
import { facilityConfig } from '@/business/site-selection/composables/facilityConfig'

// ✅ 正确 — 通过 props 传进来
defineProps<{ items: Xiaoqu[]; planType: 'site-selection' | 'flood' }>()
```

**规则 3: visualization 不依赖 business**

```ts
// ❌ 违规示例（A05，已于阶段 6 修复）

// ✅ 正确 — 通过 props 接收配置（当前实现）
```

**规则 4: stores 之间可以通过 `useXxxStore()` 互相引用**



### 2.3 组件分类与复用规则

**组件层次**（四层主架构 + 一个独立展示层）：

| 层次 | 位置 | 示例 | 依赖方向 |

**何时抽取到 `shared/`**：

- 纯工具函数（不依赖 Vue 响应式） → `shared/utils/`

**不要过早抽象**：只被一个业务使用的组件留在 `business/<name>/components/` 下。等到第二个业务真正需要它时再搬。

## 三、GCS Panel 布局系统

### 3.1 设计哲学

> Canvas ���屏幕，Grid 是尺子，Cell 是单位，Panel 是一切。

本项目不用 Header / Sidebar / Content / Footer 布局���用的是 iPad 桌面模型：屏幕上没有区域分区，所有可见元素都是浮在地图之上的 Panel。

### 3.2 Cell 是什么

Cell 是 GCS 的度量单位，不是 CSS 单位。**1 Cell 的像素值由视口宽度决定**，默认区间（1024–1919px）下为 80px，完整映射如下：

| 视口宽度 | 1 Cell = |
|---------|:-------:|
| ≥1920 | 90px |
| 1024–1919 | 80px（默认） |
| 768–1023 | 70px |
| <768 | 60px |

> 1024–1919 是默认区间，`getCellPixelByViewport` 在此区间统一返回 80px。

### 3.3 四条铁律

| # | 铁律 | 具体含义 |
|---|------|---------|
| 1 | 一切都是 Panel | 标题、图表、按钮、Dock 都通过 `<GCSPanel>` 定位 |
| 2 | 不存在容器 | 代码里没有 Zone / Area / Container 组件。只有 Panel |
| 3 | 度量单位是 Cell | 宽高和偏移全用 Cell 值，不写 px |
| 4 | 间距统一 20px | Panel 到任意边缘 / 其他 Panel 的距离 = 2×GAP = 20px |

### 3.4 PPS 定位

Panel 在屏幕上的位置由 `useGCS().panelPosition(w, h, anchor, offsetX, offsetY)` 计算。

锚点可以是：`top-left`（左上角向右下偏移）、`top-right`（右上角向左下偏移）、`top-center`、`bottom-center`、`bottom-left`、`bottom-right`。

标准用法：

```vue
<!-- 左上角放一个 4×4 Cell 的 Panel，向下偏移 1.25 Cell -->
<GCSPanel :w="4" :h="4" anchor="top-left" :offset-x="0" :offset-y="1.25">
  <LayerControlPanel />
</GCSPanel>

<!-- 右下角再放一个 4×4 Cell 的 Panel -->
<GCSPanel :w="4" :h="4" anchor="top-right" :offset-x="0" :offset-y="5.5">
  <YourChart />
</GCSPanel>
```

`offset-x` 和 `offset-y` 的单位也是 Cell。所以 `offset-y="1.25"` + `h="4"` + 间距 20px ≈ 第二个 Panel 的起始位置在第一个 Panel 底部��方约 0.5 Cell 处。

### 3.5 CSS 变量体系

**核心边界**：CSS 变量只管"这个按钮什么颜色"。GCS JS 系统（`useGCS().cell8px`）管"这个按钮在屏幕什么位置、多宽多高"。

完整的全局 Token 定义在 `src/style.css` 的 `:root` 中。以下是使用示例：

```vue
<script setup lang="ts">
import { useGCS } from '@/core/layout/useGCS.js'
const { cell8px, fontSizeBody } = useGCS()
</script>

<style scoped>
.my-button {
  /* ✅ 颜色/圆角/阴影用 var(--GCS-*) */
  background: var(--GCS-color-primary);
  color: var(--GCS-text-inverse);
  border-radius: var(--GCS-radius-md);
  box-shadow: var(--GCS-shadow-sm);

  /* ✅ 动态尺寸用 useGCS() + v-bind() */
  padding: v-bind(cell8px);
  font-size: v-bind(fontSizeBody);
}

.my-button:hover {
  background: var(--GCS-color-primary-hover);
}
</style>
```

**JS 内联样式也可以引用 CSS 变量**（来自 `GCSButton.vue` 真实代码）：

```ts
const buttonStyle = computed(() => ({
  ...cell(props.w, props.h),
  backgroundColor: props.active ? 'var(--GCS-color-primary)' : 'var(--GCS-bg-panel)',
  color: props.active ? 'var(--GCS-text-inverse)' : 'var(--GCS-text-regular)',
  boxShadow: 'var(--GCS-shadow-sm)',
}))
```

**不进入全局 Token 的颜色**——洪水风险等级色是业务域专属，在业务页面的 scoped style 中定义：

```css
/* src/business/flood-analysis/FloodAnalysisPage.vue — 不污染 :root */
.flood-page {
  --flood-color-high: #f56c6c;
  --flood-color-medium: #e6a23c;
  --flood-color-low: #67c23a;

```

设施标识色同理（医院红、学校蓝、公园绿等 6 色）定义在 `facilityConfig.js` 中，不注册到全局 Token。

### 3.6 面板分类与交互契约

Panel 按交互模式分为两类：

| 类型 | 定义 | 交互模式 | 示例 |
|------|------|---------|------|
| **数据末端 (Data Endpoint)** | 接收数据 → 可视化渲染 → 终点 | **只消费数据，不对外输出参数** | LineChart / BarChart / RadarChart / FloodAnalysisReportPanel |
| **中间件 (Middleware Panel)** | 接收参数 → 展示 + 交互 → 传出参数 | **双向通信：既读又写** | LayerControlPanel / PaginatedListPanel / SiteAnalysisControlPanel |

**数据末端的设计约束**——不能修改数据，只能展示：

```vue
<!-- ✅ 正确：RadarChart 只通过 props 接收数据，不改写 -->
<RadarChart :axis-config="axisConfig" :data="displayXiaoquForRadar" />

<!-- ❌ 错误：RadarChart 内部不能调 store 修改数据 -->
```

**中间件的交互契约**——以 PaginatedListPanel 为例：

输入（props）：
- `items` — 数据源数组
- `pageSize` — 每页条数
- `planType` — 方案类型（`'site-selection'` 或 `'flood'`）

输出（emits）：
- `click-item` → 父组件接收，触发地图呼吸灯 + 更新雷达图

内部直接操作（不用 emit）：
- 地图 `flyTo` / `startBreathing` — 通过 `useMapControls()`
- 收藏/取消收藏 — 通过 `usePlans()`
- 登录判断 — 通过 `useAuth().isAuthenticated`

**LayerControlPanel 的交互模式**：

- 输入：通过 `useLayerManager().layerCatalog` 获取图层列表（来自 `mapStore.layerCatalog`）
- 输出：通过 `mapStore.toggleLayer(key)` 控制图层显隐
- **不直接操作渲染器**——通过 store → `registerToggleable` 的 show/hide 回调间接操作

**雷达图的数据流向**（理解 `displayXiaoquForRadar` 计算属性的编排）：

```
分析结果 → SiteSelectionPage.matchedXiaoqu
  → displayXiaoqu (切片 top 8)
  → PaginatedListPanel (列表展示)
     → click-item emit
        → selectedXiaoqu 更新
           → displayXiaoquForRadar (优先选中，否则第一名)
              → RadarChart props 更新
```

## 四、Renderer Adapter 模式

### 4.1 设计意图

业务代码不直接依赖 OpenLayers 或 Cesium 的 API。所有地图操作通过 `MapRenderer` 接口完成。换一个渲染器（比如把 OL 换成 MapboxGL）不需要改任何业务代码。

### 4.2 接口定义

`src/types/renderer.ts` 定义了渲染器必须实现的接口：

```ts
// 业务层只依赖这个接口，不 import 'ol' 或 'cesium'
interface MapRenderer {
  addPointLayer(id: string, features: PointFeature[], options?: LayerOptions): void
  addGeoJsonLayer(id: string, geojson: GeoJSON.FeatureCollection, options?: LayerOptions): void
  setVisibility(id: string, visible: boolean): void
  removeLayer(id: string): void
  flyTo(target: LngLat | [number, number] | { layerId: string }, options?: FlyToOptions): void
  destroy(): void
  // 双引擎都支持
  startBreathing(lng: number, lat: number): void
  stopBreathing(): void
  // 3D Only — OLRenderer 不实现，调用时返回 false + DEV warn
  addWaterSurface?(id: string, coords: [number, number][], height: number, opts?: WaterSurfaceOptions): boolean
  updateWaterLevel?(id: string, newHeight: number): boolean
}
```

**渲染器能力矩阵**（2D vs 3D 各自支持什么）：

| ���性 | OLRenderer | CesiumRenderer | 备注 |
|------|:---------:|:-------------:|------|
| 点图层 / 多边形 / GeoJSON | ✅ | ✅ | 双引擎都支持 |
| 热力图 | ✅ | ❌ | 仅 OL |
| 水面效果 | ❌ | ✅ | 仅 Cesium |
| 呼吸灯 | ✅ (requestAnimationFrame) | ✅ | 双引擎都支持 |
| flyTo duration | 毫秒 | 秒（内部已统一） | `CesiumRenderer` 已修正 |
| destroy 资源清理 | ✅ | ✅ | camera.changed 已保存引用并 destroy 时移除 |

**Cesium Viewer 生命周期规则**（2026-07-30 更新：原"单例不销毁"已变更为 idle-destroy）：

- CesiumViewer 由 `CesiumRenderer` 内部管理，首次创建后复用
- 离开 3D 路由时 `v-show` 隐藏，启动 30s 空闲计时器（`CesiumRenderer.js:33` `IDLE_DESTROY_DELAY=30000`）
- **30s 内重入 3D**：取消销毁定时器，复用已有 viewer（无开销）
- **30s 内未重入**：自动 `viewer.destroy()` 释放显存，下次重入重建 viewer
- **trade-off**：重建时 Cesium 的 3D Tiles / 地形缓存会丢失（需重新请求），换来低端设备不会因后台挂 3D 上下文而 OOM。`requestRenderMode=true` 已设但 destroy 是额外兜底——若后续发现重建延迟不可接受，可改为仅暂停渲染不销毁

### 4.3 业务代码怎么拿到 Renderer

**标准模式**（来自 `FloodAnalysisPage.vue`）——不要直接在 `onMounted` 里取，渲染器初始化是异步的：

```ts
// ✅ 正确：用 watch 等待渲染器就绪
watch(
  () => mapStore.currentRenderer,
  (renderer) => {
    if (renderer) {
      nextTick(() => {
        registerFloodLayers()  // ← 此时 renderer 一定非空
      })
    }
  },
  { immediate: true }
)

// ❌ 错误：onMounted 时 renderer 可能为 null → TypeError
onMounted(() => {
  const renderer = mapStore.currentRenderer   // null!
  renderer.addPointLayer(...)                 // 💥
})
```

**图层注册**——业务模块通过 `BusinessLayerManager` 注册图层，不直接调 `renderer.addXxx()`：

```ts
// FloodAnalysisPage.vue 注册水面图层
businessLayerManager.register('flood-water-surface', {
  label: '水面',
  layerType: 'waterSurface',
  data: { coordinates: waterCoords, height: waterLevelStore.waterLevel },
  options: { color: 'rgba(64, 158, 255, 0.5)' },
  visible: true,
})

// 水位变化时更新水面高度（updateData 不改 visible，只改数据）
businessLayerManager.updateData('flood-water-surface', {
  data: { coordinates: waterCoords, height: newLevel },
})
```

`BusinessLayerManager` 在 `App.vue` 中创建并通过 `provide(BUSINESS_LAYER_MANAGER_KEY)` 注入——因为 RouterView 下的业务页面和 UnifiedMap 是兄弟节点，不能通过父→子 provide。业务页面通过 `inject` 获取实例：

```ts
// 业务页面顶部获取 BusinessLayerManager 实例（App.vue provide 的单例）
import { inject } from 'vue'
import { BUSINESS_LAYER_MANAGER_KEY } from '@/core/map/businessLayerManager'

const businessLayerManager = inject(BUSINESS_LAYER_MANAGER_KEY)!
```

> **禁止**直接 `new BusinessLayerManager()`——会破坏图层目录的单例一致性。

> **`BusinessLayerManager` 与 `useLayerManager()` 的区别**：`BusinessLayerManager` 是业务图层的**写入端**（注册/更新/移除业务图层，由业务页面使用）；`useLayerManager()` 是 Shared 的 composable，封装对 `mapStore.layerCatalog` 的**读取端**（供 LayerControlPanel 等通用组件消费图层列表）。两者操作同一数据源，职责不重叠。

### 4.4 引擎切换流程

路由 `meta.engine` 变化 → `App.vue` 的 `watch` 调用 `mapStore.setMapType('2d'|'3d')` → `UnifiedMap` 的 `v-show` 切换容器 → `exportState`（保存旧引擎的图层可见性 + 相机） → `importState`（恢复到新引擎）。

关键设计：
- OL 的 `<div>` 容器始终存在于 DOM 中（`v-show` 不销毁）
- Cesium 的 `Viewer` 首次创建后复用，离开 3D 路由时 `v-show` 隐藏 + 启动 30s idle-destroy 计时器（详见 §4.2 Cesium Viewer 生命周期规则）
- `isEngineSwitch` 标记防止切换时触发相机重置

**已实现的闭环机制**：
`App.vue` 监听 `mapStore.currentRenderer` 变化（`:99-106`），当检测到 renderer 切换时，
调用 `BusinessLayerManager.reapplyAll(renderer)` 将所有已注册且可见的业务图层
重新应用到新 renderer。registry 在 App 级持久，业务页面不会因切换引擎而重新 register。

reapplyAll 实现（`BusinessLayerManager.js:142-152`）：
遍历 `_registry`，对每个可见图层调用 `adapter.create(renderer, key, data, options)`。

**不受 reapplyAll 保护的情况**：
- 底图图层（由 `UnifiedMap.setupLayers` 重新注册）
- 直接通过 `renderer.addPointLayer` 添加但未经过 `BusinessLayerManager.register` 的图层

### 5.2 引擎切换链路

路由 `meta.engine` 变化时，App.vue 的 watcher 响应：

```ts
// App.vue — 核心切换逻辑
watch(
  () => ({ name: route.name, engine: route.meta?.engine }),
  (newRoute, oldRoute) => {
    const isEngineSwitch = oldRoute?.engine && newRoute.engine && oldRoute.engine !== newRoute.engine

    if (newRoute.engine && ['2d', '3d'].includes(newRoute.engine)) {
      mapStore.setMapType(newRoute.engine)   // → UnifiedMap 接收 props.mapType → v-show 切换
    }

    if (!isEngineSwitch) {
      // 普通路由跳转 → 重置相机到对应视图
      if (newRoute.name === 'Home') waitForRenderer(zoomToRegion)
    }
    // 引擎切换时不重置相机 — 由 UnifiedMap 的 importState 管理
  },
  { immediate: true }
)
```

```vue
<script setup lang="ts">

import GCSPanel from '@/core/layout/components/GCSPanel.vue'

// 模板 ref → onMounted / onUnmounted 清理

// onBeforeRouteLeave → saveState 暂存状态
</script>

<template>
  <div class="xxx-page">
    <AppLayout>
      <template #left>
        <GCSPanel :w="4" :h="4" anchor="top-left" :offset-x="0" :offset-y="1.25">
          <YourLeftPanel />
        </GCSPanel>
      </template>
      <template #right>
        <GCSPanel :w="4" :h="4" anchor="top-right" :offset-x="0" :offset-y="1.25">
          <YourRightPanel />
        </GCSPanel>
      </template>
    </AppLayout>
  </div>
</template>

<style scoped>
.xxx-page {
  width: 100%; height: 100%;
  pointer-events: none;                    /* ← 关键：鼠标事件穿透到地图 */
}

}
```

### 6.2 关键模式

**模式一：Render Handler 注入**

> 此模式让 `mapStore` 累积了 analysisHandler 职责，是已知的设计取舍（详见 `待解决问题.md` A02/A04）。

业务模块通过 `mapStore.registerAnalysisHandler` 注册一个函数来接收分析结果，而不是让 core 层 import 业务层的处理逻辑：

```ts

```

**模式二：consumeState — 页面切换状态暂存**

用户从业务页跳转到 /profile 再返回时，页面状态不丢失：

```ts
// 离开时保存
onBeforeRouteLeave((to) => {
  if (to.path === '/profile') {
    floodState.saveState({
      waterLevel: waterLevelStore.waterLevel,
      floodStatistics: floodState.floodStatistics,
      floodFeatures: floodState.floodFeatures,
      affectedFacilities: portImpactStore.affectedFacilities,
      totalLoss: portImpactStore.totalLoss,
    })
  }
})

// 返回时恢复（一次性消费后立即清空，防止二次恢复）
// 注意：如果 Vue 启用了 <KeepAlive> 或 HMR 导致 onMounted 多次触发，
// consumeState 第二次调用会返回 null（状态已被第一次消费）。这是预期行为。
onMounted(async () => {
  const savedState = floodState.consumeState()
  if (savedState) {
    waterLevelStore.setWaterLevel(savedState.waterLevel)
    if (savedState.floodStatistics) {
      floodState.startFloodAnalysis(savedState.floodStatistics, savedState.floodFeatures, savedState.floodRiskLevel)
    }
    await nextTick()
    renderFloodAreas(savedState.floodFeatures)
  }
})
```

**模式三：analysisSeq — 请求竞态处理**

用户快速拖动水位滑块时，旧请求的响应不应覆盖新请求的结果：

```ts
// FloodAnalysisPage.vue
let analysisSeq = 0

watch(() => waterLevelStore.waterLevel, (newLevel) => {
  const seq = ++analysisSeq
  setTimeout(() => { triggerFloodAnalysis(newLevel, seq) }, ANALYSIS_DELAY)
})

async function triggerFloodAnalysis(waterLevel, seq) {
  const data = await floodAdapter.getFloodAnalysis(waterLevel)
  if (seq !== analysisSeq) return    // ← 不是最新的请求，丢弃
  floodState.startFloodAnalysis(data.statistics, data.features, data.riskLevel)
}
```

### 7.8 GCS 缩写书写规范与坐标系豁免

**铁律：`GCS` 的唯一合法写法是全大写 `GCS`。**

`GCS` = **Global Component Style**（全局组件样式系统，见第三节「GCS Panel 布局系统」）。指代它时**只允许全大写**；`Gcs` / `gcs`（含历史写法 `gcsStore` / `GcsPanel` / `--gcs-*`）一律视为**违规命名**，已于 2026-07-30 全量改正（`GCSPanel` / `GCSButton` / `GCSInspectionOverlay` / CSS 变量 `--GCS-*`，见 3.5 CSS 变量体系）。

**坐标系术语豁免**：`GCS` 按"独立词 / 词边界"判定。`CGCS2000`（国家 2000 大地坐标系，EPSG:4490，见 `src/types/crs.ts`）子串虽含 `GCS`，但含义是 "Geodetic Coordinate System"，与 Global Component Style 无关，**不算违规**，保留原样。

| 写法 | 判定 | 说明 |
|------|------|------|
| `GCS`、`GCSPanel`、`--GCS-*`、`useGCS` | ✅ 合法 | Global Component Style |
| `CGCS2000` | ✅ 合法（豁免） | 坐标系术语 |
| `Gcs`、`gcs`、`GcsPanel`、`--gcs-*` | ❌ 违规 | 须改为全大写 |

### 8.4 认证

认证以 **HttpOnly Cookie 单通道**为主（对应 D04 决策：防 XSS 抓取令牌）。登录时后端 `authController.setAuthCookie` 设置 `auth_token` Cookie（7 天，`sameSite: 'strict'`）。前端 `useApiRequest` 仅通过 `credentials: 'include'` 自动携带该 Cookie，**不再发送 `Authorization: Bearer` header**。后端 `middleware/auth.js` 的 `authenticate` 仍**保留 Bearer header 作为服务端 fallback**（便于非浏览器客户端 / 调试），但浏览器前端实际只走 Cookie 通道。详细契约见 API 契约文档 §1.3。

**模块认证策略**：除预测分析（`/api/forecast/*` 视为公开数据，不需要认证）外，其余业务模块（auth / markers / facilities / plans / site-analysis / flood）均需认证。预测模块的免认证是稳定设计决策，详见 API 契约文档 §8。

## 十一、常见任务决策树

> 以下 7 个场景是 AI 或新开发者最常面对的操作。"文件清单"里的是实际要改的文件，"不要做的事"是容易踩的坑。

### 11.1 新增业务页面

```
问: 我要新增一个业务页面（如"航线分析"）
→ 参考模板: FloodAnalysisPage.vue（3D）或 SiteSelectionPage.vue（2D）

文件清单:
  1. src/business/route-analysis/RouteAnalysisPage.vue  ← 套用 §5.3 模板
  2. src/router/index.js                                  ← 加路由，声明 meta.engine
  3. src/core/layout/components/BottomNavBar.vue          ← navItems 数组加入口

不要做的事:
  ✗ 不要改 AppLayout.vue（slot 机制已足够，AppLayout 当前限制详见 `待解决问题.md` A01）
  ✗ 不要改 UnifiedMap.vue（它不关心业务）
  ✗ 不要在 views/ 下创建（那是通用页面，不是业务页面）
```

### 11.2 新增图表 Panel

```
问: 我要新增一个可视化 Panel（如"散点图"）

判断: 这个 Panel 是数据末端（只展示）还是中间件（要交互传出参数）？

如果是数据末端:
  → src/visualization/charts/ScatterChart.vue
  → 参考 RadarChart.vue 的模式：props 驱动 + useECharts() + composable
  → 在页面中通过 <GCSPanel> 包装使用

如果是中间件:
  → 如果只被一个业务使用 → src/business/<name>/components/
  → 如果 ≥2 个业务使用 → src/shared/components/
  → 参考 PaginatedListPanel 的模式：props + emits + 内部直接操作 useMapControls
```

### 11.3 新增图层到地图

```
问: 我要在地图上添加一个新图层（如"航线轨迹"）

判断: 这个图层是基础底图（互斥选择）还是业务图层（可叠加）？

基础底图:
  → UnifiedMap.vue 的 _initBaseLayers() 加 TileLayer
  → 参考 registerBaseLayer('base-image', ...) 的模式

业务图层:
  → 在业务页面的 watch(currentRenderer) 中通过 BusinessLayerManager 注册
  → 参考 FloodAnalysisPage.vue 的 registerFloodLayers()

关键时序:
  ✗ 不要在 onMounted 直接注册（渲染器可能未就绪）
  ✓ 用 watch(() => mapStore.currentRenderer, ...)
```

### 11.4 新增 Pinia Store

```
问: 我要新增一个全局状态

文件: src/stores/<业务名>Store.ts

模式选择:
  - 需要持久化（刷新后保留） → 参考 mapStore.ts，读写 localStorage/sessionStorage
  - 纯运行时状态           → 参考 floodState.ts，Pinia setup store
  - 页面切换暂存           → 参考 siteSelectionState.ts，saveState + consumeState

不要做的事:
  ✗ 不要把 UI 临时状态放进 map store（map store 职责已过重）
  ✗ 不要在 store 中直接操作渲染器（通过 composable 间接操作）
```

### 11.5 修改已有组件的 props

```
问: 我要给 PaginatedListPanel 增加一个功能

步骤:
  1. 确认这是真需求还是已有 props 可满足（先读组件顶部的 JSDoc）
  2. 如果加 props → 同时更新 TypeScript interface（Props 类型）
  3. 如果改交互模式 → 先确认 SiteSelectionPage 和 FloodAnalysisPage 的使用不会被打断
  4. 修改后至少在两个页面测试

风险点:
  - PaginatedListPanel 被 SiteSelectionPage 和 AffectedFacilityListPanel 使用
  - 改动可能影响收藏逻辑（usePlans）和地图交互（useMapControls）
```

### 11.6 修复 bug

```
问: 我要修一个后端 bug

流程:
  1. 读 待解决问题.md 确认优先级和改动量
  2. 只改描述涉及的文件
  3. 修复后验证: curl 测试关键 API 端点
  4. 完成后: 从 待解决问题.md 删除 → 写入 已解决问题.md

不要做的事:
  ✗ 不要顺手重构整个模块（§9 规则 4）
  ✗ 不要"顺便"把 JSON 存储改成数据库（那是 §10 的 Step 5，放另一个 PR）
```

### 11.7 在渲染器中新增能力

```
问: OLRenderer 不支持热力图，我要加

步骤:
  1. 在 MapRenderer 接口（src/types/renderer.ts）中新增可选方法签名 addHeatmapLayer?(id, features, options): void
  2. 在 OLRenderer 中实现该方法
  3. CesiumRenderer 可不实现（调用时返回 undefined + DEV warn）

这是"给框架加能力"，不是"动底层"。渲染器扩展是框架的自然增长。
```

## 十二、常见反模式

### 反模式 1: 页面忘记 pointer-events: none

```vue
<!-- ❌ — 地图完全不能拖拽缩放 -->
<style scoped>
.flood-page { width: 100%; height: 100%; }
</style>

<!-- ✅ -->
<style scoped>
.flood-page {
  width: 100%; height: 100%;
  pointer-events: none;
}
.flood-page :deep(.GCS-panel) { pointer-events: auto; }
</style>
```

### 反模式 2: 用 :deep(*) 恢复 pointer-events

```css
/* ❌ 通配符特异性高于 .map-container → Cesium canvas 永远收不到鼠标事件 */
.flood-page :deep(*) { pointer-events: auto; }
```

### 反模式 3: onMounted 里直接拿 renderer

```ts
// ❌ renderer 是异步初始化的，onMounted 时大概率 null
onMounted(() => {
  mapStore.currentRenderer.addPointLayer(...)   // TypeError
})

// ✅ 正确
watch(() => mapStore.currentRenderer, (renderer) => {
  if (renderer) nextTick(() => registerFloodLayers())
}, { immediate: true })
```

### 反模式 4: 硬编码颜色或 px

> **例外**: BottomNavBar 中 inspection toggle 的 `#4ecdc4` / `#f5f5f5` 是开发调试工具色（检查模式），不进入生产 UI，可保留硬编码。

```vue
<!-- ❌ -->
<div style="background: #409eff; border-radius: 8px; padding: 10px;">

<!-- ✅ -->
<div :style="{
  background: 'var(--GCS-color-primary)',
  borderRadius: 'var(--GCS-radius-md)',
  padding: cell8px,
}">
```

### 反模式 5: core 层 import business 层

```ts
// ❌ src/core/map/UnifiedMap.vue
import { useAnalysisLayer } from '@/business/...'

// ✅ 业务层通过 mapStore 注入
mapStore.registerAnalysisHandler(createUpdateHandler(businessLayerManager))
```

### 反模式 6: 把"刻意简化"当 bug 修

JSON 文件存储替代数据库是当前阶段的刻意简化。不要把第 10 节 Step 5 的规划提前执行。

### 反模式 7: 修 bug 时顺手重构

P1-07 是 markers 字段名不一致（3 行改动）。顺手把 markers 模块重构成 TypeScript 会让 diff 暴涨到 200+ 行，回滚困难。重构放另一个 PR。

### 反模式 8: 不处理请求竞态

```ts
// ❌ 快速拖动滑块时旧响应覆盖新响应
watch(waterLevel, async (level) => {
  const data = await fetchAnalysis(level)
  setResult(data)     // 旧请求可能后到达 → 覆盖新请求
})

// ��� 用递增序号过滤
let seq = 0
watch(waterLevel, async (level) => {
  const currentSeq = ++seq
  const data = await fetchAnalysis(level)
  if (currentSeq !== seq) return    // 过时请求，丢弃
  setResult(data)
})
```
