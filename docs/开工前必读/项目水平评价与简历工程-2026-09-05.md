## 二、简历可写项（按"眼前一亮指数"排序）

**标准**：有数字、有权衡、有踩坑故事；面试官追问三层你接得住。写一条=吃透一条。

### 第一梯队（双非校招极少见，差异化硬通货）

1. **WebGIS 双引擎渲染架构**——"OpenLayers/Cesium 策略模式双引擎，业务图层零改动切换 2D/3D"
   - 支撑：MapRenderer 抽象基类（能力接口隔离 3D 专有契约）、图层注册表以 registry 为唯一权威源、引擎切换相机状态迁移、依赖规则禁止渲染器互引。
   - 可讲：为什么用能力接口而不是基类空实现（ISP）；registry 为什么不持有 renderer 引用。

2. **连通性淹没分析链**——"海面种子 8 连通淹没演算，0-25m×0.1m 共 251 档预计算表（95MB→15MB gzip），查表 <10ms，LRU 动态演算兜底，EGM96/理论深度基准双基准换算"
   - 支撑：flood_engine.py 全链 + 预计算脚本 + flood.py 档位缓存。
   - 可讲：为什么连通域过滤而非高程判断（内陆高地误判）；为什么向上取档（宁可高估风险）。

3. **路网拓扑修复**——"OSM 路网纵向道路不在路口切断致主分量仅 28.6%，设计端点投影切分算法（STRtree 批量 dwithin + numpy 向量化，逐对 Python 循环 262s→秒级）提升至 95%，19.4 万节点/25.2 万边，查询 1-36ms"
   - 支撑：route/topology.py 注释即完整故事。
   - 可讲：为什么不用 OSMnx/pgRouting（轻量应用侧实现）；平行路误连的取舍。

4. **双后端等价迁移方法论**——"Express→NestJS 六模块迁移，逐模块双后端 diff 字节级验收（canonical 序列化+易变字段归一化），行为对齐而非重写"
   - 支撑：施工手册 diff 流程 + contract.e2e 契约测试 + 信封逐字节对齐。
   - 可讲：为什么要字节级而非行为级（迁移期用户无感是硬指标）；ES2022 define-fields 坑。

### 第二梯队（好，但要能背数字/讲清动机）

5. **首屏性能编排**——首屏静态资源 1.1MB，Cesium 5.7MB 懒加载（自制 Vite 插件移除注入标签）+ 空闲预热队列 + ECharts 异步；perfReporter 五层指标（FCP/LCP/CLS/TTI/FPS/API p95）。
