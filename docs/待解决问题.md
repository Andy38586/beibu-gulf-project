> **定位**：当前所有经真实代码取证确认**仍未闭环**的问题。修一个 → 从本文件删除，按**原编号**移入 `已解决问题.md`（主本），编号不重排。
>
> **编号规则**：`a`=地图层、`b`=业务层、`c`=组件层、`d`=后端层、`z`=暂未归类。编号全局唯一（本文件与已解决台账之间无重复）。**编号一经分配即为终裁**——跨会话/并行轮次若撞号，按**首次分配**者保留、后来者顺延新编号并就地铁，不重排历史。
>
> **时间戳规则**：每条 `问题编号` 下方仅标注 `discover:YYYYMMDD`（发现日）；`solve:YYYYMMDD` 在移入已解决台账时补。
> **归并规则（2026-09-19 定 · 入库前强制）**：**只有"修复单元"才准分配正式编号**。同族症状降为该条目的"化身"，不给独立编号。判据三条满足其一即合并——**同因**（同一上游缺失）/ **同解**（改一处能同时修好，最强判据）/ **同证伪**（一次复验同时出结论）。**不合并的必要条件**：需改两个不同文件/配置/签名才能修好的，即使同族也分开立号。单条吸收上限 **12 条**，超过即判粒度过粗须拆分。合并后 ① 内容须比原条目更详细（根因 + 失效机理 + 影响面 + 修复方向 + 吸收清单）；② 格式列数 ≤5；③ `discover` 取被吸收条目中**最早**（谁先发现用谁）、`solve` 取最晚、等级取**最高**；④ 必须产出 `旧编号 → 新编号` 映射表落 `docs/audits/<日期>-归并映射.md`；⑤ 归并后按前缀内 `discover` 升序重排连续编号，旧编号不复用。执行时机：问题副本产出后、用户裁决前，由主 agent 执行，不得跳过。详见 `根基文档/审查体系专项/审查体系约定.md` §4.1。
>
> **问题等级**：`p0` 致命/高危阻断｜`p1` 高（正确性/稳定性/安全非致命/面试短板）｜`p2` 中（待改进·低危 bug·语义不一致）｜`p3` 低（接受/硬化/文档/视觉 nits）。
>
> **列格式规则（4 列，每条必须完整）**：
> - **列1 问题等级**：p0/p1/p2/p3。
> - **列2 问题编号**：编号 + `<br>discover:YYYYMMDD`（无 solve）。
> - **列3 问题描述及复现方法/对应文件**：问题描述 + **复现方法**（可复现的写复现路径/操作）；无复现方法的写**对应文件**（file:line 锚定项目内位置）。不写"影响哪些文件"。
> - **列4 解决记录**：三段——**预期思路**（去项目里看代码后写的具体改法）/ **实施风险**（改这个会碰的雷、副作用、前置验证）/ **尝试日志**（实际尝试过的精简成几句话；第一版尚未实际尝试则如实写"第一版尚未实际尝试"）。
>
> **列宽换行标准**：单元格内单行显示宽度 **≤ 88 半角单位**（全角按 2 计、半角按 1 计，≈44 个全角字符）。超宽时用 `<br>` 在语义断点处换行——断点优先标点（`；。，、：！？` 空格 `,` `:` `→` `)` `）` `>` `/`），**反引号代码段内不断行**（代码完整性优先，允许超宽），已有 `<br>` 保留。换行只作用于列3/列4，列1/列2 不换行。
>
> **表格对齐标准**：全文档所有分区表格共用**同一列宽模板**（按各列最大显示宽度），行与行之间用空格补齐，使 `|` 竖线在等宽字体下上下对齐；表头/分隔行/数据行统一按模板生成。新增/修改条目后同步对齐。
>
> **副本规则（两级）**：① 子 agent 工作副本 = 批次目录内 `docs/audits/<日期>-<批次名>/专项N-*-问题副本.md`（审查产出统一落批次目录，禁止散落 docs 根目录）；② 用户裁决副本 = 主 agent 从批次目录聚合生成 `docs/问题副本-<yyyy-mm-dd>-<主题>.md`（命名含当天日期），两处不重复书写。副本经用户裁决后：有价值 → 转正进入本文件（分配正式编号，`discover` = 批次日期）；已解决/证伪 → 留在副本或删除。副本不污染本文件编号系统。
