# 性能基线（2026-08-09 实测）

> 目的：记录当前真实数据规模下的运行表现，回答"项目跑起来是什么水平"。
> 测量环境：Windows 本机，Node v25，Express + Vite dev（数据文件已读入 OS 页缓存）。

## 一、服务端实测（本机已记录）

| # | 基线项 | 数值 | 说明 |
|---|---|---|---|
| 1 | `floodArea.json` 解析耗时 | 读盘 ~1ms + `JSON.parse` **6.3ms**（3.0MB） | Node 侧实测；浏览器量级相同（2~10ms） |
| 2 | 选址分析服务端核心计算 | **1.55s** | 6 类设施全选（983 POI）+ 557 小区，前端默认参数（半径 0.5~3km） |
| 3 | 选址分析 HTTP 端到端 | **4.5s** | 含登录会话 + JSON 序列化/网络往返；服务端核心 1.55s 为大头 |
| 4 | 选址 union 分段 | `buildTypeCoverage` 占核心耗时 95%+（bus_station 372 点 + primary_school 359 点 union 最重）；`intersect` 157ms、评分 10ms、空间筛选 4ms | b044 已知瓶颈：`turf.union` O(n²)，当前规模可接受，数据量翻倍前需 rbush/聚类优化 |

## 二、需浏览器实测（DevTools 操作指引）

| # | 基线项 | 操作 | 记录位置 |
|---|---|---|---|
| 5 | 首屏可交互时间 | DevTools → Performance → 刷新首页，读 FCP/TTI | 建议 < 3s |
| 6 | 2D→3D 切换耗时 | 洪涝页点 3D 按钮，Performance 记切换区间 | 建议 < 2s |
| 7 | 557 小区点渲染帧时间 | 选址分析出图层后，Performance 记 FPS / longtask | 建议无明显掉帧 |

> 浏览器三项由人工验收时记录；首屏 JS 已做 echarts 异步化（echarts 537KB 移出关键路径），生产构建首屏约 1.1MB raw。

## 三、结论

- 当前真实数据规模下：**预测/地图/洪涝秒级响应，选址分析 2~5s（可接受，演示前预热一次接口即可）**。
- 未做：十万级假点、WebWorker、矢量瓦片、PostGIS 压测（v2 明确不做，见 v2 边界清单）。
