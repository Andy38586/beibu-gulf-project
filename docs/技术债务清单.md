### 2. 状态管理重复 —— 泛型化 State Store

**现状**: `siteSelectionState.ts` 和 `floodState.ts` 各 70 行，结构完全一样，只差类型名。后续加航线分析必然复制第三个。

**涉及文件**:

- `src/stores/siteSelectionState.ts` —— 现有
- `src/stores/floodState.ts` —— 现有
- `src/stores/pageStateStore.ts` —— 新文件（泛型）
- `src/business/site-selection/SiteSelectionPage.vue` —— 改用新 API
- `src/business/flood-analysis/FloodAnalysisPage.vue` —— 改用新 API

**修复方案**:

```typescript
// src/stores/pageStateStore.ts — 泛型版
import { defineStore } from 'pinia'
import { ref } from 'vue'
import type { Ref } from 'vue'

export function usePageStateStore<T>(id: string) {
  return defineStore(id, () => {
    const hasState: Ref<boolean> = ref(false)
    const state: Ref<Partial<T>> = ref({})

    function saveState(data: Partial<T>) {
      Object.assign(state.value, data)
      hasState.value = true
    }

    function consumeState(): T | null {
      if (!hasState.value) return null
      const result = { ...state.value } as T
      clearState()
      return result
    }

    function clearState() {
      hasState.value = false
      state.value = {}
    }

    return { hasState, saveState, consumeState, clearState }
  })()
}

// 使用
import { usePageStateStore } from '@/stores/pageStateStore'

// 类型独立定义仍在业务层
interface SiteSelectionState { matchedXiaoqu: ScoredXiaoqu[]; selectedTypes: string[] }
const siteSelectionState = usePageStateStore<SiteSelectionState>('siteSelectionState')
siteSelectionState.saveState({ matchedXiaoqu: [...], selectedTypes: [...] })
```

**难度**: 低 | **耗时**: 1 小时 | **面试得分**: +1.0

### 3. 双认证机制矛盾

**现状**: `useApiRequest.ts` 同时发 `Authorization: Bearer xxx` 和 `credentials: 'include'`。注释说"仅通过 HttpOnly Cookie 存储"，但还在给内存 `token.value` 赋值并塞进请求头。

**涉及文件**: `src/shared/composables/useApiRequest.ts`

**修复方案**: 二选一，只保留一个通道

```
方案 A（推荐，与 FIX:SEC-001 一致）：
  - 删除 token ref 和 Authorization header 逻辑
  - 只保留 credentials: 'include'
  - isAuthenticated 改为 null check（后端 /auth/me 探活）

方案 B（如果后端不支持 HttpOnly Cookie）：
  - 删除 FIX:SEC-001 注释和 credentials: 'include'
  - token 存 localStorage + Authorization header
  - 不是 HttpOnly Cookie 模式就不要注释说自己是
```

**难度**: 低 | **耗时**: 30 分钟 | **面试得分**: +0.5

## P1 — 应该修（直接影响架构质量）

### 5. 坐标系显式声明

**现状**: 全项目无 CRS 声明。`fromLonLat` 默认 EPSG:4326→3857，`Cartesian3.fromDegrees` 默认 WGS84。各类型文件 `lon`/`lng` 字段名也不统一。

**涉及文件**: `src/types/map.ts`、`src/types/renderer.ts`、`src/core/config/map.js`

**修复方案**（两步，不要一次做完）:

**Step 1** — 文档化（不动代码）

```typescript
// src/types/map.ts 加注释
/** 港口坐标（WGS84 / EPSG:4326，来源 public/data/ports.json） */
export interface Port {
  lon: number
  lat: number
}
```

**Step 2** — 统一字段名

```typescript
// 所有新 type 用 lng/lat，旧 Port 保持 lon + lng alias
export interface Port {
  lon: number // 历史字段，已读改用 lng ?? lon
  lat: number
}
```

**难度**: 低（step1）→ 中（step2） | **耗时**: 1-2 小时 | **面试得分**: +1.0

### 6. 引擎切换的数据持久化

**现状**: `exportState/importState` 只序列化 `{ visible: boolean }` 和相机。用户动态加载的图层数据（POI 标记、分析结果面）在引擎切换时丢失。

**涉及文件**:

- `src/core/map/renderers/CesiumRenderer.js`
- `src/core/map/renderers/OLRenderer.js`
- `src/stores/map.ts`

**修复方案**: 不在渲染器里存数据，数据归 Store 管，渲染器只管"画"

```typescript
// map.ts 加一个纯数据缓存
const layerDataCache: Ref<Map<string, unknown>> = ref(new Map())

// 引擎切换时：
// 1. exportState() → 保存 visibility（已有）
// 2. destroy old renderer（已有）
// 3. create new renderer（已有）
// 4. 遍历 layerDataCache，逐个 addPointLayer/addPolygonLayer（新加）
// 5. importState() → 恢复 visibility（已有）
```

**难度**: 中 | **耗时**: 3-4 小时 | **面试得分**: +1.5

### 7. layerCatalog 的响应式性能

**现状**: `layerCatalog: Ref<LayerEntry[]>` + `push()` 每次触发响应式。50 个图层注册 = 50 次重渲染。

**涉及文件**: `src/stores/map.ts`

**修复方案**: 改用 `shallowRef` + 批量更新

```typescript
// 用 shallowRef 存数组，避免深度响应式
const layerCatalog: ShallowRef<LayerEntry[]> = shallowRef([])

// 批量注册后手动触发
function registerLayer(...) {
  // 改动 layerCatalog.value（不触发响应式）
  layerCatalog.value.push(...)
  // 批量完成后手动触发
  triggerRef(layerCatalog)
}
```

**难度**: 低 | **耗时**: 30 分钟 | **面试得分**: +0.5
