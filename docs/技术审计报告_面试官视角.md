## A 级：架构与设计缺陷（面试重点）

### A-01 坐标系策略为零

```typescript
// types/map.ts 用 lon
export interface Port {
  lon: number
  lat: number
}
// types/xiaoqu.ts 用 lng
export interface Xiaoqu extends GeoPoint {
  lng: number
  lat: number
}
```

**问题**: 整个项目没有一个地方声明数据的 CRS（坐标参考系）。`fromLonLat()` 默认转的是 **EPSG:4326 → EPSG:3857**（Web Mercator）。但北部湾港口数据按国家规范应该使用 **CGCS2000**（EPSG:4490 地理 / 4547 3度分带）。你把 WGS84 的数据当 CGCS2000 用？面试追问：如果接国家海洋局数据（CGCS2000），你哪位同事负责找转换参数？能说清楚七参数还是四参数吗？

**追问**: 你代码里 `fromLonLat` 是从 OpenLayers 的 `ol/proj` 导入的，它默认用 EPSG:3857。那 Cesium 一侧的 `Cartesian3.fromDegrees` 用的是 WGS84 经纬度。两边的坐标系假设是**隐含的**——如果有人把 CGCS2000 的坐标传进去，谁会先崩？

### A-02 双引擎切换的数据丢失风险

`CesiumRenderer.exportState()` 和 `OLRenderer.exportState()` 只导出图层可见性 + 相机状态：

```typescript
export interface RendererState {
  [layerId: string]: { visible: boolean } | CameraState
}
```

**问题**: 如果是通过 API 动态加载的图层数据本身（比如用户标记的 POI），引擎切换后这些图层被销毁、新引擎重新创建，但**图层的数据源没有序列化**。面试追问：如果用户在地图上画了 10 个航线标记，从 3D 切回 2D 这些标记还在吗？如果不在，你打算怎么实现"引擎切换不丢失业务数据"？

### A-03 无空间索引，全量渲染

```typescript
const layerCatalog: Ref<LayerEntry[]> = ref([])
function setVisibility(id: string, visible: boolean): void { ... }
```

**问题**: 所有要素（港口、小区、设施 POI、洪水面）加载后**全量渲染**。如果未来数据量达到 10000+ 个设施点，OLRenderer/CesiumRenderer 没有做视口裁剪（viewport culling）。面试追问：Turf.js 有用过 `bbox` 做空间过滤吗？`rbush` 怎么用？为什么 Cesium 自带视锥剔除但你加的业务图层仍然可能卡？

### A-04 状态管理重复模式

`siteSelectionState.ts` 和 `floodState.ts` 的 `saveState` / `consumeState` / `clearState` 模式一模一样，只是数据类型不同：

```typescript
// 两个文件几乎一样的结构
export const useSiteSelectionStateStore = defineStore('siteSelectionState', () => { ... })
export const useFloodStateStore = defineStore('floodState', () => { ... })
```

**追问**: 为什么不抽一个泛型的 `usePageStateStore<T>(id: string)`？你现在要加第 3 个业务（航线分析），是不是又要复制粘贴一个 `routeAnalysisState.ts`？这违反了 DRY 原则，也违反了项目的架构验证目标。

## B 级：工程实践缺陷（加分项）

### B-01 Mock/API 切换需要重新部署

```typescript
// floodAdapter.ts
let _dataSource: 'mock' | 'api' = 'mock'
```

**问题**: 切换数据源需要改代码、重新 build、重新部署。不是运行时配置，也不是环境变量。面试追问：如果要实现"配置文件切换"，你会放在哪个文件里？`VITE_API_MODE=mock` 的 Vite 环境变量方案跟这个 adapter 模式怎么协调？

### B-02 双认证机制矛盾

```typescript
// useApiRequest.ts:56-57
if (token.value !== '') {
  headers['Authorization'] = `Bearer ${token.value}`
}
// useApiRequest.ts:72
credentials: 'include', // FIX:SEC-001: 自动携带 HttpOnly Cookie
```

**问题**: 注释说"Token 仅通过 HttpOnly Cookie 存储"，那你为什么还在发 `Authorization: Bearer xxx` 头？如果 Cookie 已经携带了 token，Authorization header 就是冗余的。更关键的是——如果两种机制同时存在，服务端用的是哪一个？别人能否只带 Bearer 头（不传 Cookie）来绕过 Cookie 的 HttpOnly 保护？

### B-03 全项目只有 1 个正经测试

```bash
src/core/map/__tests__/UnifiedMap.test.js  # 唯一的测试文件
```

**追问**: 这 14 天你做了架构验证、CSS 变量规范、TS 全量迁移，测试覆盖率从多少涨到多少？（答案：0% → 还是 0%）面试官最看重的不是写了多少代码，而是**你怎么保证代码不会退步**。没有 CI、没有测试、没有 lint 检查——下次改 map.ts 你靠什么验证不崩？

### B-04 无 API 版本号

```javascript
// 所有路由注册
router.get('/auth/login', ...)
router.get('/gcs/flood-areas', ...)
router.get('/site-analysis', ...)
```

**问题**: 没有 `/api/v1/` 前缀。以后后端接口要改，前端怎么区分新旧版本？面试追问：不加版本号的学生项目可以理解，但你打算多少用户后才加？100 个？1000 个？加到第几个接口才发现来不及了？

## C 级：GIS 专业度缺失

### C-01 �� OGC 标准服务能力

项目不支持 WMS、WMTS、WFS、WCS 等 OGC 标准。所有底图是硬编码的天地图 URL：

```javascript
// config.js (位置不确定)
'https://t0.tianditu.gov.cn/...'
```

**追问**: 如果政府客户要求接省级地理信息公共服务平台（天地图省级节点），或者接 GeoServer 发布的 WMS 图层，你现在的代码需要改几个文件？（答案是：至少改 UnifiedMap 和 config，因为没有抽象出 OGC 服务层）

### C-02 洪水分析是"假 GIS"

```typescript
// FloodAnalysisPage.vue - 风险等级颜色
'低风险': '#67C23A',
'中风险': '#E6A23C',
'高风险': '#F56C6C',
```

**追问**: 你这个洪水分析是直接调后端 API 返回特征面的。后端怎么算的淹没范围？做过水文分析吗？（Fill → Flow Direction → Flow Accumulation → 阈值提取河网 → 基于 DEM 的水位抬升淹没算法？）你用的是什么 DEM 分辨率？30m SRTM 还是 12.5m ALOS？都不清楚的话，你这个"浸没分析"就是个根据水位画不同半径的圆，跟真实洪水模拟没有关系。

### C-03 热力图没有独立的色带配置

```javascript
// OLRenderer.js L267
;['#00f', '#0ff', '#0f0', '#ff0', '#f00']
```

**问题**: 热力图色带硬编码在渲染器中。预测分析的热力图用什么色带？跟浸没分析一样？面试追问：你知道 `colorScale` 应该设计成由业务层传入的参数吗？渲染器不应该知道业务语义是什么颜色——它只负责画。

## D 级：面向前端的高频追问

### D-01 Cesium 5MB 动态导入 — 你确认 tree-shaking 了？

```javascript
// 某处动态 import
const Cesium = await import('cesium')
```

**问题**: 打包后 `dist/assets/js/echarts-uWS__17l.js 550.54 kB` + `Cesium` 相关大小？面试追问：`Cesium` 库默认不支持 tree-shaking，你知道吗？你是怎么减少 Cesium 打包体积的？用了 `cesium/Build/CesiumUnminified` 还是 `cesium/Source`？

### D-02 Pinia store 的 `layerCatalog` 数组全量替换

```typescript
const layerCatalog: Ref<LayerEntry[]> = ref([])
```

**问题**: `layerCatalog.value.push(...)` 会触发 Vue 响应式变化，但每次 push 会让所有使用了 `layerCatalog` 的 computed/watch 重新计算。如果 50 个图层同时注册，会触发 50 次重渲染。面试追问：你知道什么时候应该用 `shallowRef` 代替 `ref` 来存数组吗？`triggerRef` 是干什么的？

### D-03 UnifiedMap 职责过重（550+ 行）

**已知问题 A-04**，但你没修。面试追问：550 行的组件，你打算怎么拆分？按职责（图层管理 / 事件处理 / 生命周期）、还是按能力（底图 / 交互 / 业务注入）？拆完后组件间怎么通信？这题没标准答案，只看你有没有思考过。
