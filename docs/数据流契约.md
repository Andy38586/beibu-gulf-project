# 数据流契约(Data Flow Contract)

> 定位:项目数据流动的唯一规则文档。任何数据流动相关改动都必须遵守本契约。
> 违反规则的代码 = bug(即使功能暂时正常,也要修)。
> 本契约由 2026-08-04 数据流审查产出,已修复全部已发现的违规项。

---

## 1. 总览

```
业务组件 → adapter(forecast/flood/site-analysis)→ useApiRequest / loadStatic
                                                      ├─ mock  → loadStatic(public/data 契约桩)
                                                      ├─ api   → fetch → Express /api/*
                                                      └─ online→ fetch → FastAPI /flood-online
后端:routes → controllers(sendSuccess) → services(createReadCache) → backend/data/*.json
```

## 2. 前端请求规则

| 规则                      | 内容                                                                                                                             | 违反后果                                     |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| **R1 请求唯一入口**       | API 请求一律走 `useApiRequest`;静态资源一律走 `loadStatic`。**禁止裸 fetch/axios**。                                             | 报错口径/重试/超时/解包全部失效              |
| **R1.1 跨服务例外**       | FastAPI 返回裸 JSON(无信封)时,`apiRequest` 传 `envelope: false`,**仍在统一入口内**,禁止绕出入口裸 fetch                          | 同 R1                                        |
| **R2 信封统一**           | 响应契约 `{ code, data }`,前端解包**唯一**走 `unwrapEnvelope`。禁止手写 `res.data`/`.then(r=>r.data)`                            | 解包逻辑重复、漂移                           |
| **R3 静态资源**           | `loadStatic`(超时 10s / TTL 5min / in-flight 去重 / LRU 上限 100)                                                                | 缓存/超时/校验缺失                           |
| **R4 数据源归属**         | 数据源模式由 `dataSourceConfig` 统一管理(全局 `VITE_DATA_SOURCE` + adapter 覆盖)。业务组件**不得**直接调 `apiRequest`/判断数据源 | 数据源语义散落                               |
| **R5 业务取数走 adapter** | 每个业务模块必须有 adapter(或书面豁免),业务组件经 adapter 取数                                                                   | 中间层不一致(曾经 site-selection 无 adapter) |

## 3. 后端响应规则

| 规则              | 内容                                                                                                                   | 违反后果                |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| **R6 成功出参**   | controller 一律 `sendSuccess(res, data)`,信封 `{ code, data }`                                                         | 前端解包失效            |
| **R7 错误出参**   | 错误抛 `BusinessError(code, message)` → 全局错误中间件统一映射 HTTP 状态码。禁止 controller 裸 `res.json`/`res.status` | 错误口径不一致          |
| **R8 读文件缓存** | 后端读 JSON 文件缓存统一 `createReadCache`(TTL + LRU 上限)。**禁止自研 cache Map**                                     | 缓存实现重复(曾经 4 套) |

## 4. 分层与入口规则

| 规则             | 内容                                                                                                                                       |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **R9 跨层收口**  | 跨层 import 走 index 入口(`@/shared` / `@/core` / `@/stores` / `@/services` / `@/business`),禁止深层路径穿透(已由 dependency-cruiser 校验) |
| **R10 依赖方向** | shared ← stores/services/core ← business ← 应用层,单向(已由 dependency-cruiser 校验,0 violation)                                           |

## 5. 数据源与数据文件

| 数据源 | 位置                            | 定位                                                                            |
| ------ | ------------------------------- | ------------------------------------------------------------------------------- |
| mock   | `frontend/public/data/*.json`   | 前端契约桩(带 `_contractVersion`,CI 校验),给前端独立开发/CI 用,随真数据接入退役 |
| api    | `backend/data/*.json`           | Express 数据(过渡存储,最终归属空间数据库 PostGIS)                               |
| online | FastAPI `backend/flood-service` | 真 DEM 演算(未来接数据库后成为唯一生产通路)                                     |

**mock 与 api 物理隔离**(不混放),但**契约必须一致**(⑤ 脚本校验)。

## 6. 新增业务模块清单(z075 manifest)

```
1. business/manifest.ts 加一条(路径/引擎/标题/导航/组件)
2. 建 business/<name>/ 模块目录(页面 + components + composables + constants)
3. services/adapters/<name>Adapter.ts(规则 R5)
4. stores/<name>Store.ts(如需要跨页状态)
5. types/ 补充业务类型
```

路由/导航/meta 由 manifest 自动生成,不需改 router/App.vue。
