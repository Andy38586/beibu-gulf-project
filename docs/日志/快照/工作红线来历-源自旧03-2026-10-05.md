## 原文（零改写）

1. **git**：禁 squash / 重写历史；禁 `git rm`；写前 `git bundle create` 备份——但**备份件只保留最新 1 份**：旧件先按"`git clone --bare` 临时库 + `git fetch <bundle> +refs/*:refs/p/*` + `git cherry main <sha>` 数无上游等价补丁"证明内容为 0，再删（2026-09-19 依此收敛 15 份重复 bundle ≈ 5.5G，旧件曾堆到 8G 无载体）；**判远端只信 `git ls-remote origin refs/heads/main`**（本地 `origin/*` ref 不可信，曾据此误判分支领先 134 提交）
2. **commit**：**禁 `--no-verify` / `--no-gpg-sign`**——husky 三钩子是守护本体（`pre-commit` 跑 lint-staged、`commit-msg` 跑 commitlint、`pre-push` 跑全量门禁），绕过等于关掉门禁（旧版本文曾写"一律 `--no-verify`"，那是钩子尚未生效时代的口径，已按实装纠正，冲突以 `.husky/*` 与 `AGENTS.md` §六 为准）；提交前 `npx prettier --write` 改动文件；`fix:` / `refactor:` 的 diff **必须含 test 文件**；message 用 **Conventional Commits** `type: 中文说明`（无 `type` 前缀会被 commitlint 拒，实测 `rc=1 subject-empty/type-empty`；**禁 `type(scope):` 括号写法**，由 commitlint 的 `scope-empty` 规则强制，口径单源见 §1.6）；禁用 issue 编号；每修一项即时提交
3. **依赖**：不新增 npm 依赖（除非作为决策项获批）；色值改动集中 `colors.ts`
4. **架构**：core / shared / stores 不可被 business 引用；business 模块只允许 Page.vue + composables + constants；**禁止跨文件重构**
5. **数据**：mock / 合成 / 未标记来源数据严禁入库；只接受合法来源 + 显式 source 标记
6. **审计口径**：结论必须挂 file:line 实证；无法确认标注【无法确认】；判第三方库行为必须实跑或读其源码；验证他人报告先核对路径存在
7. **本机环境**：前端 vitest 必须从 `frontend/` 目录跑（root 下 `@` alias 失败）；后端测试本机 12s 全绿
8. **push**：沙箱无凭据（GCM 调不起），commit 后由用户在终端 `git push origin main`；pre-push hook 会跑 typecheck×2 + guard:v3 + 后端测试，tmp-hygiene 会拦截工作区临时文件
9. **服务器**：阿里云 SWAS，1.6G 内存，**禁"重置系统"**（PG 数据卷全丢）；线上探测必须 `curl -k --noproxy '*'`
10. **中文处理**：用 Write 写 UTF-8 文件 + `git commit -F`（防 GBK 乱码）；git 命令走 Bash 工具
11. 每修一项打 `@arch-note` 标签留档；文档产出进 `docs/`（多数被 gitignore，不入库，属预期行为）
