- **目标**：部署只依赖 IMAGE_TAG（脱离服务器 git 工作树 `git pull`）；落 A-5 两件低风险改动：① 镜像预拉并行；② GHCR 仅保留最近 N 个 run tag（N=10，可改）。
- **前置检查**：

```bash
cd /opt/beibu-gulf && git status --porcelain | head
# 期望: 空（有未提交改动 ⇒ 先备份，别直接 pull）
grep -n "git pull" .github/workflows/ci.yml
# 期望: 命中 1 处（确认当前形态）
```

- **执行**（低峰窗口；CI 侧改动由本机出 diff，服务器只拉镜像/重启）：

```bash
docker compose -f docker-compose.v3.yml pull
# 期望: 三个镜像 Pulled / Up to date
docker compose -f docker-compose.v3.yml up -d --remove-orphans
# 期望: 三容器 healthy（docker ps 三行 Up）
curl -sk --noproxy '*' -o /dev/null -w '%{http_code}\n' https://<你的域名>/
# 期望: 200
docker inspect beibu-nest --format '{{.Config.Image}}'
# 期望: ghcr.io/andy38586/beibu-gulf-project:nest-<本次 run_number>
```

- **回滚**：把 `IMAGE_TAG` 覆盖回上一版 run tag 后 `docker compose up -d`；旧 tag 保留是目标之一。
- **失败处置**：健康检查不过 ⇒ 立即回滚，贴回 `docker logs --tail 100 beibu-nest`；部署 >15min 或身份不符 ⇒ 先回滚，不清理旧 tag。
- **验收钩子**：三容器 Up + 首页 200 + `imageTag` 精确等于本次 run tag + 旧 tag 仍在 `docker images`。
