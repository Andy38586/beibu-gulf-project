### 问题描述

**现象1：2D/3D切换后白屏**
- 从2D切换到3D后，Cesium容器为空，无地球显示
- 从3D切回2D后，OL容器也是白屏
- 控制台报错：`Cannot read property 'updateSize' of null`

**现象2：Cesium地球无法拖拽交互**
- Cesium地球可以显示，但无法拖拽、旋转、缩放
- 鼠标事件完全无法传递到Cesium canvas
- 控制面板按钮可以正常点击

### 事故原因分析

#### 原因1：容器尺寸等待机制缺失（白屏问题）

**技术细节**：
- `v-show` 切换后，Vue的 `nextTick()` 只保证DOM更新完成
- 但浏览器完成 layout/reflow（布局计算）需要额外时间
- 此时容器的 `offsetWidth/offsetHeight` 可能仍为0
- 渲染器在容器尺寸为0时初始化，导致白屏

**代码位置**：
- `src/core/map/UnifiedMap.vue` - `switchMapType()` 函数
- `src/core/map/renderers/CesiumRenderer.js` - `mount()` 方法

**根因**：
```javascript
// 错误实现（原代码）
await nextTick()  // 只保证DOM更新，不保证浏览器完成布局
const container = getContainer(newType)
await initRenderer(newType, container)  // 容器尺寸可能为0
```

#### 原因2：CSS pointer-events 穿透配置错误（拖拽失效）

**技术细节**：
1. **GCSAnalysisPage.vue** 使用了 `:deep(*)` 通配符选择器：
   ```css
   .gcs-analysis-page :deep(*) {
     pointer-events: none;
   }
   ```
   - 这个选择器的特异性（specificity）为 `(0,2,0)`
   - 会覆盖 UnifiedMap 的 `.map-container`（特异性 `(0,1,0)`）
   - 导致地图容器的 `pointer-events: auto` 被覆盖

2. **App.vue** 存在全局规则：
   ```css
   .app-content > * {
     pointer-events: auto;
   }
   ```
   - 让业务页面根元素也变成事件拦截层
   - 阻挡了下层地图容器的鼠标事件

3. **CesiumRenderer** 的 `requestRenderMode` 配置：
   ```javascript
   requestRenderMode: true  // 错误：拖拽时不渲染
   ```
   - 技术设计文档推荐 `requestRenderMode: true` 降低GPU占用
   - 但对于持续交互场景（拖拽/旋转），需要持续渲染

4. **相机控制器未显式启用**：
   - `screenSpaceCameraController` 的交互能力未显式设置
   - 某些浏览器/环境下默认值可能不正确

5. **地图容器未设置 pointer-events**：
   - `.map-container` 缺少 `pointer-events: auto`
   - 无法接收鼠标事件

#### 原因3：CesiumViewerManager.mount() 边界情况（HierarchyRequestError）

**技术细节**：
```javascript
// 错误实现（原代码）
mount(el) {
  const viewerContainer = this.viewer.container
  if (viewerContainer.parentNode !== el) {
    el.appendChild(viewerContainer)  // 如果 viewerContainer === el，会报错
  }
}
```

**问题**：
- 当 `viewerContainer` 就是 `el` 本身时
- `el.appendChild(viewerContainer)` 会抛出 `HierarchyRequestError`
- 因为不能将元素添加到自身

#### 原因4：Cesium API 版本变更

**技术细节**：
- Cesium 1.142 版本移除了 `EllipsoidTerrainProvider` API
- 原代码使用了该API创建地形提供者
- 导致初始化失败

### 解决方案

#### 修复1：添加容器尺寸等待机制

**文件**：`src/core/map/UnifiedMap.vue`

**实现**：
```javascript
/**
 * 等待容器元素获得实际尺寸（浏览器完成 layout/reflow）
 */
function waitForContainerVisible(container) {
  return new Promise((resolve) => {
    if (container && container.offsetWidth > 0 && container.offsetHeight > 0) {
      resolve()
      return
    }

    let attempts = 0
    const maxAttempts = 10
    const check = () => {
      attempts++
      if (container && container.offsetWidth > 0 && container.offsetHeight > 0) {
        resolve()
      } else if (attempts < maxAttempts) {
        requestAnimationFrame(check)
      } else {
        console.warn('waitForContainerVisible: 容器尺寸检查超时，继续执行')
        resolve()
      }
    }
    requestAnimationFrame(check)
  })
}

async function switchMapType(newType) {
  // 1. 先更新 mapStore.mapType，让 v-show 立即生效
  if (oldType !== newType) {
    mapStore.setMapType(newType)
  }

  // 2. 首次切换到3D时，v-if 创建 Cesium 容器
  if (newType === '3d' && !cesiumInitialized.value) {
    cesiumInitialized.value = true
    await nextTick()
    await nextTick()  // 双重 nextTick 确保 ref 绑定完成
  }

  // 3. 获取容器
  const container = getContainer(newType)

  // 4. 等待容器获得实际尺寸
  await waitForContainerVisible(container)

  // 5. 初始化渲染器
  await initRenderer(newType, container)
}
```

#### 修复5：处理 mount() 边界情况

**文件**：`src/core/map/renderers/CesiumRenderer.js`

**修改**：
```javascript
mount(el) {
  if (!this.viewer) return false
  if (!el) return false

  const viewerContainer = this.viewer.container

  // 如果 viewerContainer 就是 el 本身，说明已经在正确位置
  if (viewerContainer === el) {
    this.isMounted = true
    this.viewer.resize()
    this.viewer.scene.requestRenderMode = false
    this.viewer.scene.requestRender()
    this._enableCameraControls()
    return true
  }

  // 如果 viewerContainer 的父节点不是 el，需要移动到新容器
  if (viewerContainer && viewerContainer.parentNode !== el) {
    el.appendChild(viewerContainer)
  }

  this.isMounted = true
  this.viewer.resize()
  this.viewer.scene.requestRenderMode = false
  this.viewer.scene.requestRender()
  this._enableCameraControls()

  return true
}
```

### 经验总结

#### 1. CSS pointer-events 穿透机制

**最佳实践**：
- 业务页面根元素设置 `pointer-events: none`
- 面板组件设置 `pointer-events: auto`
- **禁止使用 `:deep(*)` 通配符**，会覆盖地图容器的事件设置
- 地图容器必须显式设置 `pointer-events: auto`

**正确示例**：
```css
.gcs-analysis-page {
  pointer-events: none;  /* 页面根元素穿透 */
}

.gcs-analysis-page :deep(.gcs-panel) {
  pointer-events: auto;  /* 面板恢复事件 */
}

.map-container {
  pointer-events: auto;  /* 地图容器接收事件 */
}
```

#### 2. 容器尺寸等待机制

**最佳实践**：
- `v-show` 切换后，不能仅靠 `nextTick()`
- 必须使用 `requestAnimationFrame` 等待浏览器完成布局
- 检查容器的 `offsetWidth/offsetHeight` 是否大于0

**正确示例**：
```javascript
async function switchMapType(newType) {
  mapStore.setMapType(newType)
  await nextTick()
  await nextTick()
  
  const container = getContainer(newType)
  await waitForContainerVisible(container)  // 等待容器获得实际尺寸
  await initRenderer(newType, container)
}
```

#### 3. Cesium 渲染模式双态策略

**最佳实践**：
- **可见时**：`requestRenderMode = false`（持续渲染，支持拖拽交互）
- **隐藏时**：`requestRenderMode = true`（按需渲染，降低GPU占用）

**正确示例**：
```javascript
// 创建时
new Viewer(container, {
  requestRenderMode: false,  // 可见时持续渲染
})

// 挂载时
mount(el) {
  this.viewer.scene.requestRenderMode = false
  this.viewer.scene.requestRender()
}

// 卸载时
unmount() {
  this.viewer.scene.requestRenderMode = true  // 隐藏时按需渲染
}
```

#### 4. DOM 操作边界检查

**最佳实践**：
- 在 `appendChild` 前检查元素是否已经在目标容器中
- 避免将元素添加到自身

**正确示例**：
```javascript
mount(el) {
  const viewerContainer = this.viewer.container
  
  // 检查是否已经在正确位置
  if (viewerContainer === el) {
    // 已经在正确位置，不需要移动
    return true
  }
  
  // 检查父节点
  if (viewerContainer.parentNode !== el) {
    el.appendChild(viewerContainer)
  }
}
```

#### 5. Cesium API 版本兼容性

**最佳实践**：
- 定期检查 Cesium 版本更新日志
- 使用 API 前检查是否已废弃
- 保留降级方案
