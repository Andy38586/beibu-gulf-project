## 1. 风险等级判据（P0-P3）

| 等级 | 判据 | 处置 |
| --- | --- | --- |
| **P0 阻断** | 生产路径功能失效 / 数据错误 / 安全漏洞 / 简历诚信冲突 | 立即修复，阻塞发布 |
| **P1 高危** | 正确性 / 稳定性 / 安全非致命 / 面试短板 / 防御失效 | 近期修复，进待解决 |
| **P2 中危** | 待改进 / 低危 bug / 语义不一致 | 排期修复，进待解决 |
| **P3 低危** | 接受 / 硬化 / 文档 / 视觉 nits | 可接受，或顺手修 |

**本体系特别约定**：防御分支失效、量纲错误、除零兜底死代码这类"看起来有防护、实际没有"的问题，**P1 起评**（比没有防御更危险）；跨专项一致性问题（如断点漂移、双份配置）按影响面定级。

## 2. 指标 11 字段结构

每条指标严格按以下 11 字段书写（8 份专项逐字一致）：

```
指标名称 / 检查目标 / 为什么需要检查 / 检查范围 / 检查方法 / 需要查看 /
正常标准 / 异常情况 / 风险等级 / 整改方向 / 验收标准
```

约定：检查方法必须可执行（含具体命令/路径）；异常情况给**可 grep 的模式描述**——反例一律进附录并标注取证日期（正文内嵌 file:line 反例违反 01 §六「禁止行号/清单进规范文档」，且随代码演进必然腐烂，2026-08-14 实锤：专项7 指标 1.2 三处反例全部失效）；验收标准必须可勾选。

> **附录隔离（2026-08-14 定，防锚定）**：子 agent 输入禁止包含本专项附录（判例 / 反例库 / 已知实锤 / 误判豁免 = 「答案册」，读了会锚定结论、漏真实问题）；附录仅主 agent 汇总与验收时使用。

- **零执行依赖**：8 个专项互相独立，可 8 窗口并行；交叉点只存在于"产出层面汇总"（发现合并、同根因去重），不在执行层面。
- **命令降级口径（2026-08-14 定）**：检查方法中的 `npm test`/`build`/`cruise` 等子进程命令在受限环境不可执行时（如沙箱 spawn 被拦），以静态替代取证（逐文件读断言、源码 import 梳理）并如实标注，禁止以"跑过"名义虚报；执行记录须注明受影响指标。
- **每份专项文档自带 0.6「Agent 并行执行契约」**：输入（本文档 + 代码范围）/ 输出（问题副本 + audits 执行记录）/ 子 agent 拆分（按 Part / 第 X 部分切分，规则见下）。
- **子 agent 拆分统一规则（2026-08-13 定，防 2~7 漂移）**：专项内二次并发以「部分」为原子单位，不再逐次临时拍脑袋。规则：① 默认 **1 部分 = 1 子 agent**；② **相邻部分证据重叠 >50%（共享同一批 service/store/types 文件）可合并为 1 个子 agent**；③ 单专项子 agent 数 **上限 6**（保护主 agent 汇总/同根因去重/统一定级这一步）；④ **禁止**把单个「部分」再拆成多个子 agent（二次拆分割裂共享证据、质量负收益）；⑤ **负载均衡**：相邻轻部分（正文 <150 行）可合并，单 slice 正文目标 150–500 行、切片间失衡比 ≤2x。各专项按自身部分数与证据耦合度取 3–6 个子 agent，而不是全部一刀切。
- **产出统一规范（2026-08-11 定，防分散）**：所有审查产出必须落在**单一批次目录** `docs/audits/<日期>-<批次名>/`；命名固定 `专项N-<专项名>-执行记录.md` 与 `专项N-<专项名>-问题副本.md`；**禁止**把产出散落到 docs 根目录、各专项目录或其他子目录；目录内不建子目录。**两级副本（2026-08-14 定）**：批次目录内 `专项N-*-问题副本.md` = 子 agent 工作副本；用户裁决前由主 agent 从批次目录聚合生成 `docs/问题副本-<日期>-<主题>.md`（待解决问题.md 头部规则的裁决副本），两处不重复书写。
- **执行记录**：标准库 372 个指标，执行记录必须 ≥ 1 份（分水岭是**跑过**，不是写出）；记录须含摘要（指标覆盖/发现总数/等级分布）、发现清单（指标/证据/等级/建议）、豁免清单。**摘要等级分布必须与同批次问题副本分节计数一致**（2026-08-14 定，防两文件漂移）。
- **指标演进口径（2026-08-29 定）**：项目演进产生新的可审查语义（新机制/新交互/新数据归属）时，对应专项**尾部追加**新指标（不重排既有编号、不改写旧指标——旧指标反例已按附录隔离机制防腐烂），11 字段齐全，本文件 §3 计数同步；指标废弃不删除、原地标注废弃与日期；新增专项才动 §3 索引表结构。
- **发现流转**：发现清单 → 问题副本（同批次目录内）→ 用户裁决 → 转正主台账（分配正式编号，discover = 批次日期）。
- **引用规范**：指标交叉引用写「专项N X.Y」；转派/溯源写「详见专项N 专项名」（00 §5 C 类，可附编号，如「专项2 生命周期 4.3」）；索引表可用简称。**禁止引用不存在的"主体系"**；禁止草稿/临时编号进文档与注释。
