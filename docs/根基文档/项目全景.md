## 一、项目身份

**北部湾港智慧选址分析平台** —— 面向智慧港口场景的 WebGIS 业务应用，验证"可扩展的 GIS 系统架构"而非单纯可视化 Demo。

- **定位**：最终目标是**有交付能力的产品**。当前阶段是"工程化搭壳"；后续以毕业论文为节点注入真研究（新选址分析 + 学术因子），同时作为求职作品集（WebGIS 开发 / 智慧城市数字孪生方向的目标项目）。
- **业务全景**：三类核心业务——选址分析（2D 空间运算）、预测分析（趋势可视化）、浸没分析（3D 淹没演算）。
  - 现有业务均为未来的**新选址分析**（港口选址 + 新因子研究）做铺垫：浸没、吞吐量预测是前哨。
  - 未完成板块：最短路径（需路网 + 港口码头 + 北部湾工业区多边形数据）、预测分析真模型（当前仅框架 + 合成示意数据）、海底 DEM（当前为陆地 DEM 填洼产物，需真实海底 DEM）、航线密集度分析等。
- **历史**：2026 年中学完 WebGIS 技术栈后启动，至 2026-08 约两个月。
- **阶段**：演示可用。距产品化还差两大鸿沟：**真实用户**与**真实业务**。
- **诚实性**：合成指标（预测数据为确定性种子合成的示意数据）是当前阶段的妥协，已知、已标注、面试主动讲，不回避也不自贬。

## 三、系统架构

### 3.1 分层（L0-L8，单向依赖）

```
L0  types          纯类型声明（零运行时依赖）
L1  shared         通用工具 / composable / 常量 / 基础组件
L2  stores         Pinia 全局状态
L3  services       数据访问（adapter / API 封装）
L4  visualization  通用图表资产
L5  core           地图核心 + 布局基座
L6  business       业务模块（互不依赖，manifest 注册）
L7  views          页面装配
L8  入口            main / router / App
```

铁律：**低层不得依赖高层**；`types/` 零运行时依赖；业务模块之间禁止互引。依赖方向由 `npm run cruise`（dependency-cruiser）强制守护。已知的设计确认例外（core→stores、core→services 等）见 02。

### 3.2 双引擎（Renderer 抽象）

- **问题**：2D/3D 引擎 API 完全不同，业务不能绑死某引擎。
- **方案**：`MapRenderer` 抽象接口，OL/Cesium 各一实现；业务经接口操作地图，引擎切换业务零改动。
- **哲学**：低功耗、低需求用 2D；有 3D 需求时优先 3D。Cesium 太重，不常驻。
- 单引擎专有能力（如水面）拆独立能力接口，调用方能力检查后使用，禁止空实现 stub。

### 3.3 请求路径（总览）

```
业务组件 → 取数入口（useApiRequest / loadStatic）
  ├─ 数据源 mock   → loadStatic（前端契约桩）
  ├─ 数据源 api    → fetch → Nest /nest-api/*
  └─ 数据源 online → fetch → FastAPI /flood-online
后端：modules → controllers → services（createReadCache 等读文件缓存）→ data/*.json
```

数据源三态是**演进路径**而非平行实现：mock 契约桩 → api JSON 过渡 → online 真演算 → 最终 PostgreSQL + GeoServer。

## 五、核心设计原则

1. **地理术语优先**：`lng/lat`（非 lon）、`elevation`、`feature`、`featureCollection`、`coordinates`——见 03 术语表。
2. **代码自解释，注释写"为什么"**：注释回答设计意图与地理背景，不写"做什么"。
3. **双引擎思维渗透命名**：凡可能 2D/3D 双实现，必须 Renderer / Adapter / Strategy 风格命名。
4. **图层统一经 BLM 管理**：业务图层注册 / 更新 / 显隐 / 移除一律走 BusinessLayerManager，禁止直接操作 renderer 图层。"注册即占位"：数据未就绪也可注册，数据到达后 updateData 补建。
5. **布局是网格约定，不是组件库**：GCS——所有面板尺寸 = 整数个 Cell + 锚点定位，禁止硬编码 px。
6. **状态进 store 的判据**：只有跨组件/跨页共享的状态进 Pinia；页面内临时状态用 ref。
7. **请求唯一入口**：API 走 `useApiRequest`、静态走 `loadStatic`，禁止裸 fetch；信封 `{code,data}` 解包唯一走 `unwrapEnvelope`。
8. **边界校验**：HTTP 响应 zod schema 必传（100%）；mock 数据带 `_contractVersion` 契约版本。
9. **后端读文件缓存统一** `createReadCache`，禁止自研 cache Map。
10. **跨层收口**：跨层 import 走 index 入口（`@/shared` / `@/core` / `@/stores` / `@/services` / `@/business` / `@/visualization`），禁止深路径穿透（Q4 816 拍板：全量收口，组件经 index 聚合导出；懒加载 `import()` 属构建优化保留深路径）。

- HTTP 边界 100% zod 校验。
