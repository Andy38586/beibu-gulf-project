# 近岸测深数据需求（2026-10-04，给建模端/数据端）

> **定位**：海侧高程的**航道级升级**数据需求。当前海侧 = SRTM15+（15″≈460m 原生）重采样
> 30m 的 15 倍上采样，接缝审计已证其**基准与陆地闭合**（两侧中位差 0.00m，2026-10-04 复验
> 逐位复现，`.local/seam-audit-rerun-20261004.txt`），但分辨率仅区域参考——
> `tools/dem-pipeline/11-seam-audit.py` 结论 #2：**不可用于航道级分析**。
> 本需求对应台账 p2-③ 的升级口径（SRTM15+ 已嵌 GEBCO 15″ 测深，本需求要的是
> 航道级近岸测深，非重复 GEBCO）。

## 二、数据规格

| 项           | 要求                                                                                                                                                                                                                    | 说明                                                                                                                               |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 数据类型     | 电子海图（ENC）水深注记 / 海图数字化水深 / 多波束成果网格，任一                                                                                                                                                         | 散点或网格皆可                                                                                                                     |
| 分辨率       | 网格 ≤100m，或等效密度散点（航道内 ≥1:10 万海图级）                                                                                                                                                                     | 现海侧 460m 的 5 倍以上加密                                                                                                        |
| **垂直基准** | **核心条款**：海图水深以**理论最低潮面**起算，与 EGM96 正高不同面。交付**必须二选一**：① 附本海域深度基准面 ↔ 1985 国家高程基准（或 EGM96）的基准改正数（逐站或区域常数）；② 直接换算为 EGM96 正高交付（负值=水面以下） | 钦州海区潮差大，基准面差值达米级——不换算则水深系统性偏差直接污染浸没/航道分析。对齐《陆海DEM高程数据需求-2026-09-27》的 EGM96 口径 |
| 水平基准     | WGS84 或 CGCS2000（注明）                                                                                                                                                                                               | 管线 CRS 口径                                                                                                                      |
| 格式         | GeoTIFF 网格，或 CSV（lng, lat, depth_m）；网格 nodata 须标注                                                                                                                                                           |                                                                                                                                    |
| 命名         | `bathy_<来源>_<分辨率m>_<垂直基准>.tif`（例 `bathy_enc20_lld_egm96.tif`）                                                                                                                                               | 对齐 DEM 需求书命名规范，管线按名识别                                                                                              |

## 三、验收判据（数据到位后由管线执行）

1. **基准换算核对**：交付附带基准改正数的，逐站核对改正数与潮汐基准资料；
   直接换算版抽查近岸水深与海图注记一致性。
2. **交叉对比**：新测深网格与现 SRTM15+ 海域网格做 0~20m 水深带差异报告
   （量级 + 空间分带）——差异即升级收益的量化。
3. **融合接缝审计重跑**：融合后 `11-seam-audit.py` 重跑，海岸线两侧中位差
   仍须为 0（融合不得破坏陆海接缝）。
4. **入库红线**：数据来源与基准声明缺一即拒收（同 p2-① 禁合成数据红线）。

## 四、交付方式

放入 `.local/dem-sea-work/`（gitignore），命名见上表；同时交付一份来源声明
（数据出处、测深年代、基准与换算方法）。管线侧融合脚本**已交付**：
`tools/dem-pipeline/14-bathy-fuse.py`（2026-10-04，含红线验收、LLD→EGM96 换算、
SRTM15+→新源空间衔接与 0~20m 分带差异报告；判据自检 `test_bathy_fuse.py` 7 例），
数据到位即可按 `tools/dem-pipeline/README.md` §四-b 三条命令执行；融合只写 `.local`，
`backend/data`/`backend/static` 的改写须另行点头。
