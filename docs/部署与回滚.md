# 部署与回滚（批次5 · d064/D-8 + d066/D-9）

> 适用：北部湾港 WebGIS 后端运维上线。本文档配合 `docker-compose.yml`、`scripts/rollback.sh`、CI `deploy` job 使用。

## 一、镜像版本 tag 策略（d064）

- `docker-compose.yml` 的 `image` 已改为 `beibu-gulf-webgis:${IMAGE_TAG:-latest}`。
- 部署新版本时显式传 `IMAGE_TAG`（建议格式 `YYYYMMDD-N`，如 `20260802-1`），便于回滚时精准指定。
- 本地一键构建运行仍可用 `docker compose up --build`（默认 `latest`）。

## 二、CI 自动部署（d066 / D-9=A）

CI 在 `main` 分支 `build` 成功后执行 `deploy` job：

1. `docker/setup-buildx-action` + `docker/login-action` 登录 `ghcr.io`（用 `GITHUB_TOKEN`，无需额外账号）。
2. `docker/build-push-action` 构建并推送两个 tag：
   - `ghcr.io/<owner>/<repo>:<github.sha>`
   - `ghcr.io/<owner>/<repo>:latest`
3. `curl` 触发**服务器 webhook**（`DEPLOY_WEBHOOK_URL` + `DEPLOY_WEBHOOK_TOKEN` secret），通知服务器拉取新镜像重启。

> ⚠️ 服务器侧需自备一个 webhook 接收器（小服务或并入部署脚本）：收到请求后执行
> `IMAGE_TAG=<sha> docker compose up -d --pull always`。CI 仅负责构建推送与通知，不直接操作生产机。
> 若服务器环境暂不可得，可退化为 B 方案（仅 `artifact` 上传，部署手动），不影响构建链路。

## 三、回滚演练（d064 / D-8=A）

前提：部署时已用版本 tag 打过镜像（见第一节）。

```bash
# 1. 备份当前数据卷（data 挂载在宿主机，先备份再回滚）
cp -r backend/data backend/data.bak-$(date +%Y%m%d)

# 2. 执行回滚脚本，切回上一版本镜像
./scripts/rollback.sh 20260802-1

# 3. 健康检查确认恢复
curl -fsS http://localhost:8080/api/health/ready   # 期望 {"status":"ready",...}
```

回滚脚本等价于：`IMAGE_TAG=<上一版本tag> docker compose up -d --pull always`。

## 四、注意事项

- 数据卷（`backend/data`）通过 `volume` 挂载，**不随镜像回滚**，保证用户/收藏/标记数据不丢。
- 运行时密钥（`JWT_SECRET`/端口）由 `env_file: ./backend/.env` 在容器运行期注入，绝不烘焙进镜像。
- 后端以非 root 用户 `nodeapp` 运行（d061）；数据卷在 entrypoint 启动前 `chown` 给 `nodeapp` 以保证可写。
