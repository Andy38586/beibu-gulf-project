## 待裁决发现（7 项）

### F-1 · 指标 4.2 状态单一来源 · P1 · open
- 证据：`business/flood-analysis/components/WaterLevelProfilePanel.vue:69` `const localWaterLevel = ref(floodStore.waterLevel)`；`:84-89` `watch(()=>floodStore.waterLevel, v=>localWaterLevel.value=v)`；`:333` `<ElSlider v-model="localWaterLevel">`；`:92-100` 写回 `floodStore.setWaterLevel`（图表 `:172` 直读 store）。
- 影响：水位数据在 `floodStore.waterLevel` 与本地 `localWaterLevel` 两处存在，靠 watch+写回掩盖分歧，脆弱。
- 建议：删 `localWaterLevel` 与 watch，改用可写 computed `waterLevelModel` 代理 store action。

### F-2 · 指标 2.2 state 修改入口收敛 · P1 · open
- 证据：`business/forecast/composables/useForecastRequest.ts:22` `forecastState.activeTransactionId += 1`；`:49/:72` 直改 `isRequesting`；store 无对应 setter action。
- 影响：事务状态绕过 action，DevTools 不可追踪，隐藏并发写入风险。
- 建议：在 `forecastStore` 增 `setIsRequesting`/`incrementTransactionId` action，composable 经 action 改 state。

### F-3 · 指标 2.6 store 重置机制 · P1 · open
- 证据：`stores/forecastStore.ts:123-141` `reset()` 未清快照（`:144` 注释刻意），对比 `stores/floodStore.ts:124` `clearState()` 清快照；登出路 `App.vue:67` 调 `reset()`。
- 影响：登出后 forecast 内存快照残留，同标签页再登录 `consumeState()` 恢复上一会话状态，违背 02 5.5，且与 flood 不一致。
- 建议：登出分支显式清快照（`consumeState()` 或新增 `resetAll()`），保持与 flood 一致。

### F-5 · 指标 5.2 闭包持有大对象 · P3 · open
- 证据：`core/map/renderers/CesiumRenderer.ts:394` 与 `:1255` `provider.errorEvent.addEventListener((err)=>{...})` 匿名箭头，无保存 remover、全文无对应 removeEventListener。
- 影响：单渲染器生命周期内闭包持有 `renderer`（大对象），不符「注册必有注销」；随 viewer.destroy 释放，风险低。
- 建议：保存 remover，图层移除/渲染器 destroy 时显式移除。

### F-6 · 指标 5.4 无限增长集合 · P3 · open
- 证据：`shared/utils/perfReporter.ts:105` 与 `:122` `if (IS_DEV) state.entries.push(...)`，模块级数组无 size 上限，仅 `_resetPerfForTest` 可清。
- 影响：dev 长会话 `entries` 累积占用内存。
- 建议：dev 明细加环形上限或按 name 聚合。

### F-7 · 指标 5.1 缓存大小限制 · P3 · open
- 证据：`stores/forecastStore.ts:53` `dataCache` Map 无 size 上限；全仓无 `.set` 写路径（休眠态）；`currentData` computed 恒为 null。
- 影响：违反「每缓存有上限」常态，疑似功能缺口。
- 建议：启用则补 LRU，或移除该 state + `currentData`。

### F-8 · 指标 7.3 请求竞态 · P3 · open（校准/文档类）
