# 一、面向求职（面试怎么说、简历怎么写）

> 核心策略：**诚实 + 深度 > 完美话术**。面试官不怕项目有短板，怕的是被戳穿还圆不回来。把"被发现夸大"转化为"展示工程成熟度"。

## 1.1 项目定位话术（开场 30 秒）

不要说"企业级 WebGIS 平台"，要说：

> 「这是一个**架构能力验证型 WebGIS 前端**。我用 Vue3 + Pinia + OpenLayers + Cesium 做了双引擎（2D/3D）地图，抽象出 Renderer / BusinessLayerManager / DataAdapter 三层，验证了'新增业务模块零改核心引擎'的架构主张。三个业务模块（选址 / 预报 / 洪涝）跑通了真实前后端联调，数据是 demo 级的静态样例集，预留了真实数据适配器。」

这句话同时亮出：**架构主张 + 技术栈 + 诚实边界**，比堆功能更有谈资。

## 1.3 主动暴露缺点的策略（比藏着强十倍）

被问"项目最大不足"时，**主动说这两点并展示 root cause + 修复量**：

2. **引擎切换丢图层 D06**（已修）：`BusinessLayerManager.register:67-69` 对已有 key `warn+return` 且无重应用路径 → 2D↔3D 切换洪水图层丢失。已加 `reapplyAll(renderer)`。

## 1.4 抽象答辩速查（每个抽象都要答"为什么需要 / 没有会怎样"）

| 抽象 | 为什么需要（标准答） | 承认的债（压力追问时主动说） |
|---|---|---|
| **Renderer（MapRenderer 基类）** | 隔离 OL/Cesium API 差异；业务不直接碰底层地图 API；路由级 2D/3D 切换；测试可 mock renderer | 基类是胖接口，3D 专用方法（`addWaterSurface/startBreathing`）泄漏进核心，OL 只能空实现 `return false` |
| **BusinessLayerManager** | 2D/3D 切换时图层生命周期由谁统一编排（否则丢图层 D06） | 仅 3 个使用者，抽象成本需量化 |
| **DataAdapter** | mock↔api 可切换，隔离业务与数据源 | `api` 分支直接 `throw`（空壳）；flood "mock" 实际打后端 `/gcs`；项目共存三套数据访问范式（adapter / `useApiRequest` / `fetch`） |
| **GCS 布局** | 地图画布上的浮层锚定 + 单一 resize 真源 | 换成 CSS Grid + `position:fixed` 能覆盖 90% 场景，是首要过度设计嫌疑 |
| **mapStore** | 跨组件共享图层目录 / 引擎态 | 双图层注册机制并行（`registerToggleable` 旧 vs `registerBusinessLayer` 新），`registerBusinessLayer` 为权威 |

| # | 问题 | 标准回答要点 |

## 2.4 关键技术点原理补强（不只记结论，要懂为什么）

- **接口隔离原则**：基类把 3D 专用方法强加给 OL，违反 ISP → 理解"抽象应按使用者最小需求设计"。
- **`shallowRef` vs `ref([])`**：图层目录是大型对象数组，浅响应避免深层代理开销（`layerCatalog` 应 `shallowRef`）。
- **rbush 阈值 1000 vs 数百要素**：R 树建树有成本，数据量未达阈值时索引零收益，属"提前量"——理解"优化要对准量级"。
- **turf 主线程阻塞**：数百要素可接受；万级要素应移 WebWorker，避免 UI 卡顿。
- **ErrorBoundary 该包地图**：`UnifiedMap` 崩溃若只包 `RouterView` 会白屏；错误边界应覆盖真实崩溃源。

# 三、面向精简文档（项目如实技术说明，替代脱节老 README）

> 用途：作为项目真实说明书 / 新人 onboarding / 面试递给面试官的技术概览。客观、准确、不夸大。

## 3.1 项目概述

北部湾港 WebGIS 智慧分析平台（**架构验证阶段**）。前端 Vue3 + Pinia + OpenLayers + Cesium + ECharts + Turf.js，后端单体 Express + 静态 JSON。提供三个业务模块：港口选址分析、预报可视化、内涝评估。核心架构主张：**双引擎（2D/3D）地图 + 业务层零改核心引擎的可扩展设计**。

## 3.2 技术栈

| 层 | 技术 |
|---|---|
| 前端框架 | Vue 3 + Pinia + Vite |
| 2D 地图 | OpenLayers（Canvas） |
| 3D 地图 | Cesium（WebGL，运行时动态加载） |
| 图表 | ECharts |
| 空间计算 | Turf.js（后端为主，前端无引用） |
| 后端 | Express + 静态 JSON（验证阶段） |
| 工程化 | ESLint + Prettier + Vitest + CI（lint/typecheck/test/build） |

## 3.3 架构分层（依赖单向：business → core，core 不依赖 business）

```
business/   业务模块（site-selection / forecast / flood-analysis）
   ↓
core/       map（Renderer 抽象 / BusinessLayerManager / UnifiedMap）、layout（GCS）
   ↓
shared/     components / composables / utils / constants（colors.ts 集中色）
services/adapters/   DataAdapter（mock / api 切换，api 未实现）
stores/     8 个 Pinia Store（mapStore 为枢纽）
router/     路由 + meta.engine 配置
renderers/  OLRenderer（604 行）/ CesiumRenderer（872 行），仅此目录依赖具体引擎 API
```

- **Renderer 抽象**：`MapRenderer` 基类 + `createRenderer` 工厂，业务层不直接 import `ol`/`cesium`。
- **BusinessLayerManager**：统一编排图层生命周期，2D/3D 切换经 `reapplyAll` 重应用。
- **DataAdapter**：隔离业务与数据源；`mock` 读静态 fixture，`api` 分支待实现。

## 3.4 三个业务模块（如实说明）

| 模块 | 输入 | 处理 | 输出 | 真实性 |
|---|---|---|---|---|
| 选址 | 6 类设施 + 权重 | 后端 Turf 缓冲+并集+交集+加权打分 | Top10 小区 + 雷达图 | 真闭环（数据静态） |
| 预报 | 指标 + 时间轴 | 读 mock 时间序列 JSON + 播放 | 折线/柱状 + 动画 | 弱（无预测模型） |
| 洪涝 | 7 档水位滑杆 | 后端按水位返回预生成多边形 + 受影响设施 | 淹没面 + 设施清单 | 混合（DEM 模拟，非实时分析） |

## 3.5 已知限制（诚实列出）

- 数据集为 demo 级（数百要素），R 树空间索引当前不触发（阈值 1000）。
- 自动化测试覆盖薄（4 文件，核心 renderer/adapter/store 无直接单测），coverage 无门槛。
- `DataAdapter.api` 分支未实现（`throw`）；洪涝"mock"历史上有语义混乱（已统一为静态 fixture）。
- 无独立性能实测（帧率 / 内存）。
- 渲染器仍为 `.js` 且 `checkJs:false`，类型网未全覆盖。
- 大数据方案（矢量瓦片 / 聚合 / WebWorker）未落地。
