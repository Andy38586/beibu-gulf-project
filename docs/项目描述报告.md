> **文档版本**：v1.0

## 一、项目概述

### 1.1 项目定位

这是一个面向北部湾港口群（钦州港、北海港、防城港）的WebGIS综合分析平台，核心目标是提供港口运行态势展示、空间决策分析和未来趋势预测的完整决策链。

**三大业务模块**：

- **首页（Home）**：港口运行态势展示（当前状态）
- **选址分析（SiteSelection）**：空间决策分析（空间规划）
- **三维港口分析（GCSAnalysis）**：三维港口沉浸式分析（水位模拟、剖面分析、淹没分析、港口影响评估）
- **预测分析（Forecast）**：时间趋势分析（未来预测）- 规划中

四者共同形成：**当前状态 → 空间规划 → 三维沉浸 → 未来预测** 的完整决策链。

### 1.2 设计原则

| 原则           | 说明                                             |
| -------------- | ------------------------------------------------ |
| **地图为主角** | 地图永远是系统主体，UI面板是浮层，不是背景图     |
| **布局继承**   | 所有业务路由继承Home Layout，只替换业务内容      |
| **组件复用**   | 可视化组件、布局组件都是项目资产，禁止复制后改名 |
| **按需加载**   | Cesium不独立页面，根据路由按需初始化             |
| **引擎无关**   | 数据层引擎无关，图层对象按引擎重建               |

## 三、核心架构设计

### 3.1 策略模式：地图引擎抽象

**核心问题**：系统需要同时支持OpenLayers（2D）和Cesium（3D）两个地图引擎，且未来可能扩展Mapbox等其他引擎。

**解决方案**：策略模式 + 抽象基类

```javascript
// src/core/map/renderers/MapRenderer.js
export class MapRenderer {
  constructor(container) {
    if (new.target === MapRenderer) {
      throw new Error('MapRenderer是抽象类，不能直接实例化')
    }
    this.container = container
    this._layers = new Map()
    this._eventBus = new EventTarget()
  }

  // 抽象方法：子类必须实现
  async init() {
    throw new Error(`${this.getType()} init 未实现`)
  }
  addPointLayer(_id, _features, _options = {}) {
    throw new Error('未实现')
  }
  addPolygonLayer(_id, _features, _options = {}) {
    throw new Error('未实现')
  }
  addGeoJsonLayer(_id, _geojson, _options = {}) {
    throw new Error('未实现')
  }

  // 通用方法：子类继承
  setVisibility(id, visible) {
    const layer = this._layers.get(id)
    if (layer) {
      layer.visible = visible
      this._doSetVisibility(id, visible)
    }
  }

  removeLayer(id) {
    const layer = this._layers.get(id)
    if (layer) {
      this._doRemoveLayer(layer)
      this._layers.delete(id)
    }
  }

  flyTo(target, options = {}) {
    const normalizedTarget = this._normalizeFlyToTarget(target)
    this._doFlyTo(normalizedTarget, options)
  }

  // 事件系统
  on(event, handler) {
    this._eventBus.addEventListener(event, handler)
  }
  off(event, handler) {
    this._eventBus.removeEventListener(event, handler)
  }
  emit(event, data) {
    this._eventBus.dispatchEvent(new CustomEvent(event, { detail: data }))
  }

  // 状态导出/导入（引擎切换时保留图层可见性）
  exportState() {
    /* ... */
  }
  importState(state) {
    /* ... */
  }
}
```

**两个具体实现**：

1. **OLRenderer**（OpenLayers 2D）：
   - 使用`ol/Map`、`ol/View`、`ol/layer/Vector`
   - 坐标系：EPSG:3857（Web Mercator）
   - 底图：天地图瓦片（XYZ格式）

2. **CesiumRenderer**（Cesium 3D）：
   - 使用`Viewer`、`Entity API`
   - 坐标系：WGS84（经纬度）
   - 底图：天地图瓦片（UrlTemplateImageryProvider）
   - **单例缓存**：CesiumViewerManager管理全局唯一Viewer实例

### 3.2 如何添加新引擎（以Mapbox为例）

**步骤**：

1. **创建MapboxRenderer.js**：

```javascript
import { MapRenderer } from './MapRenderer'
import mapboxgl from 'mapbox-gl'

export class MapboxRenderer extends MapRenderer {
  constructor(container) {
    super(container)
    this.map = null
    this._initMap()
  }

  _initMap() {
    this.map = new mapboxgl.Map({
      container: this.container,
      style: 'mapbox://styles/mapbox/streets-v11',
      center: [108.62, 21.95], // 北部湾中心
      zoom: 9,
    })
  }

  async init() {
    return new Promise((resolve) => {
      this.map.on('load', resolve)
    })
  }

  addPointLayer(id, features, options = {}) {
    // 实现Mapbox的点图层添加逻辑
    this.map.addLayer({
      id,
      type: 'circle',
      source: { type: 'geojson', data: { type: 'FeatureCollection', features } },
      paint: {
        'circle-radius': options.size || 12,
        'circle-color': options.color || '#409eff',
      },
    })
    this._layers.set(id, { instance: id, visible: true, options })
  }

  addPolygonLayer(id, features, options = {}) {
    /* ... */
  }
  addGeoJsonLayer(id, geojson, options = {}) {
    /* ... */
  }

  _doSetVisibility(id, visible) {
    this.map.setLayoutProperty(id, 'visibility', visible ? 'visible' : 'none')
  }

  _doRemoveLayer(layer) {
    this.map.removeLayer(layer.instance)
  }

  _doFlyTo(target, options = {}) {
    if (target.layerId) {
      // 飞到图层范围
      const bounds = this.map.getSource(target.layerId)?._data
      if (bounds) this.map.fitBounds(bounds, { duration: 1000 })
    } else {
      this.map.flyTo({
        center: [target.lng, target.lat],
        zoom: options.zoom || 9,
        duration: 1000,
      })
    }
  }

  getType() {
    return 'mapbox'
  }
  getMap() {
    return this.map
  }
  updateSize() {
    this.map?.resize()
  }
  destroy() {
    super.destroy()
    this.map?.remove()
    this.map = null
  }
}
```

2. **在工厂函数中注册**：

```javascript
// src/core/map/renderers/index.js
import { OLRenderer } from './OLRenderer'
import { CesiumRenderer } from './CesiumRenderer'
import { MapboxRenderer } from './MapboxRenderer' // 新增

export async function createRenderer(type, container) {
  switch (type) {
    case '2d':
      return new OLRenderer(container)
    case '3d':
      return new CesiumRenderer(container)
    case 'mapbox':
      return new MapboxRenderer(container) // 新增
    default:
      throw new Error(`未知的渲染器类型: ${type}`)
  }
}
```

3. **在路由meta中指定引擎**：

```javascript
// src/router/index.js
{
  path: '/mapbox-demo',
  name: 'MapboxDemo',
  component: () => import('@/business/mapbox-demo/MapboxDemoPage.vue'),
  meta: { engine: 'mapbox', title: 'Mapbox演示' }  // 指定引擎
}
```

4. **UnifiedMap自动处理**：
   - UnifiedMap.vue会根据`route.meta.engine`自动创建对应渲染器
   - 无需修改UnifiedMap代码

**关键设计**：

- 数据层（GeoJSON）引擎无关，可跨引擎共享
- 图层对象（OL Layer、Cesium Entity、Mapbox Layer）按引擎重建
- 切换引擎时：数据保留 → 销毁旧图层对象 → 用新渲染器重建

## 四、GCS布局系统

### 4.1 Cell概念

**Cell是UI布局度量单位，不是GIS空间网格**。

```
1 Cell = 80px（默认值，响应式可调）

用途：
- 面板大小定义（如4×4 Cell = 320px × 320px）
- 布局排列（Panel间距 = 2×GAP = 20px）
- 响应式设计（根据视口宽度动态调整CELL_PIXEL）

响应式断点：
- >= 1920px → CELL_PIXEL = 90
- >= 1366px → CELL_PIXEL = 80
- >= 1024px → CELL_PIXEL = 80
- >= 768px  → CELL_PIXEL = 70
- < 768px   → CELL_PIXEL = 60
```

### 4.2 Panel系统（一切皆Panel）

**核心思想**：标题、图表、按钮、Dock都是Panel实例，不存在Zone/Area/Container。

**GcsPanel组件**：

```vue

<script setup>
import { computed } from 'vue'
import { useGCS } from '../useGCS.js'

const props = defineProps({
  w: { type: Number, required: true }, // 宽度（Cell单位）
  h: { type: Number, required: true }, // 高度（Cell单位）
  anchor: { type: String, default: 'top-left' }, // 锚点
  offsetX: { type: Number, default: 0 }, // 水平偏移（Cell单位）
  offsetY: { type: Number, default: 0 }, // 垂直偏移（Cell单位）
})

const { cellPixel, panelPosition } = useGCS()

// PPS（Panel Position System）计算位置
const panelStyle = computed(() => {
  const pos = panelPosition(props.w, props.h, props.anchor, props.offsetX, props.offsetY)
  return {
    position: 'absolute',
    left: pos.left,
    top: pos.top,
    width: pos.width,
    height: pos.height,
    borderRadius: `${cellPixel.value * 0.15}px`,
    backgroundColor: '#ffffff',
    boxShadow: '0 2px 8px rgba(0, 0, 0, 0.1)',
  }
})
</script>

<template>
  <div class="gcs-panel" :style="panelStyle">
    <slot />
  </div>
</template>
```

**PPS（Panel Position System）公式**：

```
C = cellPixel（当前Cell像素值）
S = PANEL_SPACING（Panel间距 = 20px）
W = windowWidth（视口宽度）
H = windowHeight（视口高度）

锚点计算：
- top-left:      left = S + offsetX*C,          top = S + offsetY*C
- top-right:     left = W - S - (offsetX+w)*C,  top = S + offsetY*C
- top-center:    left = (W - w*C) / 2,          top = S + offsetY*C
- bottom-center: left = (W - w*C) / 2,          top = H - S - (offsetY+h)*C
- bottom-left:   left = S + offsetX*C,          top = H - S - (offsetY+h)*C
- bottom-right:  left = W - S - (offsetX+w)*C,  top = H - S - (offsetY+h)*C
```

### 5.1 复用优先级

**原则**：复用 > 组合 > 扩展 > 新建；禁止复制组件后改名字。

### 5.2 可视化组件复用

**LineChart/BarChart/RadarChart**都是项目资产，所有业务路由都可以直接调用。

**关键设计**：

- 组件对数组props使用浅监听而非deep watch，优化性能
- ECharts实例在组件unmount时自动dispose，防止内存泄漏
- 组件只接收数据，不关心数据来源（与业务解耦）

### 5.3 布局组件复用

**GcsPanel**是所有Panel的容器，所有业务路由都使用它定位Panel。

**AppLayout**是布局基座，所有业务路由都继承它。

### 5.4 业务路由继承

**新增业务时的判断流程**：

1. **判断是否需要地图作画**：
   - 如果需要，判断现有渲染器接口能否满足
   - 如果能满足 → 不改地图组件，直接用`useMapControls`获取渲染器作画
   - 如果不能 → 新增渲染器方法（在MapRenderer基类添加抽象方法，在OLRenderer和CesiumRenderer分别实现）

2. **判断是否需要新路由**：
   - 如果需要 → 创建新路由，继承AppLayout
   - 通过`route.meta.engine`指定引擎（2d/3d）
   - 通过`<slot>`注入业务Panel

3. **判断是否需要新可视化组件**：
   - 如果现有LineChart/BarChart/RadarChart能满足 → 直接复用
   - 如果不能 → 创建新组件，放在`src/visualization/charts/`下，成为项目资产

```typescript
// src/shared/composables/useApiRequest.ts
import { ref, computed } from 'vue'
import type { Ref, ComputedRef } from 'vue'

export enum ErrorCode {
  TIMEOUT = 'TIMEOUT',
  NETWORK_ERROR = 'NETWORK_ERROR',
  UNAUTHORIZED = 'UNAUTHORIZED',
  SERVER_ERROR = 'SERVER_ERROR',
  REQUEST_FAILED = 'REQUEST_FAILED',
}

export class ApiError extends Error {
  constructor(
    message: string,
    public code: ErrorCode,
  ) {
    super(message)
    this.name = 'ApiError'
  }
}

const token: Ref<string> = ref('')
const API_BASE: string = import.meta.env.VITE_API_BASE || '/api'

export function useApiRequest() {
  async function apiRequest<T = unknown>(path: string, options: RequestInit = {}): Promise<T> {
    const headers: Record<string, string> = {
      'Content-Type': 'application/json',
      ...options.headers,
    }

    if (token.value !== '') {
      headers['Authorization'] = `Bearer ${token.value}`
    }

    const controller = new AbortController()
    const timeoutId = setTimeout(() => controller.abort(), 10000)

    try {
      const res = await fetch(`${API_BASE}${path}`, {
        ...options,
        headers,
        credentials: 'include',
        signal: controller.signal,
      })
      clearTimeout(timeoutId)

      const data = await res.json().catch(() => ({}))

      if (res.status === 401) {
        throw new ApiError('登录已过期，请重新登录', ErrorCode.UNAUTHORIZED)
      }

      if (!res.ok) {
        throw new ApiError(data.error || `请求失败 HTTP ${res.status}`, ErrorCode.REQUEST_FAILED)
      }

      return data as T
    } catch (error) {
      clearTimeout(timeoutId)
      if (error instanceof Error && error.name === 'AbortError') {
        throw new ApiError('请求超时，请稍后重试', ErrorCode.TIMEOUT)
      }
      throw error
    }
  }

  return { apiRequest, token }
}
```

### 6.4 为什么不全用TypeScript

- **历史原因**：项目初期用JavaScript，后期引入TypeScript
- **渐进式迁移**：优先在类型定义和composables中使用TypeScript
- **Vue组件**：仍使用`<script setup>`（JavaScript），保持简洁

### 7.2 Cesium性能优化

**问题**：Cesium体积大（~5MB JS）、GPU占用高（200~400MB内存）。

**解决方案**：单例缓存 + 按需挂载 + 渲染暂停。

```javascript
// src/core/map/renderers/CesiumRenderer.js
class CesiumViewerManager {
  constructor() {
    this.viewer = null
    this.isMounted = false
  }

  create(container) {
    if (this.viewer) return this.viewer // 单例
    this.viewer = new Viewer(container, {
      requestRenderMode: false, // 首次创建时持续渲染
      // ...
    })
    return this.viewer
  }

  mount(el) {
    if (!this.viewer) return false
    // 挂载到DOM
    el.appendChild(this.viewer.container)
    this.isMounted = true
    this.viewer.scene.requestRenderMode = false // 恢复持续渲染
    this.viewer.resize()
    return true
  }

  unmount() {
    if (!this.viewer || !this.isMounted) return
    // 从DOM移除（不销毁Viewer）
    this.viewer.container.parentNode.removeChild(this.viewer.container)
    this.isMounted = false
    this.viewer.scene.requestRenderMode = true // 暂停渲染，降低GPU占用
  }

  destroy() {
    if (this.viewer) {
      this.unmount()
      this.viewer.destroy()
      this.viewer = null
    }
  }
}
```

**性能对比**：

| 方案         | 首屏加载 | 切换速度  | 内存占用      | 状态保留 |
| ------------ | -------- | --------- | ------------- | -------- |
| v-show共存   | +5MB     | 瞬间      | 常驻200~400MB | 天然     |
| v-if重建     | 0        | 2~3秒     | 用时才有      | 丢失     |
| **单例缓存** | **0**    | **0.5秒** | **用时才有**  | **保留** |

## 八、总结

### 8.1 项目亮点

1. **策略模式**：地图引擎抽象，支持OpenLayers、Cesium，未来可扩展Mapbox等
2. **布局继承**：Home Layout作为基座，所有业务路由继承，最大化组件复用

5. **组件复用**：可视化组件、布局组件都是项目资产，禁止复制后改名

### 8.2 技术债务

1. **TypeScript覆盖不全**：部分composables和所有Vue组件仍用JavaScript
2. **数据规模限制**：当前使用JSON文件存储，未引入空间索引和PostGIS
3. **测试覆盖不足**：仅有少量单元测试，缺乏集成测试和E2E测试

### 8.3 未来演进方向

1. **新增业务**：预测分析（Forecast）、航线分析（RouteAnalysis）
