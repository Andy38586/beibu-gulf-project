## 十、P0-02 修复方案（唯一剩余阻断级问题）

### 问题简述

`/api/markers` 接口存在三处安全漏洞：
1. **GET `/api/markers`**：无认证中间件，匿名用户可获取全量标记数据
2. **PUT/DELETE**：仅校验登录状态（`authenticate` 中间件），不校验操作者是否为标记所有者
3. **更新白名单**：`markersRepository.js:62` 包含 `'userId'`，允许调用方篡改标记归属

### 修复步骤

```bash
# 1. server/routes/markers.js — GET 加认证
# 2. server/controllers/markersController.js — PUT/DELETE 加归属校验
# 3. server/repositories/markersRepository.js — 白名单移除 'userId'
```

### 风险评估

| 风险 | 概率 | 缓解 |
|---|---|---|
| 修复后前端标记列表突然为空（未登录） | 低 | 前端已有登录判断逻辑（PaginatedListPanel 在收藏前检查登录态），加上 `401` 响应后 `useApiRequest` 已有拦截处理 |
| 白名单移除 `userId` 导致已保存标记的 owner 字段丢失 | 无 | 白名单是**允许更新的字段列表**，移除只是禁止客户端篡改，不影响已有数据 |

### 改动量

约 10-15 行，3 个文件，预计 30 分钟（含测试验证）。
