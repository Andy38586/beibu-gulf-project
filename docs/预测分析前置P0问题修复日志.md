## 修改详情

### P0-1：渲染器接口补全

#### 1. `src/core/map/renderers/MapRenderer.js`（+49 行）

基类新增 7 个水面操作方法，均返回 `false` + dev 警告：

| 方法 | 参数 | 说明 |
|---|---|---|
| `addWaterSurface` | `_id, _coordinates, _height = 0, _options = {}` | 添加水面 |
| `updateWaterLevel` | `_id, _newHeight` | 更新水位 |
| `removeWaterSurface` | `_id` | 移除单个水面 |
| `removeAllWaterSurfaces` | — | 移除所有水面 |
| `setWaterSurfaceVisibility` | `_id, _visible` | 设置水面可见性 |
| `startBreathing` | `_lng, _lat` | 开始呼吸动画 |
| `stopBreathing` | — | 停止呼吸动画 |

代码规范：未使用参数统一加 `_` 前缀。

#### 2. `src/core/map/renderers/OLRenderer.js`（+35 行）

新增 5 个水面桩方法（`startBreathing`/`stopBreathing` 已有）：

| 方法 | 参数 | 行为 |
|---|---|---|
| `addWaterSurface` | `_id, _coordinates, _height, _options` | 打印 dev 警告 + 返回 false |
| `updateWaterLevel` | `_id, _newHeight` | 同上 |
| `removeWaterSurface` | `_id` | 同上 |
| `removeAllWaterSurfaces` | — | 同上 |
| `setWaterSurfaceVisibility` | `_id, _visible` | 同上 |

代码规范：和基类保持一致，未用参数加 `_` 前缀。

#### 3. `src/business/flood-analysis/FloodAnalysisPage.vue`（-14 行）

移除全部 7 处 `getType()` 引擎类型嗅探，改为统一调用 `renderer.xxx()` — 多态分发：

```diff
- if (renderer.getType() === 'cesium') {
-   renderer.addWaterSurface(...)
- }
+ renderer.addWaterSurface(...)  // 直接调用，OLRenderer 返回 false
```

**保留的 guard**：`if (!renderer)` null 检查保留，兼容渲染器未初始化时的调用。

#### 4. `src/core/map/UnifiedMap.vue`

无变更。`rendererReady` 方案因兄弟节点 provide/inject 限制已放弃，时序保护完全依赖 `watch(() => mapStore.currentRenderer?.value, ...)` + `{ immediate: true }`（在业务页面自行处理）。

### P0-2：Core→Business 依赖切断

#### 1. `src/core/map/UnifiedMap.vue`（-7 行）

移除 core 层对 business 的全部引用：

```diff
- import { useAnalysisLayer } from '@/business/...'
- const { createUpdateHandler } = useAnalysisLayer()
- // ...setupLayers 末尾的 handler 注册代码
```

#### 2. `src/business/site-selection/SiteSelectionPage.vue`（+10 行）

改由业务层在 `setup` 顶层调用 composable：

```diff
- import { createUpdateHandler } from './composables/useAnalysisLayer'
+ import { useAnalysisLayer } from './composables/useAnalysisLayer'
+ const { createUpdateHandler } = useAnalysisLayer()
```

在 `handleResult` 首次收到分析结果时注册 handler：

```js
function handleResult(result) {
  const renderer = mapInstance.value?.getRenderer?.()
  if (renderer && !mapStore.analysisHandler?.value) {
    const updateHandler = createUpdateHandler(renderer, registerToggleable)
    mapStore.registerAnalysisHandler(updateHandler)
  }
  mapStore.setAnalysisResult(result)
  // ...
}
```

## 与实施文档的偏差

实际实现与 `docs/预测分析前置P0问题解决实施文档.md` 有以下不同：

| # | 实施文档 | 实际实现 | 原因 |
|---|---|---|---|
| 1 | OLRenderer 新增 7 个方法 | 只新增 5 个水面方法 | `startBreathing`/`stopBreathing` 已存在 |
| 2 | 新建 `rendererReady.ts` key 文件 | 未新建 | `MapRendererKey` 已在 `useMapRenderer.js` 导出 |
| 3 | `FloodAnalysisPage` 用 `inject('rendererReady')` 替代 `setTimeout` | 完全依赖 `watch(() => mapStore.currentRenderer?.value, ...)` + `{ immediate: true }`，不引入 `rendererReady`/`setTimeout` | `UnifiedMap` 和 `RouterView` 在 `App.vue` 中是兄弟节点，`provide` 不能跨兄弟传递；且 `currentRenderer` watch 已覆盖全部时序 |
