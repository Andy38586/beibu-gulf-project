### ⚠ 静默变更 1：registerGcsLayers 新增分析触发 + floodFeatures 自动渲染

**位置**：`FloodAnalysisPage.vue:108-124`

```javascript
// 注册后重新触发一次分析（确保图层注册后数据到达）
analysisTimer = setTimeout(() => {
  triggerFloodAnalysis(waterLevelStore.waterLevel)
  triggerImpactAssessment(waterLevelStore.waterLevel)
}, ANALYSIS_DELAY)

// 一次监听 floodFeatures，数据到达后自动渲染
const unwatch = watch(
  () => floodStore.floodFeatures,
  (features) => {
    if (features && features.length > 0) {
      renderFloodAreas(features)
      unwatch()
    }
  },
  { immediate: true },
)
```

**原因**：原始版本只在渲染器就绪时注册图层开关，不触发分析。API 可能在渲染器就绪前返回（慢网络场景），数据到了但无人渲染。实施中发现此问题，补充两段逻辑：
- `setTimeout`：图层注册后补发一次分析
- `floodFeatures` watch（一次监听，自动解除）：数据到达即渲染

### 🐛 BUG-2（实施中发现）：stateRestored 时序漏洞

#### 发现问题

`stateRestored` 标志能拦截 `onMounted` 中 `setWaterLevel()` 触发的 watch，但**无法阻止 `{immediate: true}` watch 在 setup 阶段已经排入的防抖回调**：

```
时序线：
setup  ──→ immediate watch 触发 → analysisTimer = setTimeout(trigger, 500ms) ①
mount  ──→ onMounted → stateRestored=true → setWaterLevel(5m)
         → watch 被 stateRestored 拦截 → 未排入新 setTimeout
         → floodStore/portImpactStore 直接设置恢复数据
         → stateRestored=false
500ms ──→ ① 的 setTimeout 执行 → triggerFloodAnalysis(0) ← 水位 0!
         → API 返回 waterLevel=0 的数据 → 覆盖已恢复的 5m 数据 ✗
```

#### 修复

在 `onMounted` 恢复状态前清除 `analysisTimer`：

```javascript
onMounted(() => {
  const savedState = floodStateStore.consumeState()
  if (savedState) {
    if (analysisTimer) {          // ← 新增
      clearTimeout(analysisTimer)  // ← 清除旧的防抖
      analysisTimer = null        // ←
    }
    stateRestored = true
    // ...
  }
})
```

#### 修复后时序

```
setup  ──→ immediate watch 触发 → analysisTimer = setTimeout(trigger, 500ms) ①
mount  ──→ onMounted → clearTimeout(analysisTimer) ✗ ① 被清除
         → stateRestored=true → setWaterLevel(5m) → 拦截
         → 直接设置恢复数据 → stateRestored=false
         → 无残留定时器，无错误覆盖 ✓
用户拖动 ──→ setWaterLevel(6m) → watch 正常触发 → 正确 API 调用 ✓
```
