#### A. 新建 `server/utils/fileStore.js`（共 37 行）

```js
// BUGFIX-R-01: 文件存储工厂，统一缓存/写锁基础设施
export function createFileStore(filePath, { useCache = true } = {}) {
  let cache = null
  let writeLock = Promise.resolve()

  function sequential(fn) {
    const next = writeLock.then(fn, fn)
    writeLock = next.then(() => {}, () => {})
    return next
  }

  async function readAll() {
    if (useCache && cache !== null) return cache
    try {
      const content = await fs.readFile(filePath, 'utf-8')
      const data = JSON.parse(content)
      if (useCache) cache = data
      return data
    } catch (error) {
      if (error.code === 'ENOENT') {
        if (useCache) cache = []
        return []
      }
      throw error
    }
  }

  async function writeAll(data) {
    await fs.writeFile(filePath, JSON.stringify(data, null, 2), 'utf-8')
    if (useCache) cache = data
  }

  return { sequential, readAll, writeAll }
}
```

**设计决策**:
- `useCache` 选项：支持带缓存（plans/markers）和不带缓存（users）两种模式
- `sequential` 写锁保持原有逻辑不变（链式 `then`，错误不丢失锁）
- `readAll` / `writeAll` 语义与原有的三个版本完全一致
- 对外只暴露 `{ sequential, readAll, writeAll }`，内部 `cache` / `writeLock` 完全封装

```js
  warn: (...args) => console.warn(...args),
  error: (...args) => console.error(...args),
}
```

**设计决策**:
- `console.warn` / `console.error` 不静默：这些是真正的异常信号，生产环境也需要可见
- `import.meta.env.DEV` 是 Vite 注入的布尔常量，构建时可被 tree-shaking 优化（`isDev &&` 整个表达式在 production build 中被移除）
- 后续全量替换 `console.log/debug` → `logger.debug` 的工作量较大（25+ 处跨 10+ 文件），属于机械替换，建议用 `sed` 批处理或独立 PR 完成，不在本次阶段中逐文件修改

**验收**: 新建文件已存在，API 可供后续调用；生产构建（`npm run build`）后 logger.debug/info 调用被 tree-shake 移除。

### 1.10 S4-12【R-04】— 字号与 cell 解耦

**严重级别**: 🔧 架构治理

**问题**: `useGCS.js` 的 `css` 导出对象中，字号计算为 `cellPixel.value * 0.2` / `* 0.175` / `* 0.15`，随视口浮动。GCS_V2 设计规范要求固定字号 16/14/12px。字体大小不应随布局网格变化——不同视口下可读性应保持一致。

**文件**: `src/core/layout/useGCS.js` 第 220-225 行

```diff
-    // 字号尺寸（根据项目规范）
-    /** 标题字号 = 0.2 cell (约 16px) */
-    fontSizeTitle: computed(() => `${cellPixel.value * 0.2}px`),
-    /** 正文/列表字号 = 0.175 cell (约 14px) */
-    fontSizeBody: computed(() => `${cellPixel.value * 0.175}px`),
-    /** 辅助/小字号 = 0.15 cell (约 12px) */
-    fontSizeSmall: computed(() => `${cellPixel.value * 0.15}px`),
+    // BUGFIX-R-04: 字号固定 px，与 cell 网格解耦（GCS_V2 规范：16/14/12px）
+    fontSizeTitle: computed(() => '16px'),
+    fontSizeBody: computed(() => '14px'),
+    fontSizeSmall: computed(() => '12px'),
```

**设计决策**:
- 保留 `computed` 包装：虽然现在是常量，但保持接口一致性，对调用方透明
- 范围控制：**仅改 useGCS.js 的 css 导出变量**。组件内本地计算的 cell 系数字号（LoginPanel.vue 第 31-37 行等 `titleFontSizeCss = 0.225 * cellPixel`）不在本期改——那部分需要逐组件回归测试，记录为后续 UI 走查事项
- 字号序列 `16/14/12` 对应 Material Design 的字号阶梯，是标准实践

**验收**: 使用 `css.fontSizeTitle` 等变量的组件在不同视口下保持 16/14/12px。
