### 问题 1：热力图/点图层不显示，无动画

**级别：P0 | 类型：功能缺陷**

#### 实际根因

| 审查项                            | 状态    | 位置                         |
| --------------------------------- | ------- | ---------------------------- |
| 渲染器监听                        | ✅ 已有 | `useForecastLayer.js:42-70`  |
| `nextTick` 延迟注册               | ❌ 缺失 | —                            |
| `getRenderData` 数据提取          | ✅ 正确 | `useForecastLayer.js:80-83`  |
| 图层存在性检查（`manager.has()`） | ❌ 缺失 | `useForecastLayer.js:85-116` |
| 播放动画驱动图层更新              | ❌ 缺失 | `ForecastPage.vue`           |

#### 代码证据

**1a. 图层注册无延迟保障**

`useForecastLayer.js:42-70` — 监听 `[renderer, activeIndicator]`，渲染器就绪后立即注册 4 个图层。若渲染器在 `nextTick` 前尚未完全初始化，`manager.register` 可能静默失败。

```js
// useForecastLayer.js:42-70
watch(
  [() => renderer.value, () => forecastState.activeIndicator],
  ([r, newInd], [oldR, oldInd]) => {
    if (!r) return
    // 立即注册，无 nextTick 延迟
    for (const indicator of INDICATORS) { ... }
  },
  { immediate: true },
)
```

**1b. `updateForecastLayer` 无图层存在性检查**

`useForecastLayer.js:85-116` — 获取数据后直接调用 `manager.updateData(key, { data, options })`，若之前注册失败（`manager.has(key)` 为 false），`updateData` 通过 mock 对象静默丢弃：

```js
// useBusinessLayers.js:22-31（mock 实现）
manager: {
  register: () => {},
  updateData: () => {},
  has: () => false,  // 始终返回 false
  // ...
}
```

**1c. 播放动画时图层不更新**

`ForecastControlPanel.vue:108-120` — 播放按钮驱动 `setCurrentTime` 推进时间，依赖父组件 watch 触发 `doForecastUpdate`。但 `ForecastPage.vue` 中未监听 `forecastState.isPlaying`，没有任何定时器主动刷新图层。

```js
// ForecastControlPanel.vue:113-119
function startPlayback() {
  playbackTimer = setInterval(() => {
    if (!forecastState.isPlaying || currentStep.value >= maxSteps.value) {
      forecastState.isPlaying = false
      stopPlayback()
      return
    }
    forecastState.setCurrentTime(stepToTime(currentStep.value + 1))
  }, forecastState.playSpeed)
}
```

#### 修复建议

1. 在 `useForecastLayer` 的 `watch` 中增加 `nextTick` 延迟注册
2. `updateForecastLayer` 中检查 `manager.has(key)`，若无则重新注册
3. 在 `ForecastPage.vue` 中监听 `forecastState.isPlaying`，为 `true` 时启动定时器（间隔 1000ms）调用 `updateForecastLayer`

### 问题 2：节流/防抖未生效，快速操作卡顿

**级别：P0 | 类型：性能缺陷**

#### 实际根因

`ForecastPage.vue:169-187` 的 watch 实现存在 **双触发** 设计：每次状态变化同时产生尾随防抖 + 节流立即执行。

```js
// ForecastPage.vue:169-187
watch(
  () => [
    forecastState.activeIndicator,
    forecastState.currentTime,
    forecastState.confidenceThresholds[forecastState.activeIndicator],
  ],
  () => {
    const now = Date.now()
    clearTimeout(trailingTimer)
    // 触发点 A：尾随防抖（每次状态变化）
    trailingTimer = setTimeout(() => doForecastUpdate(), TRAILING_DELAY) // 250ms

    // 触发点 B：节流立即执行（每 300ms 一次）
    if (now < throttleBlockUntil) return
    throttleBlockUntil = now + MIN_INTERVAL // 300ms
    doForecastUpdate() // 立即执行
  }
)
```

**执行流程示例（快速拖动时间滑块）：**

```
t=0ms     状态变化 → 尾随防抖排入(250ms) + 立即执行 doForecastUpdate() ← 2次请求
t=100ms   状态变化 → 尾随防抖重置(250ms) + 节流拦截(未到300ms)
t=200ms   状态变化 → 同上
t=300ms   状态变化 → 尾随防抖重置(250ms) + 节流解锁 → doForecastUpdate() ← 又2次请求
t=450ms   尾随防抖触发 → 停止后最后一次请求 ← 1次请求
```

**每个节流周期至少 2 次请求，叠加无请求取消则 6 个并发请求。**

此外，`ForecastControlPanel.vue:41-47` 的置信度滑块已使用 300ms 防抖，与父组件形成 **嵌套防抖**：

```js
// ForecastControlPanel.vue:41-47
function onConfidenceSliderInput(key, value) {
  if (confidenceDebounceTimer) clearTimeout(confidenceDebounceTimer)
  confidenceDebounceTimer = setTimeout(() => {
    forecastState.setConfidenceThreshold(key, Number(value)) // 更新 store
    onSliderInput(key)
  }, 300)
}
```

#### 修复建议

1. 合并所有 watch 为一个 computed 派生依赖，使用纯防抖（300ms，取消立即执行）
2. 移除 `throttleBlockUntil` 和尾随防抖的双重机制
3. 置信度滑块改为 `@change` 事件提交，或使用本地临时状态

### 问题 3：切换指标时图表与图层数据不一致

**级别：P1 | 类型：数据一致性缺陷**

#### 实际根因

`doForecastUpdate` 使用 `startTransaction()` 生成统一事务 ID，但各请求函数对过期响应的检查不完整。

**`loadTimeSeriesData` (`ForecastPage.vue:53-104`)：**

```js
const resp = await forecastApiRequest(..., transactionId, signal)
if (resp === null) return  // 仅检查 AbortError
// ❌ 未检查 transactionId 是否过期
if (resp.code === 200 && resp.data?.series) {
  requestCache.set(cacheKey, { allSeries: resp.data.series })  // 可能覆盖新数据
}
```

**`loadPortComparisonData` (`ForecastPage.vue:107-132`)：**

```js
// ❌ 缓存命中时完全跳过事务检查
if (requestCache.has(cacheKey)) {
  const c = requestCache.get(cacheKey)
  barXData.value = c.xData
  barSeries.value = c.series
  return
}
```

**场景复现：**

1. 当前指标为"吞吐量"，请求 A 发出
2. 快速切换到"泊位利用率"，请求 B 发出，请求 A 的 `AbortController` 触发
3. 若请求 A 在 `abort()` 信号到达前已返回，A 的响应数据仍会写入图表/图层
4. 若请求 B 先到但 A 的缓存更早写入，则显示错误数据

#### 修复建议

1. 在每个请求回调中检查 `transactionId === currentTransactionId`
2. 缓存命中时也需检查事务有效性
3. 使用 `Promise.allSettled` + 统一 seq 检查

### 问题 5：缓存无清理

**级别：P1 | 类型：内存泄漏**

#### 实际根因

`ForecastPage.vue:31` — `const requestCache = new Map()` 无大小限制。

```
每次切换产生新 cacheKey 格式：
  ts:{indicator}:{granularity}:{confidence}
  cmp:{indicator}:{time}:{confidence}

4 种指标 × 3 种置信度 × 13 年 × 12 月 = 最多 1872 个缓存条目
每条包含完整的 timeSeries 数组，内存持续增长
```

`onMounted` 仅清空一次 (`L51`)，组件卸载时 `requestCache` 为模块级常量不自动回收。

#### 修复建议

1. 实现 LRU 缓存，限制最大 50 条目
2. 或在组件卸载时显式清空（`onUnmounted` 中 `requestCache.clear()`）

### 问题 6：路由切换后可视化面板响应丢失

**级别：P0 | 类型：功能缺陷**

#### 实际根因

`FloodAnalysisPage.vue:167-193` — 状态恢复逻辑有**渲染缺失**：

```js
onMounted(() => {
  const savedState = floodStateStore.consumeState()
  if (savedState) {
    if (analysisTimer) {
      clearTimeout(analysisTimer)
      analysisTimer = null
    }
    stateRestored = true

    waterLevelStore.setWaterLevel(savedState.waterLevel) // 触发 watch
    // watch 中因 stateRestored = true 跳过分析

    floodStore.startFloodAnalysis(
      savedState.floodStatistics,
      savedState.floodFeatures,
      savedState.floodRiskLevel
    )
    portImpactStore.setPortImpactResult(savedState.affectedFacilities, savedState.totalLoss)

    stateRestored = false
    // ❌ 跳过了 renderFloodAreas() 和 renderAffectedFacilities()
    // ❌ 数据恢复到 Pinia store 后，图层不更新
  }
})
```

**执行流程：**

1. 用户离开页面 → `onBeforeRouteLeave` 调用 `saveCurrentState()`，保存水位、统计、特征、设施到 `floodStateStore`
2. 用户返回页面 → `onMounted` 检测到 `savedState` 存在
3. 设置 `stateRestored = true` → 恢复水位（触发 watch 但被拦截）
4. 恢复 store 数据（`floodStore`, `portImpactStore`）
5. 设置 `stateRestored = false`
6. **结束 — 图层始终未更新，UI 面板显示旧数据但地图为空白**

#### 修复建议

1. 在 `onMounted` 恢复分支中，主动调用 `renderFloodAreas(savedState.floodFeatures)` 和 `renderAffectedFacilities(savedState.affectedFacilities)`
2. 移除 watch 中对 `stateRestored` 的检查，改为通过防抖定时器管理
3. 渲染前检查 `shouldRenderForCurrentRoute()`

### 问题 9：请求未取消（浸没分析）

**级别：P1 | 类型：性能缺陷**

#### 实际根因

`triggerFloodAnalysis` (`FloodAnalysisPage.vue:217-260`) 和 `triggerImpactAssessment` (`L262-295`) 使用 `apiRequest` 来自 `useApiRequest.ts`。

`useApiRequest.ts:59-60` 在函数内部创建 `AbortController`，**不对外暴露 `signal`**：

```ts
async function apiRequest<T = unknown>(path: string, options: RequestOptions = {}): Promise<T> {
  const controller = new AbortController()
  const timeoutId = setTimeout(() => controller.abort(), 10000)
  // ...
  const res = await fetch(`${API_BASE}${path}`, {
    ...options,
    headers,
    credentials: 'include',
    signal: controller.signal, // 内部 controller，外部无法控制
  })
}
```

`analysisSeq` 机制 (`L48`) 只能丢弃过期响应，**不能中止正在传输的请求**。快速点击预设水位时，旧请求继续传输。

#### 修复建议

1. 在 `useApiRequest.ts` 的 `RequestOptions` 中增加 `signal` 字段
2. 若外部传入 `signal`，与内部超时 `signal` 组合（使用 `AbortSignal.any` 或手动监听）
3. 在 `FloodAnalysisPage.vue` 中为两个请求函数分别维护 `AbortController`

### 问题 10：ECharts 剖面板全量重绘

**级别：P1 | 类型：性能缺陷**

#### 实际根因

`WaterLevelProfilePanel.vue:227` — `setOption(option, true)` 第二个参数 `true` 表示 `notMerge`，强制全量替换：

```js
function updateChart() {
  // ...
  chartInstance.setOption(option, true) // notMerge = true
}
```

水位变化 `watch` (`L241-248`) 每次调用 `updateChart()`：

```js
watch(
  () => waterLevelStore.waterLevel,
  () => {
    if (chartInstance && selectedProfileId.value) {
      updateChart() // 每次全量构建 option + notMerge
    }
  }
)
```

**影响：**

- 每次水位变化（滑块拖动连续触发），地形高程系列（不变数据）被重建
- ECharts 内部触发完整的布局 → 绘制流水线
- 6 个 info-item（淹没面积、平均水深等）被反复重建 DOM

#### 修复建议

将 `L227` 改为：

```js
chartInstance.setOption(option, { notMerge: false, lazyUpdate: true })
```

这样 ECharts 会进行增量更新：仅识别变化的数据项，保持地形高程系列和图表状态不变。
