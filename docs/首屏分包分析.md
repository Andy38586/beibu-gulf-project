## 二、首屏构成与估算加载时间（按需引入后）

首屏有效载荷 = 入口 + vue-vendor + ui-vendor + openlayers + echarts + AppLayout/HomePage + 小共享块 + CSS
≈ **JS 410 KB gzip + CSS 17 KB gzip ≈ 480 KB gzip**（较落地前 720KB 降约 240KB）。

| 网络档位 | 吞吐(估) | ~480KB gzip 传输 | 含解析/RTT 估算首屏 |
|---|---|---|---|
| 良好 4G | ~4 Mbps | ~1.0 s | **~1.5–2.5 s** |
| 慢速 3G（Lighthouse Slow 3G） | ~400 Kbps | ~9.6 s | **~11–14 s** |

> 结论：4G 下达标且从容；慢 3G 仍偏重，根因转为 echarts(185KB)+openlayers(121KB)，二者均首屏核心功能。

## 三、分包现状评估

✅ **已经做对的**
- Cesium：3D 引擎通过 `createRenderer('3d')` 内 `import('./CesiumRenderer')` 动态加载 + 运行时注入 `Cesium.js`，**完全不在首屏**。
- 路由级懒加载：5 个页面全部 `() => import()`，页级代码不进首屏。
- echarts 已按需 tree-shake（`echarts/core` + 指定 chart/component）。
- OL / vue / element-plus 各自独立 chunk，便于缓存。
- **Element Plus 已改为按需引入**（unplugin-auto-import + unplugin-vue-components），首屏 element-plus 占用 368→128KB gzip。

## 四、还需要做的（按杠杆排序）

### 1. Element Plus 改按需引入 —— ✅ 已完成（2026-07-28）
- 做法：`unplugin-vue-components` + `unplugin-auto-import`（ElementPlusResolver），移除 `main.js` 全量 `app.use(ElementPlus)` + 全量 CSS，删 4 处显式 `import ... from 'element-plus'`（ProfilePage / WaterLevelProfilePanel / PaginatedListPanel / errorHandler）。
- 实测：`ui-vendor` JS 320→116KB gzip，CSS 48→11.85KB gzip；首屏 element-plus 占用 368→128KB gzip。
- 校验：build ✅ / 44 test ✅ / lint ✅；样式（el-message/el-button/el-select/el-slider）随组件自动注入，无裸奔；tsconfig 已加 `auto-imports.d.ts`/`components.d.ts` include。
- 连带修复：上一轮卸载 `@turf/turf` 把传递依赖 `@types/geojson` 一并 prune，已显式补回 `@types/geojson` 修复 typecheck 的 TS2307；eslint 显式声明 `ElMessage/ElMessageBox/ElNotification/ElLoading` globals 避免 no-undef。

### 2. echarts 首屏延迟初始化（改善 TTI/LCP，不降总体积）
- charts 在 AppLayout 首屏即渲染，185KB 解析占关键路径。
- 方案：地图先 paint，图表用 `requestIdleCallback` / `onMounted` 后延迟 `init`，把 echarts 解析移出首帧关键路径。

### 3. OL（121KB）基本可接受
- 2D 地图是核心功能，必在首屏。已按需 tree-shake。
- 可选：heatmap / 特定 format 模块若非所有视图都用，可进一步异步，但 ROI 低。

### 4. 无需再"分"的
- Cesium 已正确延迟；vue-vendor / 入口已很瘦。
- 手动 `manualChunks` 已合理，下一步重点不是"再切几块"，而是**减少打进首屏的内容**。

## 五、一句话结论
分包策略本身没大问题（Cesium 延迟是亮点）；Element Plus 全量进首屏已通过按需引入解决，首屏从 ~720KB 降到 ~480KB gzip。剩余重头是 echarts(185KB) 与 openlayers(121KB)，二者均为首屏核心功能、已按需 tree-shake，进一步压缩 ROI 低。
