# 首屏加载性能评估（2026-07-29）

> 评估对象：北部湾 WebGIS 平台前端首屏（2D 地图首屏，未进 3D/Cesium）。
> 口径：基于 `frontend/dist/index.html` 实际引用的 chunk + `nginx.conf` + 地图底图数据源的**建模估算**。
> 重要：本文是**模型估算，不是真机测量**。真机数字需用 Lighthouse / RUM / WebPageTest（中国节点）从北京/上海/成都实测。

---

## 一、结论速览

| 维度 | 结论 |
|---|---|
| 首屏传输量（gzip） | **JS 252 KB + CSS 13 KB ≈ 265 KB** |
| 桌面宽带（沪/京/蓉） | FCP ≈ 0.5–1.2s，LCP（地图可见）≈ **1.0–2.3s** ✅ 达标 |
| 移动 4G | FCP ≈ 1.0–1.8s，LCP ≈ **2.5–4.5s** ⚠️ 临界/超标 |
| 优化做得对的 | Cesium 5.7MB 延迟加载、echarts 懒加载、vendor 分包、modulepreload |
| 最大短板 | nginx 无静态缓存、无 Tianditu preconnect（这俩是快速高收益修复）；Element Plus 110KB 进首屏属按需打包的真实代价（非 bug，需权衡是否换轻量组件）；无 brotli/HTTP2 |

**一句话**：首屏"体积"控制得不错（265KB gzip，且重型库都拆出去了），但**部署层几乎没做缓存与协议优化**，且首屏被 Element Plus 吃掉近一半。重复访问和移动端是弱项。

## 三、网络与时延模型（无 CDN，直连阿里云 ECS）

假设应用服务器在阿里云（华东1 杭州 / 华南1 深圳，离北部湾最近）。若实际在华北2 北京，成都会更慢。

| 城市 | → 应用源 RTT | → 天地图 RTT |
|---|---|---|
| 上海 | 25–45 ms | 30–60 ms |
| 北京 | 35–55 ms | 35–70 ms |
| 成都 | 55–85 ms | 50–80 ms |

首屏时间组成：
1. TLS + HTML 文档：1–2 RTT
2. JS/CSS 下载（265KB gzip，HTTP/2 并行，100Mbps≈22ms + 1 RTT）
3. JS 解析+执行：桌面 ~300–500ms，移动 ~600–1000ms
4. 动态 import 页面块 + 拉 `/data/*.json`（同源，+1 RTT）
5. 天地图底图瓦片（外部，首屏"可见"取决于它）：首屏视窗 z9 约 12–24 张瓦片，渐进返回

| 城市 | FCP（shell 出现） | LCP（地图可见可交互） |
|---|---|---|

## 五、已经做对的（不要动）

1. ✅ **Cesium 5.7MB 动态 import**：`vite.config.js` 移除了同步 `<script src="/cesium/Cesium.js">`，改为切 3D 时才加载——首屏省下最大头。
2. ✅ **echarts 懒加载**：未出现在 `index.html` 引用集。
3. ✅ **manualChunks 拆分 vendor**：vue/ol/echarts/ui 各自独立，利于缓存与并行。
4. ✅ **modulepreload 提示**：4 个 vendor chunk 预加载，并行度好。
5. ✅ **loading 骨架屏**：`#app` 内联 spinner，首屏感知快。
6. ✅ **target: es2020**：无多余语法降级。

## 六、待优化（按收益排序）

### 🔴 P0 — nginx 无静态资源缓存
`nginx.conf` 只开了 gzip，**没有任何 `expires`/`Cache-Control`**。后果：每次回访者都重新下载 265KB；Lighthouse 重复访问视图分数崩；CDN 失效时全量回源。
**收益**：回访首屏趋近于"0 下载"，Lighthouse 缓存项满分。改动 5 行。

### 🔴 P0 — 无 `<link rel=preconnect>` 到天地图
首张瓦片要现场做 DNS+TLS+RTT。加一行 preconnect 可省 30–80ms（每张首批瓦片都受益）。
**收益**：地图 LCP 直接降一档。改动 1 行。

### 🟠 P1 — Element Plus 110KB gzip 进首屏（已核实：按需打包，非 bug）
占首屏 JS 44%。**代码核实**：`main.js:44-47` 无 `app.use(ElementPlus)`、全仓 grep `element-plus` 零匹配、无 `import 'element-plus/dist/index.css'`（总 CSS 仅 13KB）→ 确认走 `unplugin-vue-components` 的 `ElementPlusResolver` **按需注入**，只含真实用到的组件。
110KB 的真实来源（实测）：`ElButton`(`PaginatedListPanel.vue`)、`ElSelect`/`ElOption`/`ElSlider`(`WaterLevelProfilePanel.vue`)，加程序式 API `ElMessage` 等，及其依赖树（ElPopper/ElScrollbar/ElTooltip…）。
**性质**：是正确的按需结果，不是全量引入。但因所有用到的 El 组件被合并进同一个 `ui-vendor` chunk 并在首屏 `modulepreload`，首屏要为全站 El 组件买单（哪怕落地页只用到 ElButton）。
**可选优化（权衡 DX，非必修）**：① 把重型组件（ElSelect/ElSlider）换成轻量自研组件，单项可省数十 KB；② 对 ui-vendor 做更细分包或延迟非落地页 El 组件。

### 🟠 P1 — 无 brotli / 无 HTTP/2
nginx 仅 gzip（~15–20% 劣于 brotli），且 `listen 80` 无 HTTPS/HTTP2。若 TLS 是在阿里云 SLB 终结则 HTTP2 可能已具备；若 nginx 就是边缘，则既无 HTTPS（安全风险）也无多路复用。
**收益**：brotli 再省 ~40KB；HTTP2 多路复用减少队头阻塞。

### 🟡 P2 — dist 重复 chunk 堆积
`vite.config.js:72 emptyOutDir:false` 导致 17 份 `index-*.js`、17 份 `AppLayout-*.js` 等（dist 共 23MB）。**不影响首屏加载**（index.html 只引当前 hash），但浪费磁盘/CI/部署包。
**收益**：部署包瘦身。改 `emptyOutDir` 按环境（生产 true）。

### 🟡 P2 — 天地图外部依赖不可控
底图延迟由 tianditu.gov.cn 决定，前端无法直接加速；如需更强可控，可后续用同源代理或自托管瓦片（超出本次范围）。

## 七、具体改动建议

**1. nginx 静态缓存（加在 `location /` 之前或内部）：**
```nginx
# 带 contenthash 的资源可激进缓存
location /assets/ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}
# 同源静态数据也可长缓存
location /data/ {
    expires 1h;
    add_header Cache-Control "public";
}
```

**2. index.html `<head>` 加 preconnect：**
```html
<link rel="preconnect" href="https://t0.tianditu.gov.cn" crossorigin>
```

**3. brotli（若 nginx 编译了 ngx_brotli，放在 gzip 段下方）：**
```nginx
brotli on;
brotli_comp_level 6;
brotli_types text/css application/javascript application/json image/svg+xml;
```
（注意：同时开 gzip+brotli 时，支持 brotli 的客户端会优先取 brotli。）

**4. 生产构建清 dist：**
`vite.config.js` 将 `emptyOutDir` 改为按环境：
```js
emptyOutDir: process.env.NODE_ENV === 'production',
```

## 八、怎么拿到真机数字（验证本文估算）

1. **Lighthouse**（桌面/移动）：对部署 URL 跑一次，看 FCP/LCP/TBT。注意 Lighthouse 默认从实验室环境测，跨城延迟需配合下方 RUM。
2. **WebPageTest**：选 China 节点（上海/北京），看多视点真实水线。
3. **RUM**：前端接 `web-vitals` 库，把真实用户 FCP/LCP 上报，按城市分组——这是最准的"北京/上海/成都各自多少秒"。
4. **确认两件事**：① 阿里云 ECS 具体地域；② TLS/HTTP2 是否在 SLB 终结。两者会显著改变上面的时延数字。
