# audit-kit —— 审查交付的「可复算」执行体

## 它治的是什么

四轮审查（921–924）反复栽在同一个坑上：**窗口件自称「跑过了、红了、绿了」，接收方只能读和信。**

实测证据（本工具对真实历史件的判定）：

```
923/专项1-问题副本           bash 块=2
923/专项8-问题副本           bash 块=0  ⚠ 判未交付
923/专项7-执行记录-R5        bash 块=0  ⚠ 判未交付   ← 当时被评「全批最可复算」的一份
924/专项1-执行记录           bash 块=0  ⚠ 判未交付
924/专项8-执行记录           bash 块=0  ⚠ 判未交付
```

根因不在窗口「不认真」，在**结构**：审查的承重件全落在 gitignored 的一次性目录里 ——

| 承重件        | 现状                                                              | 后果                                       |
| ------------- | ----------------------------------------------------------------- | ------------------------------------------ |
| 度量/复跑工具 | `.local/*.mjs`（37 个一次性脚本，`sliceB-analyze` 有 2/3/4 四版） | 每轮从零重建，口径必然漂移                 |
| 审查产出      | `docs/audits/**`（`git ls-files` = **0**）                        | 下一轮窗口看不到上一轮，格式与口径各自发挥 |
| 规范文档      | `docs/根基文档/审查体系专项/`（入库 10 份）                       | **只有规范入库，承载规范的执行体没入库**   |

所以往 `AGENTS.md` / `CLAUDE.md` 里加条款是无效的：条款描述的是**行为要求**，而行为由**可观测的验收信号**塑造。文档要求的格式没有工具能验证，就等于没有格式。

这正是项目本身的两条判据在审查流程上被违反：

- 禁忌 2「写了就不管 → 新增守卫必须同笔给出调用点或测试」
- 「从未红过的门禁 = 不存在」

## 契约

窗口件必须在 **`## §0`** 区段内把判据写成 bash 围栏块，且每条命令后面紧跟一行期望：

````md
## §0 五分钟核对

```bash
git rev-parse --short HEAD
# 期望: a736ab30
node tools/v3-guard/ledger-dedupe.mjs | head -1
# 期望: 待解决 57 项
```
````

- 期望值写成**实际 stdout 的原样摘录**（子串匹配），不要写「应该会通过」这类判断。
- 需要改坏源码才能复现的变异，放到 `§1` 之后 —— 本工具只复算 `§0`。

## 用法

```bash
# 1) 抽取：无块件非零退出（「交个空壳」不算交过）
node tools/audit-kit/extract-window.mjs <outDir> <window.md>...

# 2) 复算：抽 §0 → 整块实跑 → 逐条核对期望
node tools/audit-kit/verify-window.mjs <window.md> [--section 0] [--cwd .]
```

退出码：无块 ⇒ `1`（判未交付）；有 FAIL ⇒ `1`；全 PASS / 仅 SKIP ⇒ `0`。

## 三条硬口径（对应 AGENTS §5.4）

1. **抽不出块 ⇒ 未交付**，不是「部分通过」。空壳件不给重跑额度。
2. **命令起不来 / 超时 ⇒ 记 SKIP** 并计入报告，不判红也不判绿（环境限制要如实标，见 §5.5）。
3. **期望对不上 ⇒ FAIL**。这就是「窗口自述」与「机器复算」的差值本身。

## 为什么整块跑而不是逐条跑

块内命令常有 `cd` / 变量赋值，拆开跑会失真。整块跑保住上下文，代价是「期望归属哪条命令」变粗——报告按块粒度呈现，不假装逐条精确。

## 为什么用文件描述符而不是管道

受限执行环境拒绝创建管道式子进程（`spawnSync` 直接 EBUSY、`status=null`），用管道会得到一片假红。本工具把所有子进程输出重定向到 fd 再读文件。同款修法见 `tools/v3-guard/agent-docs-check.mjs`。

## 自测

`tools/audit-kit/__tests__/verify-window.test.mjs`（10 条）随 `npm run test:tools` 一起跑，钉住抽取、取节、期望解析与整体判定。
