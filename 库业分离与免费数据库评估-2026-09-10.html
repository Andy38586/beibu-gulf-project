库业分离 & 免费数据库评估（服务器 2核2G / 40G磁盘 / 4 容器，2026-09-10）
结论先行："把数据库搬出小服务器"这个方向成立，但"免费额度"救不了你的线上演示——海外免费档（Supabase/Neon）会休眠、机房在海外（大陆跨境延迟+抖动），国内云只有新用户限时试用 1~3 个月、并非永久免费。正确顺序是：先零成本调优（swap + 限内存 + 削预热峰值）→ 实测仍紧再分离，且选同云同地域的最小付费规格；海外免费档只配做开发/备演环境。
① 先算账：2G 内存到底被谁吃了（搬库前必须实测）
容器 角色 内存估算（常驻 / 峰值） 说明
app nginx + 前端静态 30~60 MB 很轻，不是问题
nest NestJS 业务 API 100~180 MB Node 常驻，平稳
algorithm-service FastAPI 洪涝/航线演算 200~450 MB 启动要全量拉路网构图（约 40s），这才是最大的内存/CPU 尖峰
postgis PostgreSQL16 + PostGIS3.4 150~300 MB 默认参数偏浪费，可调小；稳态占用并不高
系统 + Docker 宿主开销 250~350 MB 省不掉
容易被误判：顶满 2G 的多是 FastAPI 40s 预热尖峰，不是 Postgres 稳态。把 PG 搬走只能省 150~300MB，尖峰依旧。
磁盘 40G 不是瓶颈：三港业务数据进 PG、体量小；4.9 万张地形瓦片走 docker bind-mount、不进数据库。搬库几乎不释放磁盘。
先在服务器跑 docker stats（看各容器实时内存）与 free -h、docker system df，用实测决定要不要搬，而不是凭感觉。
② "免费数据库"额度真相（2026-09 核实，政策随时变，以官网为准）
方案 免费额度 休眠 / 冷启 PostGIS 大陆访问 能否挂正式演示
Supabase Free 库 500MB / 共享 500MB RAM / 出流量 5GB 7 天低活动自动暂停，冷启 30~60s，无自动备份 支持（预装） 机房海外，跨境延迟/抖动 不建议
Neon Free 存储 0.5GB / 100 CU·时每月 / 出流量 5GB 5 分钟无请求缩零（免费档不可关），冷启 0.5~2s；100 机时不够 7×24（月需约 730h） 支持（CREATE EXTENSION） 机房海外，跨境延迟/抖动 不建议
阿里云 RDS PG / PolarDB-PG、腾讯云 PG 仅新用户限时试用 1~3 个月，非永久免费；之后最小规格约几十元/月 常驻不缩零（Serverless 型号可按用量） 支持 同地域内网毫秒级 可（试用/低价档）
现状：本机容器 PostGIS 0 额外费用 无休眠、无冷启 已在用 本机 0ms 可，代价是占 150~300MB 内存
③ 为什么海外免费档对这套系统尤其危险
启动放大：FastAPI 启动要从 PG 全量拉路网构图（本机约 40s）；走跨境公网会被拉长到分钟级，甚至健康检查超时、容器反复重启。
休眠致命：Supabase 暂停后首个请求要等 30~60s，演示现场第一次点查询就"卡死"；Neon 5 分钟缩零虽冷启快，但 100 机时/月撑不起常驻服务。
链路不稳：公网弱网/跨境抖动会让 Nest 的 healthcheck 误判数据库不可用；PostGIS 空间查询往返多，延迟被成倍放大。
额度天花板：免费档库容量 500MB 级、出流量 5GB，且无自动备份/无 SLA，数据安全和增长都没保障。
④ 推荐路径：分三步走，先省后搬
Step 0｜0 元，立刻做
① docker stats 实测谁吃内存；② 宿主加 2G swap 吸收预热尖峰；③ 给 Postgres 限参：shared_buffers=64MB、work_mem=4MB、maintenance_work_mem=32MB、max_connections=20；④ compose 给 nest / algorithm 加 mem_limit；⑤ FastAPI 路网构图改懒加载或降并发，削掉 40s 峰值。
→
Step 1｜实测仍紧，再分离
选同云同地域的最小规格 PG（Serverless/突发型，必须支持 PostGIS），走内网连接；pg_dump -Fc 导出 → 云端 CREATE EXTENSION postgis 后 pg_restore；改 compose 的 PG_HOST/ROUTE_PG_HOST 等为内网地址，再停掉本机 postgis 容器。
→
Step 2｜免费档的正确位置
Supabase/Neon 只用来做开发库 / 备演 / 原型，不挂正式演示；国内云的 1~3 个月试用可用来验证分离效果，到期前决定是否转低价常驻。
安全要点：云端库安全组只放行你 app 服务器的出口 IP、强制 SSL、不要用 postgres 超户给业务连接（与本次地形修复同理：制品/配置要可校验、可回退）。
一句话：库业分离是"第二步"，不是"第一步"。先用 swap + PG 限参 + 削 FastAPI 预热把 2G 机器的水分挤掉（大概率就够了）；真要搬，搬去同地域国内云的低价 PG，而不是会休眠、在海外的"永久免费"档——对一个要现场演示的 PostGIS 系统，后者省的是钱、丢的是可用性。
